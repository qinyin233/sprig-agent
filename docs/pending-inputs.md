# 中途引导的保存与恢复

TUI 执行中仍可 Enter 发送文字要求，调整当前任务。未来任务用 `/queue 正文` 单独收存，只有明确 `/queue run` 才顺序执行，见[任务排队](task-queue.md)。启用 `--save-session NAME`、配置自动保存或手动保存过当前会话后，Sprig 先把要求写入同一私有会话文件，再提示“已接收并保存”。未启用保存时明确提示仅在当前进程内存中；退出后无法恢复。

CLI 模型任务的批准窗口也可用 `n: 更正说明` 拒绝当前提案并收存引导，单行限 4096 个 UTF-8 字节；不增加请求预算，不预先批准后续动作。本地管理命令的拒绝文字不递送。保存不确定时重试同文沿用 ID，或普通 N 返回聊天后明确 `/pending apply`；详细行为和最后一轮预算耗尽时的恢复见[拒绝反馈](rejection-feedback.md)。

恢复会话若发现待处理要求，会阻止直接继续、发送新任务、切换模型、建立分支和创建摘要。先使用以下本地命令：

| 命令 | 行为 |
| --- | --- |
| `/pending` | 显示数量和受输出预算限制的预览，不请求模型 |
| `/pending manage` | TUI 打开管理窗口，可滚动全文、编辑、移除、上移、下移和切换引导/排队模式 |
| `/pending show ID [字符偏移]` | 按 `next_offset` 分页查看完整正文；ID 来自列表，偏移按 Unicode 字符计数 |
| `/pending edit ID "JSON 字符串"` | 逐次确认后替换单条未递送正文，并分配新 ID；例如正文中的换行写作 `\n` |
| `/pending drop ID` | 逐次确认后移除单条未递送要求 |
| `/pending move ID 位置` | 逐次确认后移到指定位置，从 1 开始编号 |
| `/pending delivery ID steer\|queue` | 新确认后切换引导/排队模式，分配新 ID |
| `/pending apply` | 按顺序将引导加入用户历史并保存，排队项保留；不请求模型、不执行工具，超限保留原状态 |
| `/pending discard` | 逐次确认后移除待处理要求，不删除历史、不回滚文件 |
| `/continue` | 处理完待恢复要求后，明确发起模型请求 |

TUI 的“继续”遵守同样的恢复限制。命令行 `--chat --resume NAME` 提供这些命令；若只有排队项，可直接明确 `/queue run`，不会自动执行。直接 `--resume NAME` 遇到待恢复要求会以状态码 2 停止并提示改用聊天模式。没有待恢复要求时，原命令行继续行为保持。恢复时附带的新任务不会抢先发送；TUI 将它保留在输入框，CLI 提示处理待恢复要求后再输入。

TUI 可点击“管理待处理要求”，或输入 `/pending manage`。窗口在当前模型运行时也能打开，不替换或启动 agent worker。列表与正文是刷新时的快照；要求若已变化，编辑草稿保留并拒绝过期修改。编辑窗口内 Enter 换行、Ctrl+S 请求保存确认；主对话仍是 Enter 发送。取消批准保留编辑草稿，关闭未保存编辑时另行确认。已恢复的输入管理完后仍须明确 apply、continue；运行中的任务会在下一个安全节点继续使用修改后的要求，管理动作本身不额外调用模型。

模型 worker 领取要求到成功保存递送历史之间，队列暂时锁定，不能删除或改写正在递送的正文。批准后会重新检查会话、队列内容和领取状态，再写入存储并更新内存；审批期间新输入或递送使快照过期时，整个修改拒绝，不覆盖更新的状态。修改不改变历史、不回放工具，更不能预先批准模型随后提出的写入或命令。

正文可在窗口中完整滚动查看。含 CR、终端控制或双向文本控制字符时，以 ASCII 转义的 JSON 字符串编辑，保存时还原原文，避免把显示转义或换行规范化误当成用户正文。普通文字直接编辑；粘贴超限整段拒绝并保留草稿。聊天分页的 JSON 和终端转义展示都受输出预算限制，不能因预览截断或显示转义绕过大小上限。编辑后的队列仍限 32 条、2 MiB，并受配置请求字节上限约束；恢复的队列已超限时，仍可逐条缩小或删除。

若队列修改写入失败，内存不发布候选修改，旧正文停止后续递送；执行中的任务收到取消请求，已在等待的网络请求可能持续到超时。由于替换可能完成而目录同步失败，内存与磁盘可能不同，不能盲目重试旧正文。请关闭管理窗口后恢复当前会话，或明确丢弃全部待处理要求，再继续。单条编辑和模式切换需要新 ID；上移、下移和查看保留原 ID，旧 ID 不会误指向替换后的正文。

保存失败时草稿保留，界面不会声称新输入已经接收。重试原文沿用本地标识；若保存替换已发生、目录同步却失败，也不会再次创建同一条输入。引导可用 `/pending apply` 明确处理；排队收存不确定时须重试相同 `/queue` 正文、恢复会话，或 `/pending discard` 确认丢弃。未经处理不能改发另一条要求或切换模型。不同次明确提交的相同正文是两条请求，不按正文合并。

在运行中，输入按配置的 `steering_mode` 在安全节点递送。只有递送历史成功保存后才从内存队列确认移除。保存重试通过本地标识避免重复插入用户消息。旧响应仍会作废，尚未执行的工具调用补为 skipped；从文件恢复的未闭合调用补为结果不确定，不能重放。输入标识不表示模型已经回答、工具已经执行或任务验收通过，更不能代替新的操作批准。

私有存储沿用原目录限制、端点/模型/工作区绑定、进程租约、原子替换和脱敏。会话正文不加密。待处理输入最多 32 条、总计 2 MiB UTF-8，TUI 还受配置的请求字节上限约束；整个缩进 JSON 仍最多 8 MiB。完整正文参与预算，预览截断不会减少模型输入。线程内保存与入队串行合并，入队不会用旧 UI 快照覆盖更新的工具记录。

使用待处理输入或递送标识的文件写为 session version 2，含版本化 `input_inbox`；没有这些数据的旧会话仍可为 version 1。新版本读取两种格式，旧客户端会拒绝 version 2，避免悄悄丢弃待处理输入。标识只用于本地递送去重，不进入三种协议的模型请求、摘要原文预览或工具权限。

这不是操作副作用的“恰好一次”保证。进程或存储故障后仍需检查真实文件和进程状态。未保存的输入、编辑窗口草稿、提问表单草稿和后台进程不会因此获得跨进程恢复；新建对话会脱离原保存文件，原文件中的待处理要求仍保留。引导/排队模式只控制递送时机，不批准任何工具；批量输入管理和历史已递送消息编辑仍未实现。

本地离线回归覆盖：并发保存/入队的两个顺序、同步失败重试、递送保存失败、重复标识冲突、相同正文不同请求、容量/序列化预算、凭据脱敏、进程租约、三协议封包、真实 CLI 恢复和逐次丢弃批准、TUI Enter 草稿、恢复不自动调用模型和新会话保留旧文件。CI 依用户要求暂停到 2026-11-01；到期后仍须核对账户限制，不把本地 WSL 结果当作原生 Linux/macOS CI。
