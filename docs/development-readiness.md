更新：2026-10-15。目标仍是接近优秀开源编程 agent 的实际工作能力。此前开发偏重局部检索、编辑和基准设施，缺少配置与日常工作流的统一验收；不能用这些局部实现宣布产品成熟。

## 本轮验收范围

1. 用户只设置现有 `AGNES_API_KEY`，创建配置后可启动 TUI；未付费调用也能诊断本地配置。
2. 命名提供商确定实际模型、地址和凭据来源；错误字段、缺失环境变量、不安全文件或地址覆盖在发送前失败。不自动切换模型。
3. 配置内容不因日志、诊断、会话绑定、文件工具或子进程继承而直接泄露；命令仍明确不是沙箱。
4. TUI 命令保留各自审批和只读保护；新建对话不会覆盖原会话；执行中的本地命令不会意外变成模型任务。
5. 文件附件复用完整隐私检查、路径限制、取消与请求预算，明确是快照，不以静默截断代替完整内容。
6. 每个功能提交先通过本地完整测试；实质 OS 行为通过精确提交的原生 Windows/Ubuntu CI 后才记录跨平台结论。

## 下一阶段完成条件

- **编码推进与效果**：固定多个真实仓库的独立任务和外部验收，在相同 Flash 与预算下正常运行，完整保留成功和失败。按用户新授权，可测试私有配置中的其他模型，但仍控制调用量；不同模型或预算的运行分开报告，不能用切换配置掩盖原失败。
- **开发工作区**：把隔离 worktree、变更时间线和命令改动恢复做成可审阅工作流；不覆盖已有未提交修改。
- **隔离执行**：实现并在各平台验证文件、网络、环境变量和子进程的实际限制，再标记沙箱可用。
- **扩展**：MCP 接入需要工具来源、连接启动批准、单次调用批准、输出预算、取消与凭据边界；不能仅接上 SDK 就宣布完成。
- **复杂任务状态**：短计划已随私有历史恢复并在 TUI 展示；仍需验证它的真实任务收益，并补齐后台任务、长期目标和长上下文完整恢复。取消、失败、会话重开后仍一致是各项完成条件。
