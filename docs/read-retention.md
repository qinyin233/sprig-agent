# 长会话中的源码窗口

启用压缩后，Sprig 先省略旧成功工具正文，再在原有硬字节预算内保留少量完整读取快照。这样，近期消息之外的源码不必一律消失。不会新增文件读取、模型请求或自动续页，不改变保存的完整历史。

```toml
[context]
compact = true
max_bytes = 131072
trigger_ratio = 0.8
keep_recent_messages = 6
keep_read_bytes = 8192
```

`keep_read_bytes` 默认 8192，范围 0–262144；0 使用原先全部省略旧正文的策略。它限制本轮额外保留结果的实际 JSON 编码字节，包含元数据、快照提示与外层字符串转义，不是原文件字节或 token 数。每个结果必须完整放入，同时满足 `max_bytes`，否则继续省略，不截断正文。近期保护窗口本来保留的读取不占这个额外额度。

用户设置、profile、显式项目文件与 CLI 都支持该值，遵循已有覆盖顺序。启动参数为 `--context-keep-read-bytes`，`--show-config` 显示生效值和来源。配置不启用压缩或尚未达到阈值时，此设置不改写请求。`/context` 的强制触发预览也使用同一保留策略，并显示 `retained_reads`、`retained_read_bytes`；实际请求位置和历史变化仍可能使下次大小不同。

候选限于最近 32 个完整读取观察，须有唯一且正确关联的调用/结果、相同路径、有效完整内容摘要和读取标识。每个路径最近一次读取必须完整且可靠，候选只使用与它相同的内容版本；新版本、失败、不完整、缺失或重复关联的最新读取都不复活旧正文。仅在某路径有旧候选时才解码其近期元数据，原结果超过 32768 个字符则保守放弃该路径，不解码大正文来猜版本。

保留优先级为完整命名声明、与已可见范围不重叠的窗口、最近观察。候选若已被同版本的可见完整窗口覆盖（包括相邻窗口的合并覆盖），继续省略；文件头不会代替未覆盖的类或函数。同路径不同范围不算重复，不同版本不合并。部分重叠窗口只作为整体候选，放不下就省略，不截取、拼接或重新读取正文。这不保证最优任务相关性，有限预算仍可能减少其他文件的覆盖。

旧版缺少 `range_complete` 的历史会根据原调用和行位置核对窗口。仅完整文件、完整请求行窗口或完整命名声明可选，命名声明的位置和名称也要与调用一致；字节页、首行截断或输出缺行不自动拼接。

恢复正文仍位于原历史位置，标记 `context_retained=true` 与“可能过时”的提示，并移除 `read_id`。文件后来可能被编辑、命令或外部程序改变；历史 SHA 只标识旧观察，不能据此声称当前文件或验收已通过。后续编辑继续由后端执行版本校验、只读/取消/路径限制与新批准。旧批准不重放，恢复会话不会恢复旧读取标识的有效性。

用户要求、错误、拒绝、最新失败检查、工具状态与最近保护窗口不为腾空间而删除。脱敏发生在候选选择和实际字节计数之前；没有额外读取文件或重新识别历史秘密。显式保存的会话仍是不加密的私有记录，应避免将敏感内容放入任务或附件。

这一选择参考了 [Aider、OpenCode 与 Pi 的官方实现调研](context-retention-research-20261019.md)，只借鉴源码与历史采用不同保留策略的思路。它不是这些项目摘要系统的复刻，也不代表真实编码能力已达到它们的水平。

本地回归覆盖 Unicode/转义/脱敏的精确边界、独立保留与请求预算、最近路径策略、完整性/来源拒绝、取消、阈值和大正文拒绝前不构造完整 JSON。真实回环 HTTP 验证历史快照可见、旧读取标识被拒绝、重新读取后编辑与独立最终检查分别需要批准。真实模型效果仍需独立验证。

## 2026-10-19 初版固定历史离线对照

初版功能提交 `800b0b5e96eeba02e81e5cb8bd80d20337912634` 与冻结的 `85499d3a38b77cbf3d83326cf34bf68c7fc13217` 在同一份 Click 失败会话历史上重放请求准备。初版按路径只取最近一次读取，与上文后续按版本/覆盖范围选择的策略不同。完整请求上限仍为 32768 字节，保留额度为 8192，不新增任务、读取、候选执行或模型请求。[数值报告](benchmarks/context-retention-click-20261019.json)记录源码、私有历史及复现驱动摘要，以及每个可见窗口的路径、范围和内容版本。

| 历史位置 | 旧请求字节 | 新请求字节 | 可见源码窗口/不同文件：旧 → 新 | 新保留结果编码字节 |
| --- | ---: | ---: | --- | ---: |

空间不足的位置保持原请求不变；后两项保留两个旧完整窗口，同时遵守原硬上限。保留额度包含整个结果，原省略标记被替换，因此与请求增长字节不相等。新窗口逐项验证正文与原历史一致、没有 `read_id`；用户消息、最近六条、最新固定检查、错误/拒绝及工具状态均保持不变，原会话文件摘要未变。`restored_by_retention=false` 只表示该窗口没有被新策略恢复，不表示保存历史中的读取是本次新观察。

旧大小由冻结实现复现，其中最初未发送项的请求摘要与已发布旧报告一致；后两项旧大小与此前实际 HTTP 测量一致。新大小均由标准 JSON 编码长度复核，**新请求没有实际发送**。这是源码信息保留的确定性证据，不能换算成 token/费用节省或模型修复率提高；旧 Click 失败结果不变。
