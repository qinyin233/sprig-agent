# 按文件发现与计数

`search` 增加可选的 `output_mode`，便于先找出相关文件，再读取实现。默认 `content` 的匹配行格式保持不变；`files` 和 `count` 不返回源码正文，也不增加文件扫描、输出或模型请求预算。

```json
{"query":"NoSuchCommand|NoSuchOption","regex":true,"glob":"*.py","output_mode":"files"}
```

文件模式返回 `files: [{"path": "src/example.py"}]` 和 `output_mode: "files"`。每个匹配文件只占一条记录；完整校验受限文件后，找到第一个匹配行即可停止该文件的匹配，继续检查其他文件。它适合某个文件有大量命中、但当前只需要定位文件的情况。结果不提供编辑读取标识；接着使用 `read_file` 的编号行或精确声明读取来检查代码。

```json
{"query":"deprecated","path":"src","ignore_case":true,"output_mode":"count","limit":100}
```

计数模式返回 `files: [{"path": "src/example.py", "count": 12}]` 和 `output_mode: "count"`。只返回有匹配的文件，`count` 是**匹配的物理 CR/LF 行数**，同一行多次出现只计一次；文件末尾不额外产生一行。它不是子串出现次数。每条计数必须完成该文件的匹配扫描；正则预算在文件中途耗尽时，省略该文件的半截计数，保留此前已完成的记录，并标记 `timed_out` 与 `truncated`。

| 参数或结果 | 语义 |
| --- | --- |
| `output_mode` | `content`（默认）、`files`、`count`；非法值在读取前拒绝 |
| `context` | 内容模式仍为 0–10；文件/计数模式必须为 0，冲突时明确拒绝 |
| `limit` | 默认 100、最多 1000 条结果；内容模式按匹配行、另两种模式按匹配文件计算 |
| `glob`、`path` | 复用现有工作区路径、大小写敏感 glob 和隐私过滤，在读取不相关文件前筛选 |
| `truncated`、`skipped_files`、`timed_out` | 有遗漏、跳过或超时就不能用结果证明全局不存在；已有计数也不是全仓库总数 |

输出记录按完整 JSON 大小及已知凭据脱敏后的大小核算，放不下时整条省略，不截断路径或计数字段。单文件仍最多 512 KiB、总读取仍最多 8 MiB，遍历仍最多 5000 个条目和 32 层。只返回路径和计数也先检查完整受限文件的隐私、UTF-8 与二进制内容；敏感值出现在命中行以外同样不能绕过检查。正则的 RE2 资源与协作工作预算、取消、只读及工具禁用规则保持有效。详见[正则检索边界](regex-search.md)。

默认仍是字面查询，`A|B` 会查找这个完整字符串。未返回记录的字面查询如果含有正则元字符，且提示能放进输出限额，会附加 `search_guidance`，提醒显式使用 `regex=true`；不会改写查询、自动重试或创建额外模型请求。提示不判断表达式是否有效，也不证明备选名称不存在。

显式历史压缩可省略旧成功结果的文件列表和提示，保留模式、覆盖标记、最近消息及完整保存历史。超时等失败仍保留。数值诊断区分返回的匹配文件数与匹配行数；文件模式没有完整行计数，不伪造该统计。

这些是工具能力与协议保证。真实模型是否采用这些模式、是否减少请求或提高编码成功率，仍需独立实测。

## 离线文件发现复核

功能源码 `77b9da3a519b6ff9273ce38e4c6bbcb8d01d4df0` 的[Windows 报告](benchmarks/search-modes-20261018-windows.json)与[WSL Linux 报告](benchmarks/search-modes-20261018-linux.json)使用相同驱动、源码字节、锁文件和输入摘要，四个场景的数值结果一致。每次调用创建新的 Tools 实例，限制为 6000 字节输出、1000 条记录、零上下文；没有模型请求、命令工具或候选源码执行。

| 输入与查询 | 内容结果 JSON 字节 | 文件模式字节 | 计数模式字节 | 文件发现及计数 |
| --- | ---: | ---: | ---: | --- |
| 40 个文件各 800 个匹配物理行 | 5953 | 1258 | 1818 | 内容返回首个文件的 90 行后截断；文件/计数模式均列全 40 个文件，计数合计 32000 行 |
| 保留 Click 候选，`src/click` 内字面 `NoSuch` | 1152 | 274 | 322 | 三种模式均覆盖 4 个文件；内容与计数均为 10 个匹配行 |
| 同候选，显式异常名称分支正则 | 2038 | 332 | 392 | 三种模式均覆盖 5 个文件；内容与计数均为 16 个匹配行 |
| 同候选，显式测试器分支正则 | 227 | 189 | 201 | 三种模式均覆盖 1 个文件、1 个匹配行 |

Click 输入是[真实失败恢复记录](live-evaluation-named-20261018.md)使用的旧候选，52 文件摘要为 `cd5c28d37e22ac09236d52349599776c220648241ec2410c02585c13c0d34bc6`，不是原始上游初始快照。检查器从原始 UTF-8 内容独立枚举物理行，使用字面匹配或这些简单表达式的 Python `re` 结果核对每个返回位置、文件集合和计数；不调用 Sprig 的匹配生成器来生成预期值。这不能证明 Python `re` 与 RE2 的全部语法相同。原快照和临时副本前后摘要一致；公开报告只含固定查询、摘要和数值，不含返回正文、私有绝对路径或会话。

各模式的输出契约不同，表内字节数不是相同正文的压缩率，也不是模型 token 或账单。密集场景的内容模式读取 1 文件、12000 字节就停止，新模式为列全结果读取 40 文件、480000 字节；不会将较少输出误报为较少磁盘读取或更低延迟。三个 Click 场景中，各模式实际文件读取量相同。没有计时成绩、真实模型采用证据或新任务验收成绩。

共享检出上早期 WSL 的 `git diff` 预检未通过，尚未进入测量；当时 Windows 报告与对应驱动保留在私有目录。最终共同驱动逐个比较固定提交中的 Python 源码内容（仅在此比对中统一 CRLF），另外保留实际原始源码字节摘要，不依赖共享索引的模式位/工作树状态。最终两份报告的源码和驱动摘要一致。测量为本地 Windows Python 3.13.0 与 WSL Python 3.13.14，不代表远程 Ubuntu runner 或 macOS 验证；功能提交和本记录使用 `[skip ci]`。
