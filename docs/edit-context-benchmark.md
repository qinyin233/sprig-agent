# 大块编辑的上下文回放

日期：2026-10-05。本入口针对一个实际代码缺口：原有显式压缩仅省略旧工具输出，历史 `edit_file` 的大块 `old/new` 仍反复发送，工具结果很小时几乎无法缩减。在 131,072 字节请求预算下，多文件任务可能在已完成部分写入后停止。

现行开源实现也将长会话处理单列为能力：OpenCode 的 [compaction](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/compaction.ts)包含旧工具输出清理和模型摘要，Pi 的 [compaction](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/src/core/compaction/compaction.ts)跟踪保留上下文和文件操作。Sprig 本次增加的是可预览、显式启用的历史编辑正文省略，不能称为同等的模型摘要或自然长任务表现。

## 产品行为

`--compact-context`、CLI `/compact` 或 TUI“压缩旧工具记录”显式启用。每个旧编辑必须关联唯一旧调用和旧结果，结果 `approved`、`changed` 均严格为 `true`，返回路径与参数路径一致，且没有错误、跳过、取消、超限或不确定状态。单次替换、创建文件与同文件多片段都支持；收益不足 128 字节的记录不改动。

只在请求副本中把历史编辑参数改为路径和“已完成、正文省略、不可执行、需重读实际文件”的 JSON 标记。它是历史说明，不满足新 `edit_file` 的参数形式，调用工具入口会拒绝它；应用不从历史执行动作。保存的原始参数、正文和结果保持完整。系统与用户消息、助手解释、调用 ID、工具结果顺序、最近六条消息以及失败/拒绝/未完成/无改动/不确定的编辑保留。结果位于最近六条消息内时，其更早的调用也保留。

请求统计在替换后按实际序列化体重算，包含新增省略标记的密钥遮盖；没有缩减时避免额外整体验算。压缩中取消会在调用 provider 前停止。用户要求或受保护消息本身超预算时仍停止，不自动删除记录、放宽限额、摘要用户要求或申请新权限。

## 可重复的离线流程

```powershell
uv run --locked python scripts/benchmark-tools.py --edit-context --compare-ref 1b6901746d5248ebfdb369e37906abe1928b57a4 --repeat 5
```

两版从明确本地源码导入 `Agent`，核对实际来源，运行同一个[固定夹具](../benchmarks/context/replay.py)。每轮创建一次性工作目录和外部私有会话目录。只绑定 loopback HTTP 地址；服务端按固定顺序回复六次编辑和结束消息，不连接模型、不读取凭证，也不解释自由任务。六个文件每个把 20,000 个 `x` 改为 20,000 个 `y`。默认请求上限保持 131,072；两版均显式开启压缩。输出上限 65,536 用于容纳这些已知 diff，不代表产品默认值被提高。

工具实际展示完整 diff，并经过仅接受这六个已知 diff 的逐次夹具批准；固定验收命令也单独获得一次批准。批准回调拒绝任何其他动作。验收用当前 uv Python 检查六个文件的全部字节，记录真实退出码、超时和输出状态。命令使用原有 Windows Job / POSIX 进程组；会话每次保存意图、再保存结果，最终重新加载检查原始编辑参数。脚本中的批准只属于这个封闭夹具，产品审批方式保留。

服务端记录实际收到的 POST 字节和调用数，校验收到的完整调用/结果协议。与 provider 的传输统计独立核对；预算挡住的下一次请求不算 HTTP 请求。报告只包含数值、布尔状态和源码 / 驱动 / 锁文件 / 夹具身份，不包含原始对话、diff、命令输出或请求正文。

## 对照结果与边界

[Windows 原始报告](benchmarks/edit-context-windows.json)保留每版五轮、每轮请求大小、停止位置、编辑/验收批准次数、文件效果、验收状态和原始会话完整性。

| 项目 | 旧版显式压缩 | 新版显式压缩 |
| --- | --- | --- |
| 实际 POST | 4 | 7 |
| 已批准并完成的文件修改 | 4 / 6 | 6 / 6 |
| 固定验收执行 | 0 | 1 次批准，检查通过 |
| 128 KiB 预算 | 下一次请求在发送前停止 | 每次实际 POST 都在上限内 |
| 已完成编辑的原始保存参数 | 完整 | 完整 |

五轮均得到相同停止位置和字节数。旧版下一次准备发送的请求为 166,498 字节，被应用挡住；新版最大实际 POST 为 127,813 字节。服务端的请求数与 provider 统计相同，六次编辑与一次验收各自经过夹具批准，已加载的会话保留六组完整原始参数。

请求增加来自流程完成得更远，不能解释为更低请求数、更低 token/费用或更短整体延迟。夹具指令和编辑参数均来自固定脚本，没有模型定位、规划、生成代码或自然长期引导；这是请求压力与执行链回归，不是 agent 编码成功率。真正服务对历史省略标记的兼容性、自然长会话表现及同模型复杂仓库对照仍待验证。平台测试跳过项不计为通过，远程 CI 按额度限制随大更新运行。

本批本地全量测试均运行 361 项：Windows Python 3.11 / 3.13 各 348 通过、13 项 POSIX 检查跳过；WSL Linux Python 3.12 为 345 通过、16 项平台检查跳过。TUI Pilot 验证新增说明、默认 Enter 拒绝和明确批准；读写、请求预算、失败保留、重复 ID 拦截、压缩中取消、固定验收和完整会话均实际覆盖。本批跳过 GitHub CI，本地结果不等于远程矩阵通过。
