# 在外部编辑器中编写草稿

TUI 空闲时按 **Ctrl+G**，或输入 `/editor` 打开空白草稿。编辑器退出后，内容回到输入框，由 **Enter** 发送；打开、编辑和返回均不调用模型。执行中的普通 Enter 引导保持原有行为；当前模型任务或模态窗口未结束时，不能启动外部编辑器。聊天 CLI 的 `/editor` 仅提示进入 TUI。

## 配置与批准

在私有用户配置或可信 profile 中设置：

```toml
[editor]
command = ["nvim", "{file}"]
timeout = 300
```

`command=[]` 默认关闭。最多 32 个字面 argv，合计最多 8 KiB；不解析 `EDITOR` / `VISUAL`，不展开 shell、环境变量或引号。最多一个独立的 `{file}` 参数；省略时将私有草稿路径追加到最后。Windows 使用实际的原生可执行文件，例如按实际安装路径填写 `["C:/Program Files/Microsoft VS Code/Code.exe", "--wait", "{file}"]`。批处理启动器须明确指定解释器，审阅其 shell 语义；不会隐式改用 shell。

编辑器必须等待用户完成保存并关闭文件，提前返回的 GUI 启动器不提供可靠的完成信号。默认期限 300 秒，上限 3600 秒。项目配置不能指定编辑器；`/config` 展示已生效的 argv、期限与来源。`[tui.keybindings].external_editor=["f8"]` 可添加别名，Ctrl+G 与既有输入/审批键保持固定。

每次调用都新批准准确 argv、临时目录、期限和草稿字节数/摘要。只读模式、禁用 run、已配置凭据出现在草稿或参数中时拒绝执行。拒绝、Esc、批准前 Ctrl+C，以及批准期间的草稿/会话/配置变化都会阻止旧提案。没有新的模型工具能够启动这个用户终端操作。

## 文本、附件和预算

启动前展开真实长粘贴元数据，保留缩进、首尾空白和普通 Unicode；不会把可见占位标记当作完整正文。返回内容必须完整 UTF-8，CRLF/CR 归一为 LF，拒绝终端控制字符。原始文件和完整展开草稿均最多 2 MiB，不静默截断；空文件可以清空草稿。

返回后是一次可撤销的文字替换，保留粘贴撤销/重做。既有内联文件选择只在明确选中的标记仍位于未改动区域时保留；改变或移动标记会使选择失效，编辑器新写出的 `@` 标签不会自动附加文件。撤销文字不恢复已失效的文件授权。已有 `/add` 快照和 `/ref` 引用保持各自语义，文件内容仍在实际发送前检查。

编辑结果作为字面任务文本，首行 `/new` 等内容也不会在下一次 Enter 时自动成为本地命令。完整模型请求仍受原有字节预算；即使编辑器返回成功，发送预检失败也保留草稿，等待用户调整。返回不产生模型请求、会话分支或自动续跑。

## 文件和进程边界

每次生成随机的仓库外私有目录和 `draft.md`，批准后才创建文件。POSIX 使用 0700 目录、0600 草稿及子进程 0077 umask；Windows 使用本用户保护 ACL。Windows 原子保存产生替换文件时，先按固定临时路径、普通文件、单链接和大小检查，再按句柄收紧 owner/DACL，随后沿用严格私有读取；拒绝重解析点和硬链接后才改变权限。对应 Windows API 见 [SetSecurityInfo](https://learn.microsoft.com/en-us/windows/win32/api/aclapi/nf-aclapi-setsecurityinfo)。

只在退出 0、取消/策略复查通过、文件身份和读取期间状态稳定后导入。非零退出、删除文件、无效 UTF-8、超限、权限错误或超时均保留原草稿；不重新启动命令。清理只移除已知 `draft.md` 和空目录，不递归删除编辑器创建的其他文件；有 swap/备份等残留时保留私有目录并提示手动检查。

编辑期间键盘和画面由外部程序控制，Sprig 不将终端画面采集为工具输出；导入文本和后续请求仍有界。POSIX 交接并恢复前台进程组，Windows 使用从启动起归属的 Job Object；超时/取消清理所拥有的进程组或 Job。外部程序、插件和转交给既有 GUI 实例的行为拥有当前用户权限，不能视为 OS 沙箱。此功能也不向模型提供 PTY、终端仿真或按键注入。

终端恢复后再报告运行异常，避免异常直接穿过 Textual 8.2.8 的 suspend yield 而跳过恢复。执行批准也清除旧读取版本/语法缓存，并使界面中的旧验收结论失效；实际工作区仍需独立检查。

## 验证范围

新增 21 项自动测试包含真实文件/进程、原子保存、权限、硬链接、POSIX FIFO/链接、超时/取消及子孙清理、凭据过滤、真实 stdin、配置合并、草稿/附件/长粘贴、拒绝与过期批准，以及三协议 JSON/SSE 的六条完整发送链。完整本地回归两端各 1679 项，均为 1655 通过、24 项平台跳过；Windows Python 3.11 新增 21 项为 20 通过、1 项 POSIX 跳过，两套 SDK 环境在两端各 30 项通过。

最终应用模块和自动测试与完整回归快照一致；末次仅修正独立手动终端夹具的观察时序和完整完成门禁。最终夹具在 WindowsDriver / LinuxDriver 的真实终端中依次完成键盘交接、固定文本输入、草稿返回和恢复后的 Enter；请求数从发送前 0 到发送后 1，该请求使用固定回复，没有外部模型调用。它不证明所有第三方编辑器/GUI/插件组合均可用，也不证明编码成功率提高。源码阅读见[上游对照](research/opencode-external-editor-20261028.md)，数值、失败和源码身份见[机器记录](benchmarks/external-editor-20261028.json)。远程原生 CI 继续待解禁验证，11 月 1 日前不触发。
