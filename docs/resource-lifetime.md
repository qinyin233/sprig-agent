# 关闭后的目录与工具

目录句柄关闭后，文件读取、扫描、写入、替换、删除、创建目录、私有权限检查和锁操作都必须拒绝执行。原先 POSIX 的 `dir_fd=None` 会让部分相对路径操作退回进程当前目录；Windows 的部分路径操作也能在目录句柄关闭后继续访问原路径。这是在新本地 HTTP 测试关闭工具后继续预览上下文时发现的边界问题，不是模型测试结果。

`Directory.ensure_open()` 现在在所有新操作前检查句柄，包含子目录构造与上下文进入；关闭保持幂等。`Tools.execute()` 和目录遍历入口也检查根句柄，使关闭后的模型工具派发及直接命令入口在批准前失败。不会因为句柄关闭而重新打开原目录，也不会退回当前目录。它检查新操作的生命周期，不替代取消机制、操作中途的并发关闭同步或 OS 沙箱。

回归在一次性工作区与外部目录放置同名文件，再把进程当前目录切换到外部目录。关闭后逐项调用全部目录操作和工具，要求报固定关闭错误、没有批准请求、两个目录的文件内容与结构均不变。生成配置的上下文预览则在工具仍存活时完成，避免测试依赖关闭后的未定义使用。

原有全版本 CI 矩阵保持不变。新增 `Native regression` 仅手动触发，在 Ubuntu、Windows 的 Python 3.13 上运行完整根测试与 CLI 检查，先要求 GitHub 实际运行 SHA 等于输入的 `expected_sha`。小提交仍可用 `[skip ci]` 跳过自动大矩阵；涉及原生 OS 的批次显式运行两个必要作业，并逐一等待。此范围不包括 macOS、其他 Python 版本或真实模型性能；不能用这两个作业宣称全部平台/版本通过。
