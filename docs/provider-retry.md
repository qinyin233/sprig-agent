# 明确启用的模型 HTTP 重试

提供商的临时限流或服务错误可在同一次模型步骤内重试，无需重新发送任务。考虑额度，默认 `retry_attempts = 0`；需要时在私有配置中明确启用：

```toml
[providers.my_provider]
model = "your-model"
base_url = "https://your-provider.example/v1"
api_key_env = "YOUR_API_KEY"
retry_attempts = 2
request_deadline = 300
```

或使用 `--retry-attempts 2` 覆盖。整数范围 0–5，表示**额外尝试次数**，所以 2 最多产生 3 次 HTTP 尝试。配置、来源和 `--show-config` 均可检查；切换模型确认显示目标策略。它不改变模型 JSON、工具定义或模型步骤上限，但启用后可增加实际 HTTP 请求和用量，不是费用上限。

## 哪些情况会重试

Chat Completions、Messages、Responses 共用策略，JSON/SSE 相同。仅当服务明确返回 HTTP **429、500、502、503、504**，且尚有次数和总期限时重试。请求体和鉴权头仅准备一次，重发相同字节；配置改变则停止，不把旧凭据转发到新端点。上述状态的失败响应收到头部后即关闭。用户开启会话恢复时，明确的上下文超限可以触发摘要确认，之后发送更短的任务请求。[长会话恢复](summary-checkpoints.md#在任务中恢复)

退避基础间隔为 1、2、4、8、10 秒，添加至多 25% 抖动，每个基础间隔含抖动不超过 10 秒。单一合法 `Retry-After` 秒数或完整标准 GMT 日期（如 `Sun, 25 Oct 2026 08:30:00 GMT`）作为最短等待时间；非法、重复、过长或超过 24 小时的字段使该次错误不能自动重试。非标准日期写法或日期后的多余文字也拒绝。等待放不进剩余总期限时直接返回错误，**不截短服务要求后提前重发**。

从第一次封包完成开始，所有尝试和退避共用 `request_deadline`，不会每次重新得到 300 秒。每次网络尝试重新计算空闲期限；退避等待不算网络空闲。取消与配置检查约每 100 毫秒轮询，实际 UI 调度和系统 DNS 限制沿用[请求生命周期](request-lifecycle.md)。

## 不完整交付与操作批准

网络/TLS/连接错误、socket 超时、总期限到达、重定向、非法 JSON、输出 token 上限及不完整 SSE **均不重试**，即使已配置次数。HTTP 200 后的解析失败不能转成一次新 POST；已展示的流式文字不会被新的响应拼接，也不会据半份工具参数执行动作。

重试不执行工具、不复用批准、不重新运行先前的命令和编辑。完整响应仍走原有校验与逐次批准；等待期间送入的新要求仍在安全节点处理，旧提案不能越过新引导执行。TUI Ctrl+C 可取消等待，保留新要求供明确继续使用。终端显示状态、等待秒数和下一次尝试编号；这些本地提示不加入模型上下文或保存的对话。

`/summary create` 保持确认时“只发一次”的约定，强制不重试；`--list-models` 元数据请求也不采用此策略。没有自动切换模型、提供商或协议，重试耗尽后不自动恢复任务。

## 用量与会话

`/usage` 对每个进入传输入口的尝试单独记录成功/错误、请求字节和耗时；这不保证服务收到请求。退避结束前取消或失败属于 `not_attempted`。HTTP 错误的 token 用量保持未知，最终成功也会保留之前的错误记录。单条耗时和首文字延迟从进入该次传输时计算，完整调用墙钟时间另含此前的退避等待。

非零重试次数加入会话绑定，改变策略后不能静默恢复旧会话；零值保留原有绑定形状。恢复不重放失败请求，需用原策略恢复或建立新会话。已发出的失败请求是否被服务计费仍由服务决定。

本地测试使用一次性文件、脚本化回环 HTTP 和真实 Textual；没有外部模型调用，不据此推断真实任务成功率或所有网关均可恢复。最终源码、验证及隔离反例范围见[机器记录](benchmarks/provider-retry-20261025.json)。2026-11-01 前继续暂停 GitHub Actions。
