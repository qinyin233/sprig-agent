# 完整文本附件与读取预算

CLI `--file`、chat/TUI `/add`、文件选择器的“附加快照”和本轮 `@` 文件选择共用完整 UTF-8 快照读取。附件不再经过模型 `read_file` 的展示窗口，不会因 `max_output` 较小或超过 10000 行而变成部分正文。

| 约束 | 当前行为 |
| --- | --- |
| 文件数 | 每批 1–16 个工作区文件 |
| 本地读取 | 单文件最多 1 MiB、整批最多 2 MiB 原始字节；按 64 KiB 块读取并检查取消 |
| 内容 | 完整 UTF-8 文本，保留 BOM、CRLF 和 Unicode；拒绝 NUL、无效 UTF-8 和疑似凭据模式，已配置的秘密继续脱敏 |
| 请求 | 原有 `max_context_bytes` 硬上限；规则、历史、工具、文件路径、完整正文及 JSON 转义全部计入 |
| 显示 | `max_output` 继续约束模型文件工具和命令展示；附件回执只显示路径与原始字节数 |

本地读取上限与模型请求预算分别检查。原始大小能放进读取上限，不表示序列化后的完整请求能发送；已配置的秘密脱敏和 JSON 转义也会改变实际字节数。超出任一限制都报错，不截取前缀，不自动增加上下文或重试。

例如较大源码可由用户明确选择更合适的现有上下文预算：

```powershell
uv run --locked sprig --tui --max-context-bytes 524288 --file src/main.py
```

文件以内联文本进入模型上下文，未增加远程文件上传服务或绕过模型自己的上下文限制。当前仍没有图片、PDF 或音频的多模态输入后端；本批没有为二进制文件增加例外。

## 隐私、取消与批次一致性

读取前检查当前根句柄、read_file 开关、工作区相对路径和文件隐私规则，继续使用现有 Windows/POSIX 的无跟随目录与普通文件句柄。过大文件先由元数据拒绝，读取中增长超过上限也拒绝，不能上传未验证后部的干净前缀。

每个文件比较读取前后版本；整批读取结束后，再检查所有路径的隐私和版本。准备过程中普通修改、替换或 `.sprigignore` 撤销会使整批失败，不加入部分附件。这些是有时间范围的观察，不是多文件锁，也不能保证后来磁盘仍未变化。

文件选择元数据、取消、闭合资源和工具禁用不会被附件入口绕过。完整请求预算失败发生在历史提交、任务前检查和模型请求之前；TUI 保留本轮草稿与文件选择，重试会重新读取当前内容。写入和命令仍分别取得新的具体批准，附件不产生编辑 read_id 或审批证据。

## 生命周期

`--file` 与 `/add` 把固定快照加入当前对话；启用保存后正文也在私有会话中。后续源文件变化不会刷新这个历史快照。`@` 所选文件只用于本次任务调用，跨该调用的工具步骤保留，结束后清除，不把正文写进保存历史。

实时 `/ref` 的刷新规则保持原样：小文件受原来的 32 KiB 与 `max_output` 门槛约束，大文件只提供路径/大小。已有引用集合不会因为这次更新自动上传更多正文。超过快照或请求预算时，可选择引用和有界范围读取；超过模型文件工具的扫描上限仍需其他明确批准的处理方式。

## 验证

15 项新增回归覆盖完整输入和相关安全边界。其中大型正文采用 132030 字节、12002 行的合成文本，包含 BOM、CRLF、中文、emoji、引号和反斜杠。历史快照/本轮快照 × 三协议 × JSON/SSE 共 12 组实际回环请求均检查完整正文，模型读取展示仍限制为 256 字节。另覆盖完整上下文驱动的真实文件编辑与独立新批准验收、命令行、80×24 TUI、预算失败保留草稿及小正文重试。

安全边界包括大文件未读取正文即拒绝、剩余批次预算、读取中取消、后部凭据/NUL/无效 UTF-8、配置秘密脱敏、禁用/关闭资源、文件变化与后续读取中撤销前一路径。隔离父版本读取器会拒绝全部 12 个大输入组合，并漏掉该隐私撤销，见[机器记录](benchmarks/large-snapshots-20261024.json)。

完整主测试首轮发现旧文件选择取消测试仍拦截模型工具分发；测试钩子已移到实际解码边界，保留全部取消、无提交、无请求和草稿断言，再重新全量验证。具体最终范围以机器记录为准。没有新增外部模型调用或真实编码胜率结论，远端 CI 按冻结要求待验证。
