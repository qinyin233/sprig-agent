# 固定检查与长任务上下文

开启 `compact_context` 后，旧工具正文的省略现在也覆盖两类历史冗余。改动只影响待发送请求，完整保存历史、最近保护窗口、用户要求和拒绝不改写；不发起额外模型请求，也不增加字节限额。

第一类是已经重新观察过的用户固定检查。只有 `run` 的参数恰为 `{"argv": [...]}`、argv 与当前用户配置的检查完整相等，并且两次结果都明确批准、完整退出、输出是字符串且没有错误、取消、跳过、超时或输出超限时，后来的结果才可以取代旧的详细输出。负退出码、不确定或格式异常的结果不能作为新的可靠观察；重复调用 ID 也不允许据此省略。

旧调用和结果都在最近保护窗口之外时，旧 argv 可变成明确标记为不可执行的历史说明；旧结果省略 `output`，保留 `approved`、`returncode` 和其他状态，通过 `check_ref` 指向较新的观察。它不假设两次输出相同：旧失败仍是失败，即使后一次已通过。最新失败保留完整输出；成功结果继续沿用原有旧成功输出压缩策略。普通失败命令、不匹配的检查、带额外 `cwd` 或 `timeout` 等参数的调用，仍按原有规则处理。

这不是检查缓存或批准记录复用。每次真正运行检查、修改文件或执行命令仍须取得新批准；历史说明不能作为工具输入重放。独立最终验收也不会因较新的阶段检查通过而省略。

第二类是正文已经省略的旧成功读取。与对应读取意图唯一匹配、路径一致时，一并省略原 SHA、短读取标识、行位置和 `next_offset` 等附属字段，保留 `truncated`、`line_truncated`、`range_complete`、`symbol_complete` 等原有覆盖标记。字节分页的 `next_cursor` 不在这次省略范围内，继续受原有版本校验约束。工具调用参数仍保留原路径和选择条件；标记说明要重新读取源码。这些旧元数据不能代替已经丢弃的正文证据，也不提供当前编辑授权。正文仍在最近窗口内的读取不改变。

请求大小继续使用实际 UTF-8 JSON 字节计数，并在发送前检查完整请求。长用户要求、最近的大输出、不同命令的失败或多个尚无新观察的检查仍可能超限；压缩不能保证任意历史都放得下。完整性标记描述原始观察，`context_elided` 表明当前请求没有它的完整正文。
