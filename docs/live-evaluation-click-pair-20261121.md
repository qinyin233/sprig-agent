# Sprig 与 mini-SWE-agent 的 Click 实测

2026 年 11 月 21 日，用 USTC `deepseek-flash-2` 在原生 Windows 顺序运行 Sprig 和 mini-SWE-agent 2.4.6。两次运行均从同一份 52 文件快照开始，使用相同的任务文本和外部验收文件。运行源码对应提交 `771e52f6e209792a5549039b3c89eafb396f85ec`。原始快照的离线校准为 635/642，参考实现为 642/642，两次校准均零跳过。公开异常契约单独检查，原始快照失败，参考实现通过。[任务协议](repository-task-benchmark.md) · [数值与摘要](benchmarks/click-pair-20261121.json)

| 客户端 | 停止原因 | HTTP 尝试 / HTTP 200 | 模型循环审批通过 / 拒绝 | 独立后置验收 |
| --- | --- | ---: | ---: | --- |
| Sprig | 第 8 次 HTTP 尝试超时 | 8 / 7 | 1 / 0 | 635/642，零跳过，公开异常契约失败 |
| mini-SWE-agent 2.4.6 | 12 次请求预算用尽 | 12 / 12 | 27 / 2 | 未执行，独立审批等待超时 |

Sprig 收到 7 个有效回复，调用了 7 次 `grep`、6 次 `read_file` 和 1 次 `list_files`，尚未提出写入。循环中的一次审批用于运行基线，独立验收另行批准。mini 发起 28 次 Bash 调用和一次基线命令。两次被拒绝的调用都试图导入未限定到候选快照的 Click。其余命令仅检查现有文件或在内存中验证字符串匹配，无写入。一次候选文件核对显示 52 个文件与初始快照一致，之后获批的命令也未写入。mini 的独立验收等待时间耗尽，临时工作区随后被清理，因此该行保留为未测。

两个客户端均使用各自的 uv 锁定环境、Python 3.12.12 和 pytest 8.4.2。模型请求走非流式 Chat Completions，同一配置端点，名义上限为 12 次请求，每次 2048 输出 token 和 131072 请求字节。命令超时为 60 秒，请求超时设置为 120 秒。Sprig 另有 180 秒单请求总期限，启用原有确定性上下文压缩并保留供应商推理状态。Sprig 使用系统代理模式，mini 显式直连。两者的工具、提示模板、传输及历史处理各有差异，这次结果无法区分这些因素对运行的影响，也无法据此判定超时发生在供应商还是网络链路。

供应商为 Sprig 的 7 次请求报告了 64,443 token，超时请求的用量未知。mini 的 12 次请求均有用量报告，合计 153,212 token。两条记录保留各自的用量覆盖；实际费用未知。两款客户端在这次尝试中均未完成任务，这组数据不足以比较速度、成本或综合编码能力。

独立验收入口所在提交的本地全量回归在 Windows 为 1,928 项通过、47 项跳过，在 WSL 为 1,949 项通过、26 项跳过。对应的 Click Sprig 和 mini 集成套件分别通过 5 项和 3 项。提交使用 `[skip ci]`，GitHub Actions 继续暂停。
