# 实时文件引用

`/add` 和 `--file` 仍是加入对话历史的固定快照。需要模型在下一次请求看到修改后的文件时，可显式维护引用集合：

```toml
[context]
files = ["src/main.py", "tests/test_main.py"]
```

```sh
uv run --locked sprig --tui --ref-file src/main.py
uv run --locked sprig --cli --reference-file logs/build.log "检查日志中的失败"
```

TUI 和连续 chat 都支持：

| 命令 | 行为 |
| --- | --- |
| `/ref PATH` | 加入引用，预检全部选中文件和实际请求预算；任一失败保留原集合 |
| `/unref PATH` | 移除引用，不要求源文件仍存在或可读取 |
| `/refs` | 查看所选路径及上次准备的元数据；不读取文件、不联网 |
| `/refs clear` | 清空引用，即使文件失效、变成私有或剩余历史超出请求预算也可移除 |

这些操作不执行命令或调用模型。TUI 在空闲时修改集合；运行中可继续发送普通引导，先取消任务再修改引用。整段参数作为一个路径，允许空格；Windows 支持本机反斜杠及工作区内绝对路径，并接受一层路径引号。TOML 和保存格式使用相对 POSIX 路径；相对路径也可在所有平台使用。

## 有界刷新

每次模型请求前重新校验文件路径、启用的 `read_file`、当前隐私规则与文件句柄；只读取工作区内普通文件，不跟随符号链接或 Windows 重解析点。越界、活动配置、排除项或不可读文件使准备失败，整次请求不调用 provider。读取和预算处理响应取消。

文件不超过 `min(32768, max_output)` 字节时，尝试取得完整 UTF-8 内容。必须通过既有完整文件隐私检查和 10,000 行窗口，输出也完整才附加正文；不把前缀当作完整文件。可用时携带本次 SHA 和短读取标识，后续编辑仍复核当前版本并请求新批准。已配置秘密值按现有规则遮盖；二进制、无效 UTF-8 或内置凭据模式错误会拒绝，不静默退回上传前缀。

较大文件、超过行窗口或无法在输出预算内完整呈现的文件只附加 `path`、`bytes` 和 `content_attached=false`；没有正文、摘要或编辑读取标识。超过 8 MiB 时额外标明超出当前 `read_file` 扫描上限。模型可按需提出既有读取或命令，但引用不提高读取上限、不自动执行命令。**仅有路径和大小的文件没有经过正文隐私/编码检查，也不能据此认定正文安全或已读取。**

最多选择 16 个文件，单个相对路径最多 4096 个 UTF-8 字节，全部路径最多 8192 字节；完整正文合计最多 128 KiB。所有转义、元数据、规则、历史和工具定义继续计入实际请求字节硬限额。超限不自动截断、扩大预算或重试。准备结束重新检查元数据与隐私，发现准备过程中的普通并发变化会停止；这不是多文件原子快照，也不保证随后磁盘不变。

## 会话与输入

刷新正文仅作为当前请求的额外用户上下文发送，明确标为不可信文件数据；不因引用本身反复复制到完整历史。启用保存后，私有未加密会话保存引用路径和上次准备记录（大小、是否附加正文及可用摘要），不保存引用正文或短读取标识。模型回答、显式工具读取、编辑参数仍可能引用源码并进入普通历史，不能将这个功能理解为源码绝不落盘。

记录表示“已准备”，不证明模型服务收到或磁盘仍是相同版本。恢复只恢复元数据，不读取源文件、不重放操作；下一次显式请求才重新校验与刷新。`[context].files` 是新应用的初始选择，恢复时沿用保存的集合，显式 CLI 引用标志再合并；TUI `/new` 清空运行时选择。旧会话没有引用字段时仍可恢复。移除引用不删除历史中已存在的快照、模型文字或工具结果。

TUI 普通任务在本地预检完成前保留草稿，包括完整请求预算失败或引用失效。修正后原样再次 Enter 会继续已保留任务，避免重复；也可显式 `/continue`。真正调用 provider 后才清空未改动的已发送草稿；期间编辑的新文字保留，运行中 Enter 引导继续使用原有安全队列。网络请求发起后的失败不承诺恢复输入框。

本功能没有 `@` 模糊补全、图片/PDF 解析、通用上传下载或远程断点传输；大文本仍使用行范围、声明读取或版本绑定的 UTF-8 字节页。离线回归覆盖实际回环 HTTP、刷新后整行编辑与独立验收、会话正文隔离、CLI 恢复合并、TUI 草稿与路径边界；这些协议夹具不能证明真实模型编码效果或顶尖 agent 性能。
