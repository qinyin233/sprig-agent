# 后台命令任务

长测试或服务可以在当前 Sprig 进程中后台运行，模型继续进行其他调查，用户可查看状态、等待、读取输出或停止任务。后台命令仍是有完整系统权限的外部程序，不是 OS 沙箱；每次启动都批准准确 argv/cwd、期限、环境名称及输出限制。

## 开启与操作

用户配置或可信 profile：

```toml
[execution]
background = true
background_timeout = 300

[tools]
run = true
job = true
```

也可启动时使用 `uv run --locked sprig --background --background-timeout 300`，`--no-background` 覆盖配置。默认关闭；项目层不能声明 execution，不能开启后台执行。关闭 run/job 或启用只读模式在执行层阻止启动，模型也不获得相应定义。开关及启用时的期限绑定会话，模型切换不能放宽策略。

启用后 `run` 接受 `background=true`，返回 `job_id`，不等待程序退出；仅后台可使用独立的 `background_timeout` 上限（默认 300 秒，最大 3600 秒）。普通前台命令仍受原有 timeout 上限限制。argv 不经过隐式 shell，cwd 仍为工作区相对 POSIX 路径，执行前和批准后复查路径、开发指令、取消和凭据。Windows 的批处理需明确批准 cmd.exe /c，不能隐式换解释器。

TUI/chat 本地入口：

```text
/jobs
/job start {"argv":["uv","run","python","-m","unittest","discover","-s","tests","-q"],"cwd":".","timeout":300}
/job status job-<ID>
/job wait job-<ID> 5
/job output job-<ID> 0
/job cancel job-<ID>
```

`job` 模型工具提供 list/status/output/wait/cancel；启动统一使用 run(background=true)。list 可带列表偏移，输出页有 next_offset。wait 的 seconds 最多 30 秒，模型未提供时只观察当前状态；本地 `/job wait ID` 默认等待 1 秒。等待可以取消，不重发命令。

启动和 cancel 都新批准。用户 Ctrl+C 明确取消当前任务和当前对话的全部后台命令，空闲时也有效；退出/关闭会停止当前归属的进程树。TUI 每隔短暂时间显示完成状态，空闲完成不自动请求模型，不自动继续任务。需要后续处理时用户正常 Enter 发送或继续。执行中输入引导的原有语义不变，批准中的新要求会拒绝旧启动。

## 状态、输出与验收

状态区分 running/exited/cancelled/timed_out/output_limited/failed/cleanup_failed。只有实际观察到自然退出时才有可靠退出码；取消、超时或清理失败不能伪装成退出 0。启动结果标为 started、task_completed=false；任务句柄不是可重放的命令，也不允许用任意 PID 停止其他进程。状态里的 command 是有截断标记的短预览，完整批准文本才是原 argv。

stdout/stderr 分别进行增量 UTF-8 解码和跨块脱敏，再合并为观察顺序的文字；不保证两路的全局时间顺序。命令应输出 UTF-8，其他编码按替代字符处理，不会自动修改任意程序的编码设置。stdin 默认立即关闭；后文说明显式开启的标准输入管道。PTY 和终端仿真仍未提供。

原始总输出仍受 output_limit 或 max_output 限制，超限会停止进程树。另有独立的**内存回查上限**：每任务最多 1 MiB 脱敏正文、最多 8 条记录，至多 4 条同时运行。超出内存上限明确标 retention_limited，程序可在原输出限制内继续；不要把未保留正文当成命令失败。新启动可淘汰已结束的旧记录，不能淘汰正在运行的所有权。

output 返回 UTF-8 字节 offset、end、next_offset、脱敏快照前缀 SHA-256 和不可信标记。续读时同时传回 end，可在输出继续增长时保持同一前缀；模型使用 job(action=output,job_id,offset,end)，本地命令 `/job output ID OFFSET END`。字符边界错误和越界明确拒绝。完整 JSON 页不超过 min(max_output,16384)，后台启动要求 max_output>=1024。新获知的凭据命中已存正文时，回查内容整体丢弃并禁止后续正文保留，程序状态与退出码独立保留。

默认后台输出仅在内存；同时配置 `storage.command_log_dir` 时，可在结束后提交同一私有日志 journal，详见下一节。已进入模型工具结果的片段仍可能作为普通私有会话历史保存。只保存历史文字/已观察状态，不保存后台进程、PID 归属或启动授权；恢复、历史分支、模型切换和新对话都不会重启命令。

模型在下一安全边界收到有界的结束状态，不把程序输出当开发指令。后台任务的启动/结束使旧文件读取标识与语法缓存失效。仍有任务运行或清理不确定时，最终结束保持未验收，固定基线/最终检查不启动，编辑后检查延后；等待或停止后需明确继续。检查过程中后台状态发生变化也不能宣布最终通过。后台命令退出 0 不是应用的固定验收，最终检查仍另起一次新批准。

## 完成后保留日志

同时开启 `execution.background` 和已有的 `storage.command_log_dir` 即可；不增加新开关、模型工具或依赖。启动具体命令的新批准会说明日志位置、单份/总容量、到期规则、额外捕获内存和延迟提交方式。拒绝或只读不会启动进程、创建日志。存储不安全或不可用时，批准说明本次无留存，已批准命令仍可运行。

采集继续按 stdout/stderr 分别增量解码、跨块脱敏，内存 `job output` 仍最多 1 MiB；另捕获最多 8 MiB 脱敏文本用于完成后保存。每次最多四个活动任务，因此额外捕获载荷至多 32 MiB，提交或放弃后释放；这不是 Python 进程总内存上限。原始输出停止上限与期限不增加。日志截取在脱敏之后，`capture_limited` 与命令的 `output_limited` 分开。

启动时 `log.pending=true`；正常结算后，`job status` / `wait`、CLI/TUI 本地通知和模型的下一安全边界包含 `log` 结果。成功时用 `log.log_id` 调用 `read_log` 或 `/log ID [OFFSET]`。`read_log` 的 offset 是**字符偏移**，不使用 `job output` 的 UTF-8 字节偏移、end 或前缀摘要；每页仍受完整 JSON 字节预算限制。内存记录被清除后，已提交日志仍按原会话所有权回读；恢复只恢复日志访问，不重建进程。`read_log=false` 继续阻止模型回查，用户本地查看入口保持。

后台保存只追加，不用启动时的旧批准淘汰任何记录或清除遗留 pending 文件。已批准的旧记录必须仍完整存在；期间新增的前台/后台日志可保留并合并。全 journal 仍最多 16 条、16 MiB；容量不足、旧记录被删除/修改、锁竞争、owner/配置变化时单独报告留存失败，保留命令原状态。前台保存仍按它自己的新批准处理淘汰；不在后台刷新淘汰授权。

进程清理、输出结算和这次留存尝试结束后才发布终态。超时、输出超限或执行失败可保存实际采集的诊断，退出码未知时是 `null`，不能伪造为零。任务状态仍保留 stdin 交付失败，不能因日志结算把失败改成成功。取消、重置、关闭或会话归属变化会撤销待提交权限，日志提交不持有 job 锁，不阻止发出取消。进入原子 I/O 后若被中断或同步失败，可能返回留存结果未知；用 `/logs` 检查，不重新运行命令或重放输入。

这是**完成后有界提交**：运行中仍用内存分页，崩溃会丢失尚未提交的捕获，不能称为执行中持续落盘或跨进程后台恢复。已保存文本按既有隐私/期限规则回读，日志成功不等于命令成功或固定验收通过。源码对照见[OpenCode 后台日志调研](research/opencode-background-logs-20261028.md)，本批最终范围见[验证记录](benchmarks/background-logs-20261028.json)。

本批新增 19 项后台日志测试和 1 项 POSIX 进程观察反例；最终冻结后 Windows / WSL 完整回归各 1658 项，分别 1635 / 1634 通过，23 / 24 项平台跳过。Python 3.11 相关 21 项为 20 通过、1 项 POSIX 跳过；WSL 相关 21 项及两套 SDK 环境在两端各 30 项无跳过通过。固定回复链完成日志回查、批准修复及独立验收，不代表真实模型编码收益；远程原生 CI 仍待解禁验证。

## 标准输入管道

启动具体命令时可显式设置 `stdin="pipe"`。开启后台功能并不自动保留每条命令的输入；前台命令不能使用该选项。TUI/chat 的 Enter 仍提交对话或本地命令，普通消息不会直接送入程序。需要给程序发送一行时，在 JSON 字符串中明确写出 `\n`：

```text
/job start {"argv":["python","-u","script.py"],"stdin":"pipe"}
/job input job-<ID> "yes\n"
/job input job-<ID> "原文，可包含空格和 Windows 路径 C:\\Temp\\file\r\n"
/job eof job-<ID>
```

模型使用 `run(background=true,stdin="pipe")` 和 `job(action="input",job_id=...,text=...)` / `job(action="eof",job_id=...)`。每次 input/EOF 都审批准确目标与正文；批准启动不授权后续输入，EOF 也可能让程序继续执行文件或网络操作。没有隐式换行、shell/变量/文件引用展开、自动回答或输入重放。拒绝输入保留当前程序；审批窗 Enter 提交新要求会拒绝旧提案，并进入已有的新要求处理流程。后台自行完成不会触发模型请求。

每次 input 为非空 UTF-8 文本，最多 **4 KiB**，不接受 NUL 或无效 Unicode；每个任务累计写入最多 **64 KiB**。已配置凭据在审批前和发送前再次检查，不能通过这个入口发送。它是普通任务输入，会出现在正常输入/工具历史中，不是密码或凭据通道。程序需要能够处理 UTF-8 管道；不提供终端尺寸、TTY 回显、控制信号或密码提示仿真。

输入受原任务剩余期限和每次 2 秒的写入循环预算约束，不延长后台任务。IO 锁不可立即获得时返回等待状态供循环检查，避免等待进程清理锁后才写出已过期输入。读取输出的工作线程继续独立运行；原输出上限仍会终止进程。偏移/等待参数不适用于输入，旧 EOF 或已经关闭的管道不能重新开启。

返回的 `input_complete` 只表示完整写入管道或关闭了写端；`written_bytes` 是本次实际写入数，`stdin_bytes` 是累计数，不证明程序已消费或正确处理。发生错误、期限耗尽或部分发送时，停止该任务并报告不确定性，不重发原文；写入已有的部分可能造成效果，停止不是回滚。自然退出码也不能把后续发现的输入交付失败改成成功。取消时仍保留进程归属，清理不确定继续阻止固定验收。

输入绑定当前对话的任务对象、策略、工作目录身份及输入版本。重置、模型/策略变化、另一条已获批输入使旧提案失效；输入前后清除旧读取标识与代码地图缓存。模型产生的输入还会复查当前项目指导。完成的输入不会恢复授权，保存/分支/恢复仍不重启或附着进程。默认关闭后台功能时不会增加普通模型请求的工具定义。

[本批验证记录](benchmarks/background-stdin-20261027.json)包含三协议 JSON/SSE 的实际管道→两段输入→EOF→输出→独立验收，Enter 提交的 CLI / 80×24 TUI、拒绝和新要求、部分写入、满额、自然退出竞态及锁竞争反例。固定回复不构成真实模型能力或性能成绩；远程 CI 仍按 11 月 1 日前冻结的要求待验证。

## 所有权与退出边界

复用已受管的非阻塞进程管道：Windows 在子进程执行前分配 kill-on-close Job Object，POSIX 独立进程组保留组长归属直至清理。命令结束也清理继承管道的后代，避免只留下父 PID 消失、后代仍运行的情况。后台线程只泵取有界输出和观察状态，不执行模型回调或申请批准。

重置期间禁止新启动，已打开的旧启动提案失效；清理完成前不丢弃进程所有权。关闭永久禁止该所有者再启动；清理超时会保留记录供检查/重试关闭，不报告已清理。目录/会话句柄在所属工作线程结束前保持有效。

这些是正常取消和关闭的进程归属管理，不是系统隔离。命令可能访问外部文件、网络或把工作交给外部服务；进程组/Job 不会撤销已有副作用。宿主被强制杀死/崩溃后，特别是 POSIX 上，无法保证所有后代已消失；恢复应检查实际系统和工作区，不能按旧记录盲目重启或附着到可能复用的 PID。

验证覆盖实际 Windows/POSIX 子进程与后代、stdin EOF、双通道分片 UTF-8、私有参数/环境和分页、同时启动上限、退出/超时/超限/取消、重置并发与永久关闭、任务未结束/检查中变化禁止验收，以及真实 TUI/chat 和三协议的启动→并行编辑→等待→读取→独立检查。固定模型回复不证明新的编码能力或性能排名。最终范围见[机器记录](benchmarks/background-jobs-20261022.json)。
