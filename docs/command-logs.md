# 命令日志保留与分页回查

首尾展示会省略长命令日志的中间内容。启用命令日志后，命令结果返回一个 `log_id`，模型可用只读 `read_log(log_id, offset)` 回查；用户也能在聊天 CLI 或 TUI 使用 `/logs`、`/log ID [OFFSET]`。这些都是历史观察，不能恢复文件 `read_id`、批准动作或独立验收状态。

## 启用

默认关闭，不创建日志目录、不增加普通任务的工具定义。只在可信用户配置或 profile 中启用，项目配置不能改存储位置：

```toml
[storage]
command_log_dir = "~/.sprig/command-logs"
auto_save_session = true

[execution]
max_output = 16000
output_limit = 1048576
```

CLI 可用 `--command-log-dir PATH` 覆盖，`--show-config` 和 TUI `/config` 显示位置与来源。目录必须专用、私有，并位于所有 Git 仓库之外；不能与配置、会话或修改备份目录混用。路径不能包含已知模型凭据。POSIX 使用 owner-only 权限，Windows 使用现有私有 ACL 与不跟随重解析点的目录层。

`output_limit` 仍是进程原始合并 stdout/stderr 的停止上限，`max_output` 仍是展示预算。日志功能不会悄悄提高任何上限：进程因输出超限被终止后，超出采集上限的内容无法恢复。示例让命令采集到 1 MiB，模型先看最多 16000 字节，再按需回查实际保留的文本。

启用后，每次命令的现有批准界面还列出日志位置、容量、过期规则、可能被淘汰的记录 ID，以及固定崩溃暂存文件的清理。拒绝命令、只读模式或取消都不能绕过批准来创建日志。若目录不安全、含无关文件或已不可用，界面明确说明本次不保留日志；命令仍须新批准。

## 会话范围与用法

| 入口 | 行为 |
| --- | --- |
| 模型 `read_log(log_id, offset=0)` | 仅能读取当前会话命名空间、当前工作区中的未过期日志，不接受路径或其他会话名 |
| `/logs` | 本地列出当前会话的日志 ID、大小、退出状态与过期标记，不调用模型 |
| `/log ID [OFFSET]` | 本地回查，默认从 0 开始；使用返回的 `next_offset` 继续 |
| `/logs clear` | 新批准后只删除当前会话的记录；只读模式拒绝；其他会话保留 |

`offset` 是保留文本的字符偏移，不是原始管道字节位置。每页完整 JSON 受 `min(max_output, 8192)` 字节限制，含元数据和转义开销，UTF-8 不截断码点。`complete=true` 只表示已读到这份保留文本末尾，必须同时看 `returncode`、`timed_out`、`output_limited`、`capture_limited`；它不表示命令成功或任务通过。

默认非交互任务有十种工具；交互回调另可提供 [question](questions.md)。启用日志且 `[tools].read_log=true` 才增加回查工具，有摘要时可再增加 `read_history`。`read_log=false` / `--disable-tool read_log` 禁用模型回查，用户的本地查看入口仍保留。启用的确定性上下文压缩可省略旧成功回查正文，保留元数据；失败/超时/超限和近期记录仍受原保护规则约束。

日志所有权随启用保存的会话写入少量元数据，完整日志正文不复制进会话 JSON；恢复只恢复只读访问范围，不执行命令。新对话生成新的所有权，不能继续读前一对话的日志。另存分支沿用来源对话的日志访问范围。若未保存会话，退出后应用会失去该次命名空间，日志仍可能留在私有存储中，直到后续获批清理或淘汰；因此示例同时开启自动保存。

## 容量、隐私和故障

- 每份日志最多 8 MiB 脱敏 UTF-8 文本；整个专用存储最多 16 条、16 MiB 序列化 JSON。一次原子更新可能另有最多 16 MiB 的固定暂存载荷，即至多 32 MiB 日志载荷加零长度锁文件；这不是物理文件系统分配空间的精确计数。无关文件、硬链接、非普通文件、不安全权限或超限文件会被拒绝使用，应用不会删除它们。
- 日志读回在创建七天后过期。磁盘删除不是后台定时任务：过期正文会留到下一次获批保存或明确清理。新保存按容量/数量淘汰旧记录，候选在本次批准时列出；存储若已被另一进程改变，放弃本次保留，不能用旧批准淘汰新记录。
- UTF-8 增量解码和已知凭据脱敏先于文本容量截取，覆盖跨管道分块的凭据和既有长尾前缀规则。读取时还会先对整份文本按当前凭据重新脱敏，再分页，避免跨页拆开秘密。重新脱敏也受 8 MiB 文本上限约束；替换标记使文本膨胀时按 UTF-8 边界保留前缀，返回 `capture_limited=true`。无效 UTF-8 使用替代字符；这不是原始二进制日志。
- 未知密码、个人信息和业务数据不保证能自动识别。保留的是私有明文，不是加密归档；模型回查的页面会进入该轮模型请求和启用保存的对话，与普通工具结果相同。终端控制字符在 CLI/TUI 显示时继续转义。
- 命令失败、超时和输出超限也可留下实际采集到的日志及原状态。取消不提交当次采集；旧记录保留。进程崩溃可能留下固定暂存文件，读回不会采用它，下一次获批保存才清理；不会扫描或重放副作用。
- 日志保存失败与命令结果分开报告。校验/快照变化会明确拒绝保留；原子替换或同步 I/O 失败可能已改变磁盘，此时报告未知结果，用 `/logs` 检查，不自动重跑命令。

## 验证

`tests/test_command_logs.py` 覆盖真实子进程中间日志回查、UTF-8/控制字符/跨块与跨页脱敏、容量淘汰、过期、崩溃暂存、锁竞争、保存故障、权限/硬链接、只读/拒绝/取消、历史读取标识失效、会话所有权与恢复、CLI 本地控制和实际 TUI 新对话/恢复/逐次清理。三协议真实 HTTP 回放验证命令只批准一次，随后通过回查找到展示中省略的细节，并在 16 KiB 请求预算内继续。

源码对照基于固定 OpenCode `dev@9d90d89` 的 [`tool-output.ts`](https://github.com/anomalyco/opencode/blob/9d90d892dcbfc52b47e95b2ea31b8aba877128fd/packages/core/src/tool-output.ts)：它将截断正文写入工具输出文件并返回路径。Sprig 使用受限会话句柄和专用有界存储，明确展示批准与清理边界；不提供任意路径下载。后续已增加[后台命令及完成后日志提交](background-jobs.md#完成后保留日志)：复用同一 journal 和回查接口，延期保存仅允许追加，不能借用旧批准淘汰后来生成的日志；执行中崩溃仍可能丢失未提交输出。后台日志额外包含 job_id、原终态和 stdin_failed，未知 returncode 为 null；这些字段不授权恢复进程。旧版本可能拒绝含新状态的 journal，不要据此重跑命令。

本批完整测试、打包和精确 CI 结果见[机器记录](benchmarks/command-logs-20261020.json)。固定回复回放证明工具和状态流程，不证明模型编码成功率或已追平其他 agent。
