# 单文件地图与完整输出预算

2026-10-25。本批针对真实工具记录中暴露的定位缺口，补齐 `project_map` 的文件入口，并修正普通地图的输出计量。没有外部模型调用，远程 CI 按要求暂停。

## 复现与原因

[Click 工具记录](benchmarks/click-work-progress-tools-20261023.json)保留了 `project_map(path="src/click/core.py", query="resolve_command")` 请求。旧实现无条件用目录句柄打开 `path`，因此具体文件在 Windows 被拒绝，在 POSIX 返回 `ENOTDIR`。最小夹具只有一个含函数的 Python 文件：同一路径的 `read_file` 成功，目录地图也能提取函数，具体文件地图失败。两端均可复现，问题位于地图入口。

另一个独立夹具使用 74 个汉字组成的 `.txt` 文件名及 256 字节输出预算。旧普通地图只累计文件记录，漏算完整 JSON 外壳，而且没有计入凭据遮盖可能增加的字节；实际返回 271 字节，`truncated=false`。筛选地图原有的完整预算逻辑保持。

这两项是可复现的工具问题。单次历史记录不能证明它们导致了 Click 的剩余两个失败；本批没有重跑或改写该模型成绩。

## 接口与安全边界

```json
{"path":"src/service.py","query":"Service.get"}
```

`path` 现在接受一个普通文件或目录，省略时仍是工作区。文件模式只处理目标文件，复用目录模式的逐文件解析；九种语言、字面名称/路径筛选、语法调用位置及原有资源限制保持。其他扩展名仅返回路径，不读取正文。

分流使用现有父目录句柄及不跟随链接的 `stat`；实际读取继续通过原有普通文件句柄检查。没有修改 Windows/POSIX 文件系统后端或放宽重解析点规则。文件模式返回前重新加载排除规则，并检查取消；禁用工具、已关闭根句柄、隐私拒绝和读取/解析上限继续生效。

单文件查询不启动“完整目录遍历”的缓存淘汰，避免查询一个文件后删除其他文件的有效声明和调用缓存。缓存仍按内容摘要区分，每次重新读取文件，不保存源码或 AST。

普通地图预留完整 JSON 外壳，逐条计算原始与遮盖后字节数的较大值。放不下完整声明时尝试返回路径及 `symbols_unavailable`；连该记录也放不下时省略并标记 `truncated`，不会超过配置预算。

地图提供定位信息，不发放 `read_id` 或批准。`edit_lines` 仍须使用 `read_file` 取得版本凭证；实际编辑和最终命令验收分别要求新的明确批准。工具说明也继续要求先读取源码再编辑。
