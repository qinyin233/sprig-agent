# 项目规则发现与动作前复查

日期：2026-10-05。Sprig 原先仅提供通用系统提示；用户没有重复给出仓库测试命令、目录规范时，模型需要自行寻找它们。现已加入工作目录内的 `AGENTS.md` 发现。Pi 的[资源加载实现](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/src/core/resource-loader.ts)与[SDK 示例](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/examples/sdk/07-context-files.ts)将项目规则纳入提示，说明这属于常见编码 agent 能力。本批实现和测试来自 Sprig，没有复制竞品源码，也没有取得模型完成率对照。

根目录规则在首个请求前加载。文件 `read_file` 会登记其父目录及工作根内的祖先，下一次请求加载这些目录的 `AGENTS.md`；不会递归扫描整个项目。每个规则记录包含相对路径、作用目录和完整 UTF-8 内容。较深目录优先于较浅目录，用户当前请求与应用安全要求优先于仓库规则。规则既不执行代码，也不改变审批、只读、命令环境或固定验收配置。

应用每次请求都重读已发现规则，在保存已启用时检查点保存当前提示。上下文预览使用副本，包含规则的真实请求字节，但不改变原始历史或授予任何动作权限。压缩不删除系统规则；超预算仍在 HTTP 前停止。恢复会话时替换旧系统提示，重新读取当前规则，不能依靠保存时的过期正文继续行动。

文件编辑及命令 `cwd` 会发现其适用规则，并与产生模型响应的那次请求做内容摘要对比。创建、修改、删除和隐私排除状态变化都能产生差异。未知或已变化规则使该动作先返回工具错误，尚未请求批准，也没有写入/执行；下一个请求带上新规则，模型需重新提出动作。即使同一响应先读取文件、再提出编辑，读取到的新规则也不能被误认为模型已看过。规则在审批期间改变时，批准不被沿用，应用在写入/进程启动前复查并停止。

只处理精确名称 `AGENTS.md`，允许 UTF-8 BOM。每文件 16 KiB、规则 JSON 总体 64 KiB、已发现目录 128 个，达到上限明确停止，不返回部分规则。`.sprigignore` 和现有敏感文件规则可排除规则文件；排除项不读取正文。已知配置密钥遮盖，通用密钥/私钥特征阻止加载；无效 UTF-8、NUL、非普通文件或无法安全打开的文件均停止。所有读取使用原有工作目录句柄与 no-follow / Windows 无重解析检查，没有新增 OS 原语。

`--no-project-instructions` 可关闭发现，保存会话绑定该选择；改变选择恢复原会话会被拒绝，需要保持原设置或新建会话。关闭规则发现不会关闭其他代码防护。本批不加载用户主目录、工作目录之外的祖先、`CLAUDE.md`、`AGENTS.override.md` 或远程规则。

命令规则仅按 `cwd` 决定，无法解析任意命令实际读写的全部路径；命令仍需逐次批准且没有沙箱。内容复查也不是在规则文件与工作文件之间建立操作系统事务，不能声称对任意恶意并发修改提供隔离。保存的系统提示反映最近使用的规则，并非逐轮永久保留所有旧规则版本。

规则快照比较用于模型生成的动作。本地 Git 等用户直接操作、独立 Tools 调用和用户固定验收命令继续使用原有逐次批准与路径/取消/输出限制，不会要求先调用模型来刷新规则，也不套用“模型是否已看过规则”的条件。

验证入口：

```powershell
uv run --locked python -m unittest tests.test_instructions tests.test_tui.TuiTests.test_scoped_rules_replan_before_showing_fresh_edit_approval -q
uv run --locked python -m unittest discover -s tests -q
```

检查覆盖首个请求、嵌套目录、同响应读取/编辑、规则创建/修改/删除/隐私变化、审批中变化、只读/拒绝、完整规则限额、密钥遮盖、取消、恢复和关闭设置。真实回环 HTTP 回放使用实际 Provider、原生文件编辑、单独获批的固定验收命令及外部私有 SessionStore，核对服务收到的调用/结果顺序、规则正文、请求预算、文件效果与重新加载的会话。Textual Pilot 通过实际 Enter 操作验证先重新规划、再展示新 diff，并保留默认拒绝。回放响应来自固定脚本，不是模型任务成绩；新增提交按额度限制跳过 CI，平台证据以本地实测为准。

本批最终全量运行 380 项：Windows Python 3.11 / 3.13 各 366 通过、14 项 POSIX 检查跳过；WSL Linux Python 3.12 为 364 通过、16 项平台检查跳过。Linux 复测包含原有父目录 symlink 置换时目录 FD 不被重定向的检查。`uv build --no-sources --quiet` 与 CLI 帮助检查通过。对 Sprig 自身工作目录的只读预览发现一份 1,340 UTF-8 字节规则，实际准备请求为 5,491 字节、未调用 HTTP；这只证明发现和预算路径可用，不能当作真实模型遵循规则或竞品性能的证据。
