# 在消息中选择本轮文件

普通 TUI 消息里输入 `@关键词`，光标停在关键词后按 Tab，在本地选择器中按 ↑↓、Enter 选取。支持多行消息、中文和路径中的空格；可以在句子中间选取，后面的文字保留。关键词不含空格，打开选择器后可以继续输入带空格的查询。Esc 关闭并保留草稿。

选取后出现 `@"工作区相对路径"`。这是带明确选择元数据的标记；再按主输入框的 Enter 才发送任务。多个文件可以依次选择，每条草稿最多 16 个标记，路径合计最多 8 KiB；同一路径在发送时去重。候选发现继续使用[文件选择器](tui-completion.md)的隐私规则、数量和时间限制，不读取源文件正文、不请求模型。

## 选择与编辑

- 在标记前后编辑普通文字，选择随位置移动；插入换行、中文或 emoji 不改变文件身份。
- 删除、替换标记，或在标记内部编辑，会撤销该文件选择。撤销后通过重做或手动输入相同文字不会重新授权附件；需要再次用选择器选取。
- 手动输入或粘贴 `@"file.txt"`、邮箱地址和普通 `@` 文字不会自动变成附件。模型仍能通过原有、受隐私限制的文件工具处理用户文字中的路径。
- 弹窗期间草稿变化时，旧选择不覆盖新草稿。选择器关闭后保留原有编辑撤销历史。

## 发送、预算与重试

发送时才按当前路径和隐私规则读取完整 UTF-8 文本快照，复用 `/add` 的读取后端：每个文件最多 32 KiB、合计最多 128 KiB，现有 `max-output` 同时生效。不接受二进制、不完整正文、敏感内容或排除路径，不会静默截断大文件。大文件可改用 `/ref` 的路径/大小上下文，或让模型按范围读取。

文件和任务一起进入实际协议的完整请求预算预检，包含工具定义、项目指令、持久引用和运行预算说明。Chat Completions、Messages、Responses 均沿用各自请求编码。文件读取或这次预检失败时，不改变原历史、不保存新任务、不执行基线命令，也不开始 Provider 请求。草稿和选择保留；再次发送会重新读取文件并重新检查。文件变更后重试可读到新内容，删除标记后重试不沿用旧选择。

预检通过后，文件正文只作为本次 `Agent.run` 的请求上下文，包含该次运行内的多轮模型请求。它是发送时的快照，后续工具修改文件不会刷新它。运行结束、取消或失败时清除这份临时上下文；下次新消息或 `/continue` 不自动重新附加。应用不把这份正文作为附件写入对话检查点或会话；原有 `/add` 仍保留快照，`/ref` 仍用于跨轮次刷新引用。模型回复和模型工具读取本来就可能引用文件内容，这些正常对话记录不因此消失。

主输入草稿只在实际请求预检完成时、且仍与提交草稿相同时清空。在准备期间输入的新草稿保留。进入 Provider 后的连接失败保留现有对话恢复语义，不声称请求一定未抵达服务器，也不自动重发。

当前文件选择入口只在空闲时开放；如果带选择的草稿遇到执行中任务或待处理引导，发送会被拒绝并保留草稿。执行中普通文本引导继续可用。没有将文件正文排入引导队列；后续增加[大粘贴折叠](tui-paste.md)，多选弹窗和图像/PDF 仍未实现。

文件内容是未受信任的数据，不能授权命令或写入。只读、逐次批准、取消、版本检查和完整响应校验继续由应用执行。
