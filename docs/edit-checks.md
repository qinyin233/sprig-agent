# 文件编辑后运行固定检查

需要由用户独立检查当前工作区时，可用[本地 `/verify` 或一次性 `--verify`](manual-verification.md)：复用同一固定 argv 和新批准，保留观察而不请求模型。它不启用这里的自动编辑后检查，也不启动队列或自动修复。

已有 Click 实测中，模型一直调用工具直到轮数耗尽，没以完成消息触发应用验收；后置外部检查仍有失败。可选的编辑后检查让用户指定的测试、编译或 lint 结果更早进入正常反馈循环。这是执行工作流的改进，没有通过新的真实模型对照证明成功率提高。[Aider 官方文档](https://aider.chat/docs/usage/lint-test.html)也提供 `--test-cmd` / `--auto-test`；Sprig 保留每条命令的新批准。

```toml
[agent]
checks = [["uv", "run", "--locked", "python", "-m", "unittest", "discover", "-s", "tests", "-q"]]
check_before_task = false
check_after_edit = true
```

CLI 使用 `--check-after-edit` / `--no-check-after-edit` 覆盖。用户、profile、显式受限项目层和 CLI 按现有规则合并；项目层不能关闭可信配置已启用的编辑后检查，也不能提供检查命令。profile 可继承已有 `checks`，最终配置必须包含非空固定 argv。只读或禁用 `run` 与检查命令不兼容，会在启动时拒绝。`--show-config`、TUI `/config` 显示生效值和来源。

| 时机 | 设置 | 完成含义 |
| --- | --- | --- |
| 本次任务/继续/恢复首次模型请求前 | `check_before_task=true` | 基线观察，不完成任务 |
| 一次模型工具响应中，成功的文件编辑全部结束后 | `check_after_edit=true` | 阶段证据，不完成任务 |
| 模型输出无工具调用的完成消息后 | 非空 `checks` | 重新执行最终检查，不复用阶段通过结果 |

同一响应含多个 `edit_file` / `edit_lines` 调用时，只在全部调用已有结果后检查一次，避免未解决的工具意图与应用检查交错。创建文件也属于编辑；只读、拒绝、无变化、错误或结果不确定不触发这一检查。普通命令、手动撤销/重做不在触发范围内，命令是否改变文件没有自动推断。

普通非零退出的完整检查结果会加入历史，下一次模型请求可据此修复。通过只代表这些命令完成且返回 0，不能证明完整任务语义；模型仍需完成解释，应用仍做独立最终验收。固定的是配置中的 argv，不自动搜寻或执行仓库未知脚本；检查可能写文件，仍是普通获批命令，没有 OS 沙箱。它们也会按原有命令规则使旧读取标识失效，后续编辑应重新读取。

拒绝任一检查即停止本次运行，不再请求模型绕过；缺失/非法退出码、跳过、取消、中断或不确定结果也停止为未验收。超时、输出超限和信号结束的已批准命令作为失败反馈，在剩余轮数内仍可诊断修复，不能因为退出码碰巧为 0 就当作通过。预算耗尽时保存阶段失败证据，不额外调用模型，也不因最后一轮检查通过就宣布任务完成。用户选择继续后按原预算开始新调用，不重放旧工具意图或旧批准。任务前基线仍沿用其原有的不完整即停止规则。

执行前保存检查意图；保存失败不启动命令。中断后恢复只补“未重放”结果，不重启旧命令。中途引导使未执行提案失效；已被引导取代的编辑批次不会在模型看见新要求前运行这一检查。检查本身的输出、取消、环境和隐私限制沿用原有执行器。

TUI 与 `--chat` 的 `/status` 显示本次编辑后检查状态；详细结果保留在当前历史，落盘仍需显式启用私有会话保存。该开关绑定会话；默认关闭不改变旧会话绑定，切换后不能直接恢复使用原绑定的会话。不会修改用户现有配置或自动启用额外检查。
