# 不调用模型的固定检查

在 chat 或 TUI 输入 `/verify` 并按 Enter，Sprig 只提议运行当前配置的固定检查。每条命令仍单独显示 argv、目录和输出预算，取得新的具体批准后才执行。结果进入当前会话，之后明确输入任务或 `/continue` 时才会随对话发送；这次操作本身不请求模型，也不自动修复。

```toml
[agent]
checks = [["uv", "run", "--locked", "python", "-m", "unittest", "discover", "-s", "tests", "-q"]]
```

也可一次性运行，不需要模型凭据，不创建保存的对话：

```powershell
uv run --locked sprig --verify --check '["uv","run","--locked","python","-m","unittest","discover","-s","tests","-q"]'
```

`--verify` 使用当前工作目录和已选配置，也接受重复的 `--check`。不能同时传入任务、文件附件、`--chat`、`--tui`、`--save-session` 或 `--resume`；需要保留对话时使用交互界面里的 `/verify`。它明确使用命令行界面，即使配置默认打开 TUI。可选命令日志仍遵循原有存储设置，日志不是保存的对话。

## 结果表示什么

所有固定命令均取得本次批准、可靠完成且返回整数 0，才显示“固定检查通过”。这描述所选命令当时的结果，不能证明每条需求已落实，也不会把排队任务标为已执行。没有配置 checks 时直接报错；只读模式或禁用 run 仍不能配置这些命令。

拒绝、取消、异常、超时、输出超限、不确定结果或保存失败都不能成为通过。已有后台命令尚未结束或清理不确定时，固定检查会延后。本地验收仍使用原来的进程、输出、目录及环境过滤规则；获批检查程序可能修改文件或访问网络，应用不会替它增加 OS 沙箱。

TUI 在开始检查时使先前通过状态失效，直到本轮全部成功才更新结果。保存失败保留“未完成/错误”，恢复对话不会恢复通过状态或重放待定命令。检查后清除旧读取版本和地图缓存，后续编辑仍需新读取与新批准。

## 跟踪验收文件

在可信用户配置或 profile 的 `[agent]` 中，可以用 `check_files` 指定验收依赖的文件：

```toml
[agent]
checks = [["uv", "run", "--locked", "python", "-m", "unittest", "discover", "-s", "tests", "-q"]]
check_files = ["src/app.py", "tests/test_app.py"]
```

终端也可重复传入 `--check-file PATH`。最多跟踪 16 个工作区相对路径，每个文件须为不超过 512 KiB 的 UTF-8 普通文件。受保护或排除的路径、符号链接及不可读文件会使该次验收无法建立证据。

Sprig 比较固定检查开始与结束时的身份、元数据和内容摘要。命令即使全部返回 0，任何所选文件在两次读取之间发生可观察的变化，也需要重新验收。TUI 空闲时每两秒复查，输入 `/status` 可立即请求一次，CLI chat 在 `/status` 时复查。通过状态一旦过期，需重新运行并批准 `/verify`。复查在本地进行，指纹和文件内容只在当前进程使用。

范围由用户指定，适合跟踪关键源文件、测试和配置。文件扫描并非原子操作，记录描述各次实际读取的状态。模式支持检查期间和检查后的复查，文件在两次采样间变化又完全恢复时可能漏过。

## 中途引导与后续修复

在检查批准窗里发送新要求，或在 chat 确认时输入 `n: 更正说明`，会停止原提案并沿用现有保存和递送链。新要求在检查期间到达，或恰在结束前到达，都不会自动调用模型；结果保持待处理，随后可明确继续。未确认保存的输入和恢复后的待处理要求必须先处理，检查不能绕开恢复。

`/verify` 不启动排队任务。运行中的操作也不会被这个 slash 命令替换：先等待或取消，再明确检查。普通任务里的中途引导和已明确启动的队列仍沿用原行为。

失败观察留在对话后，可输入 `/continue` 让模型按原预算修复；最后仍重新逐次批准独立验收。没有在本地检查后增加隐藏请求、自动重试或额外轮次。模型计划中的“已完成”不改变检查结果。

观察累计较多时，下一次模型请求仍受原上下文字节预算限制；本地检查不会自动提高预算或丢弃失败正文。

## 失败复现卡

在 chat 或 TUI 中输入 `/repro`。清单从最近的失败开始，显示固定检查的结果消息编号、退出码和当前能否复跑。可用 `/repro OFFSET` 按偏移翻页。把清单中的编号交给以下命令：

| 命令 | 操作 |
| --- | --- |
| `/repro show 12` | 查看原始失败、同一 argv 的最近后续观察、两次运行之间变化的受跟踪文件和有界输出摘录。 |
| `/repro run 12` | 用当前配置中的同一 argv、工作区根目录和现有执行策略复跑这一条检查。显示命令详情，逐次请求批准。 |
| `/repro report 12` | 在当前对话区预览 Markdown 报告。 |
| `/repro export 12 reports/repro 12.md` | 审阅完整 diff 并批准后，在工作区内创建新文件。路径可以含空格，父目录须已存在。 |

复跑只接受 Sprig 实际安排过的固定检查，且 argv 必须仍在当前检查配置中。历史编号指向工具结果，可用 `/history 12` 追查原始输出。超时、输出超限、拒绝和未结算各有状态；后续观察可能是拒绝或失败。即使复跑退出码为 0，也应另行运行 `/verify` 完成整体验收。复跑不会自动请求模型或启动队列。报告使用命令的合并 stdout/stderr，只有有界、脱敏摘录。导出需要工作区写权限，文件已存在时拒绝覆盖。

新检查会记录观察时间、Sprig 主进程的平台和 Python 版本。命令所用的解释器与 uv 版本由命令环境决定。配置了 `check_files` 时，Sprig 在每条命令提议前和结束后采样这些文件的内容。报告列出采样之间内容不同的路径，尤其适合发现测试脚本本身变化的情况。文件不可读、未列入 `check_files` 或来自缺少采样的旧记录时，比较显示未知。采样只覆盖所列文件和实际读取时刻，摘要留在本地会话，报告和后续模型请求都省略文件摘要与正文。

## 验证范围

17 项新增离线回归覆盖真实子进程、私有保存、意图/结果保存失败、不重放、拒绝及只读/禁用策略、后台状态、取消、引导、命令行无凭据运行、真实 chat 的拒绝更正，以及 80×24 TUI 的 Enter、再次检查、排队保留和结束竞态。三协议回环分别先观察本地零请求，再经明确继续完成失败反馈、编辑和新批准的最终检查；回环回复是固定夹具，不是模型能力成绩。

隔离进程中仅换回父版本的 TUI 结束策略，结束前收到引导时实际产生一次不应自动启动的脚本化查询，新测试失败；当前策略下对应测试通过并保持零查询。该对照没有外部模型调用。

完整本地范围与 CI 待验证状态见[机器记录](benchmarks/manual-verification-20261024.json)。本批不改 OS 后端或协议适配器，没有新增外部模型调用，未改变此前 Click 或小任务实测的成绩。
