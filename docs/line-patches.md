# 读取绑定的紧凑补丁

`edit_lines` 支持 `edits` 数组或 `patch` 文本二选一。多个相隔较远的修改可以放进同一份补丁，复用一次读取版本和一次完整差异批准。先 `read_file` 查看相关完整物理行，使用本次返回的 `read_id`：

```json
{"path":"source.py","read_id":"r0123456789ab-1","patch":"@@ -2,2 +2,3 @@\n-old\n+new\n+insert\n keep\n"}
```

补丁仅包含 1–32 个标准编号 `@@ -旧起点,旧数量 +新起点,新数量 @@` hunk；数量为 1 可省略。每个正文行以空格（上下文）、`-`（删除）或 `+`（增加）开头。插入使用旧数量 0，起点表示前一行；例如文件开头是 `-0,0`。空上下文行也必须保留空格前缀。

调用中的 `path` 是唯一目标。文件必须已存在，可以是空文件；文件头、Markdown 围栏、重命名/删除文件指令及多个文件路由都会拒绝。创建、移动和删除文件继续使用各自的既有入口。多文件独立调用仍走[整批预检](edit-batches.md)，初始任一提案错误就没有批次写入，随后逐文件批准。

旧位置、完整内容版本、每行上下文/删除正文和新旧数量必须一致；后续 hunk 的新位置必须计入先前增删。保留缩进、尾部空白和 Unicode，不偏移搜索、不做模糊匹配。错误返回后重新检查文件并提出新补丁，不自动修补参数或执行部分 hunk。

补丁的 LF/CRLF 是输入格式。未改动行保持原始字节，新增行沿用文件唯一的 LF、CRLF 或 CR；空文件和只有未终止一行的文件使用 LF。混合换行文件增加有终止符的新行时拒绝，改用明确换行的 `edits`。UTF-8 BOM 保持。文件末尾缺少换行须在对应的上下文、删除或增加行之后明确写 `\ No newline at end of file`；该标记不能把未终止行插到其他内容前面。

补丁 UTF-8 最多 512 KiB，结果仍受既有 512 KiB 文件上限及完整请求预算限制。只读、禁用工具、隐私/凭据、取消、项目规则、审批期间文件变化、备份与精确撤销/重做沿用原后端。读取标识不能跨文件、命令、新任务或恢复使用；补丁没有新增执行批准渠道。

明确开启上下文压缩后，已完成且结果明确批准、实际改变同一路径的旧补丁可以和其他成功编辑一样省略参数正文；原始私有历史完整保留。最近窗口、拒绝、失败、无改动、不确定、重复调用身份与未结算结果保持原文。省略标记不包含可重放补丁或新的 `read_id`。

实现前的[OpenCode 源码对照](research/opencode-patches-20261029.md)记录了不同格式和匹配策略。[验证记录](benchmarks/line-patches-20261029.json)区分标准 diff 随机对照、实际文件/批准、三协议 JSON/SSE、TUI 和完整本地回归；这些固定回复测试不代表真实模型完成率提高。远程原生 CI 在 11 月 1 日前继续冻结。
