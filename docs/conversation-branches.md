# 对话轮次与分支

TUI 和连续 chat 可以从当前会话的完整用户轮次建立新分支。原对话文件保留，当前输入草稿及待发送文件/粘贴不清空；选取、确认和本地预检不调用模型。只有下一条任务或明确“继续”才发送保留的历史。

## 操作

- TUI 侧栏“从历史建立分支”，或 `/timeline`、`/fork`，打开本地选择器。可搜索消息号和最多 160 字符的预览，↑↓选择，Enter 进入确认，Esc 关闭；最多显示 20 个匹配项，更多时请细化查询。
- `/fork current` 保留整个当前对话，另建分支。
- `/fork MESSAGE` 保留该用户消息对应的整轮对话：从开头直到下一条用户消息之前，包括该轮完整的助手/工具记录。消息号与 `/history MESSAGE [OFFSET]` 一致，从 1 开始；系统、助手和工具消息不能作为此入口的分支点。
- `/timeline OFFSET` 输出有界的本地 JSON 页，最近轮次在前，按 `next_offset` 翻页。连续 chat 的 `/timeline` 和不带参数的 `/fork` 也输出第一页，然后用 `/fork MESSAGE` 或 `/fork current`。

较早会话中由应用保存的工作区变更说明也可能列为独立轮次。预览最多 160 字符，不是完整原文；用 `/history MESSAGE [OFFSET]` 查看。若当前输出上限连单个预览项都容纳不下，分页会明确拒绝，不绕过上限。

分支在当前模型、端点、协议和工具策略下建立。启用了会话保存时，确认会给出新建的 `fork-<UUID>.json` 私有文件；当前未保存时只保留内存，可另存。原文件不覆盖。拒绝、取消、预算不足、保存失败或过期提案不会替换当前对话；一次确认只允许一次提交，失败后需重新确认。保存交付不明时核对确认中指定的分支文件，不自动覆盖、删除或重试。

## 工作区与历史

**对话分支不回滚工作区文件。** 确认会说明这一点，保留历史也会追加应用说明：旧读取、批准、检查结果都不是当前证据，需要检查实际文件并重新验收。文件编辑备份保持，可通过现有 `/changes`、逐次批准的 `/undo` / `/redo` 操作；这不是多文件原子回滚或命令快照。

只保留所选轮次及更早的可见文字和工具历史，移除旧 `reasoning_content`、原生协议 `native_state` 和摘要投影，不把未来轮次带入新分支。中断的工具意图按现有恢复规则标为可能执行/未执行、交付不明，不重放；无效历史仍拒绝。所有保留内容重新脱敏，原始父分支文件可能仍包含其原生/推理元数据，本地保存不加密。

分支重置旧文件读取标识、语法缓存、MCP 本地连接/结果、运行及独立检查状态。计划只按保留前缀恢复为模型报告；完成勾选不表示重新验收。旧命令日志的所有权不会复制给分支，旧日志句柄在分支不可用，仍可恢复原会话回查；分支新日志按当前设置独立保存。MCP 清理不暗中发送 DELETE。引用文件沿用当前显式选择，实际请求前重新检查范围、隐私及内容；它们不代表历史文件版本。

模型配置不变，数值用量仍来自同一 provider 实例，不把建立分支伪装成用量清零。新模型提案或分支生效后，其他已打开的旧切换/分支提案失效；新对话和恢复也使先前提案失效。执行中不能建立分支，控制命令不会入队成为模型任务；确认期间的新要求会放弃分支，回到原对话正常处理。完成后的取消不会回滚已经生效的本地分支。
