# 图片输入

通过现有附件入口选择工作区内的 PNG、JPEG、WebP 或单帧 GIF，可以把截图、界面稿等作为模型的原生图片输入，与文本源码一起使用：

```powershell
uv run --locked sprig --tui --max-context-bytes 1048576 --file screenshots/error.png
```

chat/TUI 中可输入 `/add screenshots/error.png`；TUI 消息里输入 `@关键词` 后按 Tab，选择文件，再按主输入框 Enter 发送。文件名后缀不决定类型，以实际字节和解码结果为准。模型另外可提出[需单独确认的 `read_file(image=true)`](model-image-reads.md)，该模式的像素不随会话保存。

选择支持视觉输入的模型；协议可携带图片，不表示所有兼容服务或模型都能理解图片。应用不会自动换模型、重试收费请求或丢弃图片后改发文本。此次验证使用合成图片与回环服务，没有新增真实模型视觉能力或编码成绩。

## 读取、规范化与请求预算

| 范围 | 行为 |
| --- | --- |
| 本地文件 | 沿用每批 1–16 个文件、单文件 1 MiB、整批 2 MiB 原始字节限制，和文本共用隐私/路径/版本/取消边界 |
| 解码 | 仅允许 PNG/JPEG/WebP/GIF；完整校验和加载像素；任一边至多 4096、总像素至多 4 Mi，拒绝动画和多帧，不默认取第一帧 |
| 规范化 | 应用 EXIF 朝向，不缩放，转为 8 位 RGB/RGBA PNG；保留透明度，移除 EXIF、XMP、ICC、注释及文本块，色彩空间和位深可能改变 |
| 图片输出 | 每张规范化 PNG 至多 1 MiB、每批规范化图片至多 2 MiB；压缩源文件很小也可能在规范化后被拒绝 |
| 模型请求 | 使用原有 `max_context_bytes`，所有路径、正文、原生图片块和 Base64 编码均计入实际序列化字节；不自动增大预算 |

超限需用户明确调整图片或请求预算；不静默缩图或只上传部分文件。解码、朝向转换、输出和请求投影之间检查取消，单次受像素上限约束的底层编解码操作不能被逐像素中断。使用 uv 锁定的 Pillow；普通文本路径延迟导入图片解码器，不增加比较客户端的依赖。

图片按 Chat Completions 的 `image_url` 数据 URI、Messages 的 `image/source/base64`、Responses 的 `input_image` 数据 URI 编码。原始 Base64 不嵌入正文 JSON，也不会被当作一大段文字发给模型；没有远程图片 URL 获取、单独文件上传或 OCR 服务。字段依据 [OpenAI 图像输入文档](https://developers.openai.com/api/docs/guides/images-vision)与 [Messages 视觉文档](https://platform.claude.com/docs/en/build-with-claude/vision)。完整解码不能仅依赖 `verify()`，见 [Pillow Image 文档](https://pillow.readthedocs.io/en/stable/reference/Image.html#PIL.Image.Image.verify)。

## 隐私、保存与后续轮次

候选列表只发现路径，不解码图片。实际提交才使用现有无跟随句柄读取，并复查全批版本和隐私。混合文本/图片批次任一文件失败，不加入部分历史或请求；TUI 保留草稿和选择，重试重新读取当前文件。

`--file`、`/add` 是固定快照；启用保存后，规范化图片作为私有会话的一部分保存，仍受原 8 MiB 会话上限约束。恢复时验证结构、大小、Base64、摘要、PNG 块/CRC、尺寸和像素，不重读已删除或变化的原文件，不执行操作。只接受固定长度的 RGB/RGBA 头、无额外正文的结束块和恰好覆盖扫描行的完整有界解压流；重算摘要/CRC 也不能夹带解码器忽略的数据。坏记录、元数据重插入、非法角色/身份组合和配置秘密造成的编码冲突在请求前拒绝；存储编码冲突不覆盖原会话。

TUI `@` 选择只在本轮调用中保留，跨工具步骤继续提供图片，结束后清除，不把像素写入保存历史。终端回执和恢复显示只含说明与图片元数据；历史分页和摘要输入省略图片 Base64，并明确像素已省略。已有摘要仍是有损文本报告，不等同于重新看过图片。

隐私路径检查和已配置秘密的文本脱敏继续有效。重编码能移除附带元数据，**不会识别或遮盖图片像素里的凭据、个人信息或文字**；请选择适合发送给当前提供商的图片。若秘密文本会破坏 Base64 或原生图片块，整张拒绝，不发送损坏的脱敏编码。

实时 `/ref` 不自动刷新图片；模型文件工具默认仍按文本规则工作，显式图片模式需另外确认。当前没有剪贴板位图粘贴、PDF/音频输入、图片生成或图片编辑后端。

## 验证范围

新增 23 项回归包括历史/本轮输入 × 三协议 × JSON/SSE 的 12 组实际回环请求，比较收到的完整 PNG 字节；另覆盖命令行、80×24 TUI Enter、保存恢复、混合批次、透明度、EXIF 朝向、损坏像素及资源边界。脚本化服务还读取实际像素，提出文件修改，再经两次独立新批准完成真实写入与固定验收。

修正了新图片测试发现的发送前身份投影缺口：非法输入身份不能先被剥离再作为正常图片发送；拒绝测试检查 `invalid_request`，不把连接失败算作成功拦截。保存记录的 PNG 头、像素流和结束块中追加惰性数据并重算校验和的三个反例，在修正前均被接受；现全部拒绝，并覆盖三协议请求前拦截。最终源码与本地验证结果见[记录](benchmarks/image-inputs-20261024.json)。远端 CI 按冻结要求待验证，本地 WSL 不替代原生 runner。
