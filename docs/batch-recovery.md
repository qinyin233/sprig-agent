# 独立编辑批次的关联与恢复

2026-10-25。本批让用户检查并恢复同一独立编辑批次中已经完成的文件写入，并修复 TUI 在多文件预检阶段处理内部对象的错误。没有新增模型工具、默认请求预算或外部模型调用；CI 按要求保持冻结。

## 源码依据与实现取舍

继续阅读固定 OpenCode 提交 `9d90d892dcbfc52b47e95b2ea31b8aba877128fd`。其 [patch 工具](https://github.com/anomalyco/opencode/blob/9d90d892dcbfc52b47e95b2ea31b8aba877128fd/packages/core/src/tool/plugin/patch.ts#L96)先准备变更，再请求权限并应用写入；出错时把已经完成的资源放入错误信息。[对应测试](https://github.com/anomalyco/opencode/blob/9d90d892dcbfc52b47e95b2ea31b8aba877128fd/packages/core/test/tool-patch.test.ts#L834)明确检查：第二个文件写入失败时，第一个文件仍然存在，错误中列出已完成前缀。这里不能据“多文件补丁”推导跨文件原子性。本次只读副本保持干净，相关文件逐一与该提交的 Git 对象比对；没有安装或运行 OpenCode，也没有复制其代码。

Sprig 原有批次预检能在初次写入前验证全部独立提案，并在每次批准后复查剩余目标；实际仍逐文件提交。本批保留这条执行路径，为每个已完成写入的精确备份添加批次标识与顺序，并提供用户本地恢复入口。拒绝或取消不触发自动回滚，也不执行后续恢复。

## 使用方式

在 TUI 输入框或连续 CLI 对话中输入并按 Enter：

```text
/changes review
/undo-batch
/redo-batch
/verify
```

修改审阅列表显示批次短标识和写入顺序；单条记录的分页快照也关联该标识。`/undo-batch` 从当前历史游标逆序撤销当前批次的已应用记录；`/redo-batch` 正序重做相应未应用记录。每个文件都展示完整差异，并要求新的明确批准。

这类批次来自同一模型响应中通过预检的 2–16 个独立 `edit_file` / `edit_lines` 提案。重复路径的依赖链、混合读/命令/编辑响应，以及文件移动原有的两阶段记录，继续采用原顺序和单文件恢复。本批没有把它们或整条用户任务归为可统一恢复的消息快照。

如果一批需要恢复三个文件，第一个完成后第二个被拒绝，结果会报告 `completed=1`、`total=3`、`complete=false`。已完成的恢复保留；再次明确执行同一命令时，只处理历史游标处尚待恢复的部分。没有后台续跑、自动请求模型或重放批准。

## 恢复边界

在第一个批准前检查所有待恢复目标；每次批准后再次检查剩余文件的内容、文件身份、隐私与凭据规则，以及配置和历史快照。任意目标已有外部改动，会在进一步写入前阻止恢复。只读模式、禁用编辑、关闭根句柄和历史目录、取消及已有未结算状态仍会阻止操作。

备份继续受 16 条、合计 4 MiB 上限约束，没有增加保留容量。如果批次开头已被淘汰，批次恢复会明确拒绝；用户仍可检查记录并逐条撤销剩余备份。没有批次标签的旧历史继续支持原来的 `/undo`、`/redo`，不按时间猜测分组。

恢复仍通过原有逐文件替换及日志结算。写入或日志结算不确定、写入后中断时，结果标记不确定并保留 pending，后续恢复被阻止；不会尝试自动补偿。Windows 重新创建文件沿用已有私有 ACL 策略。这里没有新增文件系统事务或命令/Git 快照。

恢复会让旧验收失效，通知按计数进入会话。已明确删除的创建文件从活引用列表移除；对应路径留在本地结果的内部属性中，不随结果 JSON 或通知自动上传。部分恢复也按真实已完成部分更新，不因后续拒绝而丢失变更观察。`complete=true` 只表示这次选择的备份恢复完成，须重新执行固定检查才能确认当前行为。

## 验证

新增测试覆盖往返恢复、部分拒绝与继续、批准后外部修改、取消、写入后中断、未结算日志、隐私/凭据变化、配置及历史变动、递归操作、旧历史和持久重开、默认备份容量裁剪、Unicode/CRLF、创建文件的引用更新，以及遮盖扩张后的 256 字节结果预算。

三协议各自的 JSON/SSE 共六条真实回环 CLI 流程走完：读取两个文件 → 版本关联编辑 → 独立验收 → 批次撤销 → 重做 → 明确重新验收。每条仅三次模型夹具响应，八个具体操作批准；恢复及重新验收不增加模型请求。80×24 Textual 测试通过 Enter 提交，查看批次标识，逐文件批准、拒绝并再次恢复，同时检查旧验收失效和草稿保留。

TUI 流程还暴露了旧包装层把内部 `EditPreview` 当作普通字典的错误。新增的独立回归在未修改的 77 个父版本模块上复现相同失败；当前包装层直接传回内部预检对象，不展示、序列化或赋予批准意义，无效批次能生成完整失败结果且没有写入。

完整检查还暴露两处夹具耦合。后台进程测试在 PID 文件刚创建、尚未写入时读取了空串，现改为写完关闭后原子发布就绪文件。文件选择交互测试则在一次 250 毫秒预算耗尽时等不到候选；重复诊断确认按钮、挂载和返回消息正常，结果为 0 条目、`limited=true`。交互夹具现使用独立的 5 秒发现预算，产品仍保持 250 毫秒，等待时限未增加；另加真实零预算的 TUI 测试，确认显示截断、Enter 不选择或提交、主草稿保留。两个旧用例的关键断言经 AST 比对保持，三个相关场景各重复 20 次、共 60 项通过。初次 Schema 未同步和随后 Windows 夹具失败均保留为中间失败记录，不借作最终通过。

配置 Schema 的保留命令名称同步增加两个入口，防止任务模板静默覆盖它们；模型工具定义仍为 4927 字节。最终本地结果、隔离父版本证据及源码摘要见[机器记录](benchmarks/batch-recovery-20261025.json)。本地 WSL 与平台跳过不能代替远程原生 runner；2026-11-01 前不触发 Actions，到期后仍须核实账户限制及原有门禁。复杂仓库成功率和整体顶尖水平仍未证明。
