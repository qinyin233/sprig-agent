# 长命令输出：执行上限与展示预算

默认行为保持兼容：命令输出超过 `max_output` 字节时，Sprig 停止该进程及其后代，结果标记 `output_limited=true`。长测试日志可能在末尾才给出失败原因；单纯提高 `max_output` 又会把更多日志放进模型上下文。

现在可以显式设置独立的命令总输出上限：

```toml
[execution]
max_output = 16000
output_limit = 1048576
```

上例允许命令产生至多 1 MiB 原始 stdout/stderr 合并输出。送给模型的 `output` 正文保留开头和结尾，并用省略标记连接，UTF-8 正文预算为 16000 字节。命令可执行到末尾，让最后的错误、测试统计和退出码返回修复流程。正文之外仍有 JSON 字段和消息封装开销，整个请求仍受原上下文预算检查。

CLI 对应 `--command-output-limit 1048576`；其优先级高于 profile 和用户 TOML。`--show-config`、TUI `/config` 展示实际 `execution.output_limit` 及 `command_output_limit` 的设置来源。Schema 和完整示例同步支持；项目配置不能修改 execution，不能借仓库文件扩大执行预算。

`output_limit` 为 256–8388608 的整数，最多 8 MiB。不设置时等于 `max_output`；也可设置得更低，对命令实施更严格的限制。只有总输出上限大于展示预算时启用首尾展示。文件读取、附件、编辑大小和模型回复上限沿用各自原有规则。

## 如何判断命令是否完成

| 字段 | 含义 |
| --- | --- |
| `returncode` | 实际进程退出码；超时或强制停止仍需结合下面的状态判断 |
| `output_limited` | 进程因达到原始总输出上限而停止；验收不能据此通过 |
| `timed_out` | 达到命令超时；验收不能据此通过 |
| `output_truncated` | 首尾模式省略了展示正文的中间部分；本身不表示进程被停止 |
| `output_bytes` | 首尾模式收到的原始字节数，达到上限后不继续收集 |
| `output_omitted_bytes` | 脱敏后的 UTF-8 正文中未展示的字节数；不包含省略标记 |

后三个字段仅在首尾模式下提供。只有命令完整结束、退出码为 0、且没有超时、输出上限或其他不确定状态时，应用的固定验收才可能通过。展示省略不替代实际检查，阶段检查也不替代独立最终验收。

## 隐私、取消和资源边界

每个命令仍需一次新批准；批准界面同时显示原始输出上限、展示预算和首尾模式。只读、工具禁用、工作目录、环境过滤、超时、取消、POSIX 进程组和 Windows Job Object 清理继续执行。显式总输出上限加入会话绑定；恢复时更改或去掉该显式值会拒绝复用原会话。

UTF-8 解码和已知凭据脱敏在选择首尾之前连续进行，包含跨管道分块的密钥；这样省略边界不会把完整密钥切成无法匹配的片段。展示边界不切出无效 UTF-8，终端控制字符仍转成可见表示。输出开头可立即展示，末尾在命令结束或停止后补齐，省略量如实报告。

执行层仍可能在进程内存保留至多总输出上限的原始字节；选取展示内容的缓冲区受 `max_output` 约束。不会因此将完整日志写入工作区或持久化会话，保存的工具正文是脱敏后的有界结果。现有命令权限允许的文件/网络副作用仍由用户审阅批准；这项配置不提供操作系统沙箱。

## 离线验证

`tests/test_command_capture.py` 包含真实子进程的成功/失败日志尾部、精确上限与多一个字节、持续输出强制停止、超时和后代清理、取消、拒绝、只读、禁用工具、UTF-8、凭据脱敏、配置优先级与会话绑定测试。回环 HTTP 固定检查在长日志末尾报告失败，随后执行脚本化修复、阶段检查和独立最终验收；请求仍受 16 KiB 上限约束。

这些验证支持输出处理和修复协议结论，没有付费模型效果或与其他 agent 的性能对照结论。
