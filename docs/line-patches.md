# 读取绑定的紧凑补丁

`edit_lines` 支持 `edits` 数组或 `patch` 文本二选一。多个相隔较远的修改可以放进同一份补丁，复用一次读取版本和一次完整差异批准。先 `read_file` 查看相关完整物理行，使用本次返回的 `read_id`：

```json
{"path":"source.py","read_id":"r0123456789ab-1","patch":"@@ -2,2 +2,3 @@\n-old\n+new\n+insert\n keep\n"}
```

补丁最多包含 32 段。每个正文行以空格（上下文）、`-`（删除）或 `+`（增加）开头。空上下文行也要保留空格前缀。

用单独一行 `@@` 开始的补丁段按原始文件中的上下文和删除行定位。这些行必须连续且完整，并且在整个已读取版本中只匹配一次。插入时带上相邻的原文。多个段按源文件顺序排列，各段不能重叠。

```json
{"path":"source.py","read_id":"r0123456789ab-1","patch":"@@\n-old\n+new\n+insert\n keep\n"}
```

标准编号段使用 `@@ -旧起点,旧数量 +新起点,新数量 @@`，数量为 1 可省略。编号插入使用旧数量 0，起点表示前一行，文件开头为 `-0,0`。同一份补丁统一使用一种段格式。

`edit_lines` 调用中的 `path` 是唯一目标。文件必须已存在，可以是空文件。补丁正文只包含 hunk 和行变化。创建、移动和删除文件继续使用各自的既有入口。多文件独立调用仍走[整批预检](edit-batches.md)。

编号段要求位置、原文和新旧数量精确一致，后续段的新位置计入先前增删。两种格式均验证完整内容版本，逐字匹配缩进、尾部空白和 Unicode。定位失败或有歧义时，重新读取后添加更多上下文，或使用编号段。所有段都要通过验证才显示完整差异并请求批准。

补丁的 LF/CRLF 是输入格式。未改动行保持原始字节，新增行沿用文件唯一的 LF、CRLF 或 CR；空文件和只有未终止一行的文件使用 LF。混合换行文件增加有终止符的新行时拒绝，改用明确换行的 `edits`。UTF-8 BOM 保持。文件末尾缺少换行须在对应的上下文、删除或增加行之后明确写 `\ No newline at end of file`；该标记不能把未终止行插到其他内容前面。

补丁 UTF-8 最多 512 KiB，结果仍受既有 512 KiB 文件上限及完整请求预算限制。只读、禁用工具、隐私/凭据、取消、项目规则、审批期间文件变化、备份与精确撤销/重做沿用原后端。读取标识不能跨文件、命令、新任务或恢复使用；补丁没有新增执行批准渠道。

明确开启上下文压缩后，已完成且结果明确批准、实际改变同一路径的旧补丁可以和其他成功编辑一样省略参数正文；原始私有历史完整保留。最近窗口、拒绝、失败、无改动、不确定、重复调用身份与未结算结果保持原文。省略标记不包含可重放补丁或新的 `read_id`。

上下文定位的参考实现见固定版本 OpenCode 的 `computeReplacements` 和 `seek`。Sprig 的规则要求精确且唯一匹配，并沿用文件版本检查和逐文件审批。[OpenCode 源码](https://github.com/anomalyco/opencode/blob/9d90d892dcbfc52b47e95b2ea31b8aba877128fd/packages/util/src/patch.ts#L299-L359)

## 在一个调用里提议多文件补丁

模型刚读取过两个或更多独立目标时，如果出站请求预算允许，Sprig 会提供 `patch_files`。每个目标使用自己的 `read_id` 和与 `edit_lines` 相同的 hunk 格式。文件数为 2–16。上下文紧张时可以继续使用已有的 `edit_lines` 调用。

```json
{
  "files": [
    {"path":"registry.py","read_id":"r0123456789ab-1","patch":"@@\n-KEY = 'old'\n+KEY = 'new'\n"},
    {"path":"dispatch.py","read_id":"r0123456789ab-2","patch":"@@\n-DEFAULT = 'old'\n+DEFAULT = 'new'\n"}
  ]
}
```

Sprig 在第一次审批前验证全部目标、读取版本和 hunk。通过后按数组顺序展示每个文件的完整 diff，请求各自的批准。每次写入前核对剩余目标和项目规则。拒绝、文件变化或新引导会停止剩余补丁，已经完成的文件会保留，并在修改记录中使用同一个批次 ID。取消后的会话恢复沿用现有意图结算与修改备份。

结果中的 `changed_files` 是确认完成的写入数量，`stopped_file` 是从 1 开始计数的停止位置。若回执处于输出上限内，`files` 会返回各文件的结果与新的读取标识。配置了编辑后检查时，确定已完成的写入可进入独立的检查环节。对完整成功且较旧的补丁组，启用上下文压缩后可省略请求中的补丁正文，原始会话保留完整参数。

可用 `[tools].patch_files=false` 或 `--disable-tool patch_files` 禁用。运行还要求启用 `read_file`、`edit_file`、`edit_lines` 和允许写入。逐文件审批、隐私、文件大小和换行规则沿用现有编辑后端。
