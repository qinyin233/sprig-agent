# 刷新模型目录

修改私有 `config.toml` 的提供商、模型别名、鉴权或生成设置后，在空闲的 TUI/chat 输入：

```text
/models reload
/models
/model ustc/flash
```

TUI 也有“刷新模型目录”按钮；按钮保留主输入草稿、文件选择和折叠粘贴。刷新只读取本地配置和当前 Sprig 进程的环境快照，不请求模型、不执行任务、不建立新会话。随后选择目标仍走[原有模型切换确认](model-selection.md)；下一条任务或明确“继续”才发往目标。

## 生效范围

- 刷新提供商默认项、模型别名及其端点、协议、鉴权、生成参数和请求预算快照。新增项会出现在列表和选择器；删除项不再能按旧别名选择。
- **当前模型及其实际鉴权保持原值**，不会因为文件编辑或刷新而自动切换。`@startup` 始终表示最初启动时的模型设置与凭据，不随刷新改写。
- 选择刷新后的目标继续保留原命令行优先级、跨提供商凭据隔离、完整请求预检和新批准。工作区、工具/路径权限、验收命令、命令环境、UI、模板、MCP/LSP 与存储策略保持当前运行值；修改这些设置仍需重启。
- 配置环境引用来自当前 Sprig **进程**；父 shell 后来设置的变量不会自动进入已启动进程。可编辑私有配置中的凭据，或重启以取得新的父进程环境。

这不是整个配置的自动热重载，没有文件监视、远程模型发现、自动回退或可用性/费用推断。

## 来源、取消与失败

始终读取启动时固定的用户配置路径和显式项目配置路径，不跟随后来更改的 `SPRIG_CONFIG`、当前目录或新仓库配置。隐式默认文件启动时不存在，可以在原默认位置创建后刷新；`--no-config` 明确禁用刷新。已存在的配置被删除、权限不安全、路径有符号链接/重解析点、TOML 非法或超过 64 KiB 时保留旧目录。

读取复用原有私有文件检查与配置字段校验；目标的完整解析和请求预检仍在选择时进行。目录和凭据快照一起发布；读取失败、取消、关闭资源、来源会话变化或保护容量不足不发布新目录。错误不回显配置值，也不改写原会话或草稿。

执行/确认期间不能从 UI 刷新。目录一旦刷新，之前尚未提交的模型切换提案失效，需要重新选择确认。刷新时收到普通新引导会保留，等待用户明确继续；失败或取消也不会自动调用模型。

## 凭据保护

刷新成功时，整份配置声明的新凭据立即加入进程内脱敏和子进程环境过滤，包含尚未选择的提供商及 MCP/LSP 凭据。环境变量名也保留保护：即使刷新时为空、以后其值改变，也不会因普通环境继承而泄露。旧凭据保护不会因目录更新或切换丢失；累计保护有容量上限，达到上限需重启。

若当前显式命令环境覆盖与新发现的凭据值或变量名相撞，拒绝构造该命令环境，需修正配置并重启。模型切换不替用户放宽这些策略。保护是当前进程的安全状态，不是新提供商授权，也不持久保存密钥清单。

## 验证

19 项新增回归覆盖固定来源、默认文件首次创建、私有文件失败、过期提案、取消、凭据容量与连续轮换、80×24 TUI 草稿和引导，以及实际子进程环境过滤。三个协议各 JSON/SSE 的六条真实 CLI 回环链先保存旧对话，再在配置中新增目标，刷新、确认切换、读取当前文件、新批准修改并独立固定检查；原会话逐字节保持。

这些是合成夹具与回环 HTTP 的实现证据，没有外部模型调用或编码质量结论。最终本地范围及隔离反例见[机器记录](benchmarks/model-catalog-refresh-20261025.json)。环境过滤有变化，远程原生 Windows/Ubuntu CI 仍待解禁验证；2026-11-01 前不触发 Actions。
