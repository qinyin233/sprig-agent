# 代码修复与重构提案

先配置[本地语言服务器](lsp.md)，在 CLI 或 TUI 对话框输入并按 Enter：

```text
/lsp code_actions cpp "src/main.cpp" 12 8
/lsp code_actions cpp "src/main.cpp" 12 1 14 8
/lsp apply_code_action lsp-action-<查询返回的标识>
```

第一条查询光标位置，第二条查询一个范围，行列从 1 开始、按 Unicode 字符计数。查询先显示服务器、待同步源码、范围和超时，请求本次批准；可收集该文件的有界诊断上下文。诊断原始 data 在校验后原样回传，不显示或执行其中的内容。缺少诊断发布者时仍能查询通用重构；等待诊断只占剩余预算的一部分。无版本推送可用但标记 `version_confirmed=false`，没有报告或没有提案均不代表文件正确。

返回的 `actions` 给出标题、类型、是否首选、是否需要解析、已知文件数和 `action_id`，最多 32 项。标识只在当前对话内存中有效，结果分页只读取已缓存的文字。配置禁用 `edit_file` 时仍可观察，但不提供可应用标识；只读模式禁止启动语言服务器。

选中操作后需要另一次批准。直接编辑使用已有快照；延迟编辑通过同一存活连接的 `codeAction/resolve` 发送原始提案，服务器必须保留既有属性，不能把 JSON 数字改成布尔值。断线后延迟提案失效，不自动启动、重查或重放；直接提案在完整源码仍一致时可以应用。源码、服务器配置、文档版本、归属、隐私或权限变化都会阻止过期应用。

选中批准后消耗该服务器的全部旧提案，解析失败或文件拒绝也不复用；选中阶段直接拒绝则保留提案。客户端先关闭归属服务器，再分别展示每个文件的完整差异并请求新批准，复用[编辑批次与撤销](lsp-rename.md)。没有跨文件原子事务：后续文件拒绝/取消会留下已经完成的前缀，未结算写入保留不确定状态与备份，不自动重试。

支持已有文件的普通 WorkspaceEdit，最多 16 文件、合计 512 处 TextEdit；同一版本、UTF-16、BOM、物理换行、路径与隐私检查共用重命名后端。带版本目标必须对应本连接同步的版本与完整摘要；无版本目标在取得编辑后绑定当前字节，返回 `unversioned_target_files`，不能据此证明服务器索引新鲜。提案缓存按源码、编辑及同步元数据保守计费，总上限 8 MiB；不保留已断开服务器的文档缓存。

带 command 的整项操作、文件创建/移动/删除、变更注解、未知字段和禁用提案均拒绝；不截取复杂操作的可执行部分。服务器本身具有当前用户权限，现有路径和批准检查不是 OS 沙箱。服务器结果不是授权、read_id、完整项目索引或任务验收。

模型工具使用相同的 `code_actions` 和 `apply_code_action` 两步操作，三种协议均适配 JSON/SSE。完整成功的修改触发已配置的编辑后固定检查，最终验收仍独立批准执行。终端本地命令不调用模型、不自动重新验收，可明确输入 `/verify`。

已安装 clangd 时可以运行固定的一次性 C++ 夹具：

```text
uv run --locked python scripts/verify-lsp-actions.py --clangd <已安装的 clangd> --approve-disposable
```

该选项仅批准脚本硬编码的六次临时查询、写入和恢复，不安装程序、不调用模型。它验证实际编译器修复、BOM/CRLF/Unicode 保持、精确撤销/重做和修复后空诊断；不等于真实仓库任务或模型成功率。[源码依据](research/lsp-code-actions-20261029.md)与[本批验证记录](benchmarks/lsp-code-actions-20261104.json)分别记录协议、引擎和平台证据。
