# 超过缓存容量的地图查询

日期：2026-10-05。旧版 `309936b405d1803bb7dd0d97ccfce00e4b90ee9f` 的解析缓存使用 LRU。顺序扫描 129 个不同文件时，128 项缓存每轮从头逐出下一份待用结果，导致重复查询仍解析全部 129 个文件。65 个较大符号列表也会触发 1 MiB 字节容量上限并产生同类问题。Aider 的 [RepoMap](https://github.com/Aider-AI/aider/blob/main/aider/repomap.py)同样将解析标签缓存作为地图的一部分；本批修复 Sprig 自己的有界内存缓存，没有移植它的磁盘缓存或引用排序。

## 当前行为

每次地图遍历保护开始时已有的缓存键，新结果不能逐出它们。不能缓存的新文件仍正常解析并参加完整候选选择，不缩小检索范围或改变工具输出。普通单次索引调用继续按最近使用逐出；索引仍按语言及内容摘要识别结果，每次读取最新文件并通过隐私检查，保存的只有编码声明元数据与摘要。

完整遍历结束后淘汰未再用到的旧摘要，释放空间供后续扫描适应内容变化。扫描失败、取消或因遍历/读取/输出预算不完整时保留未访问条目。整体内容替换时，首轮可能没有空间缓存新结果；清除未使用摘要后的下一轮重新填充，再次查询才取得稳定命中。此取舍保留 128 项、1 MiB 编码元数据与摘要的上限，不申请额外的无界候选缓存；两个临时键集合各最多覆盖 128 个原有键，Python 容器、AST、原生解析与进程 RSS 不属于这个编码字节指标。

## 对照入口

```powershell
uv run --locked python scripts/benchmark-tools.py --scan-cache --compare-ref 309936b405d1803bb7dd0d97ccfce00e4b90ee9f --repeat 5
```

两版使用同一驱动、uv Python、依赖锁文件、生成输入和输出预算，源代码由独立子进程从当前源码或明确 Git revision 导入。没有模型、HTTP、命令工具或文件工具写入；夹具创建和报告编码不计入工具耗时。每个场景使用新的只读工具实例，记录一次冷调用与五次重复调用。查询场景仍完整读取和检查全部文件，并核对每轮所有已知声明数量；不因目标提前出现就停止扫描。缓存内文件也必须重新读取。

这些是生成项目上的实际工具查询，证明缓存失效修复和本地重复解析开销变化。没有真实模型决策、任务成功率、完整 agent 延迟、引用图或与顶尖开源 agent 的同条件成绩。当前进程没有模型凭据，真实复杂任务对照仍待进行。
