# 排队任务与中途引导

TUI 中普通 Enter 在执行中继续表示“调整当前任务”。用 `/queue 正文` 收存下一项任务，用 `/queue run` 明确启动顺序执行；收存、查看、编辑均不请求模型。`--chat` 也支持这些本地命令，但它在当前调用返回终端提示符后才接受命令。

```text
/queue 为参数解析补充错误提示
/queue 为错误提示补充测试
/queue run
```

两项使用同一对话和工作区，按顺序各自调用现有 agent 执行链；每项重新获得配置的 `max_steps` 模型请求上限。若配置 12 轮、启动 3 项，最多授权这 3 项共 36 次模型请求，当前正在执行的任务另计。它不是独立会话或并行任务，较后的项能看到此前对话与文件变化。收存正文不会把未来任务提前加入当前模型请求，也不会关闭正在等待的批准或提问。

`/queue run` 只授权当时已有的条目标识。启动后新增的项，以及编辑或切换模式后获得新 ID 的项，均须再次 `/queue run`；不会为绕过未获授权的首项而跳到后面执行。可以在 TUI 当前任务运行时启动队列，它会等当前调用正常结束再递送。未配置 `checks` 时，“正常结束”只表示模型回复结束；有固定检查时，每项仍走独立最终验收。模型自报完成或任务计划不能代替检查。

| 命令 | 行为 |
| --- | --- |
| `/queue` | 查看受输出预算限制的待处理预览及 ID |
| `/queue 正文` | 收存文本项，保留正文首尾空白与换行 |
| `/queue add "JSON 字符串"` | 显式编码正文；换行可写为 `\n`，原始 CR 写为 `\r` |
| `/queue run` | 明确顺序请求模型，不批准任何工具动作 |
| `/queue pause` | TUI 暂停后续项，当前任务继续；聊天模式下队列已空闲 |
| Ctrl+C | 取消当前任务并暂停后续项 |
| `/pending manage` | TUI 查看、编辑、移除、排序及切换引导/排队模式 |
| `/pending delivery ID steer\|queue` | 新确认后切换模式，分配新 ID |

`run`、`pause` 和 `add` 是命令字。正文恰好为 `run` 时，用 `/queue add "run"`。TUI 在已输入的 `/queue ` 后粘贴正文，会将粘贴内容作为数据；即使粘贴的是 `run`，也只收存。折叠、F4 展开与撤销/重做保留这一属性；修改命令前缀会撤销该属性。终端粘贴仍规范化 CR/LF，需精确保留时使用 JSON。一次性粘贴整段命令遵守原有粘贴保护，不能借折叠内容隐式触发控制命令。

队列当前接收文本。带 TUI 文件选择元数据的提交会拒绝并保留草稿和选择；不会静默丢掉附件。可在文字中指定工作区路径，让模型按范围读取，或使用已有实时文件引用；引用属于当前对话，不是每条排队任务独立的附件快照。长正文仍受 UTF-8 和完整请求预算限制，不能因折叠预览绕过限额。

用户拒绝或配置策略拒绝、取消、请求/保存错误、轮次耗尽、未完成验收会暂停后续项。可用 `/continue` 继续当前任务，处理后再明确 `/queue run` 启动余下项；继续当前任务不会重新启动队列。`/queue pause` 不撤销正在执行的动作。每次写入、命令和外部工具仍需新的明确批准，只读模式、隐私路径、版本绑定和取消检查仍由执行层负责。

启用会话保存时，先保存条目才接收；未保存的队列仅在当前进程内存中。恢复不保存“队列已启动”状态，不自动请求模型或重放工具。TUI 先 `/pending apply`：引导加入对话，排队项保留，之后 `/queue run` 才执行；聊天模式中只含排队项时，也可直接明确 `/queue run`。混合恢复仍须先处理引导。保存不确定时按原 ID 重试或明确丢弃/恢复，不盲目递送；详细边界见[待处理输入](pending-inputs.md)。

存在未递送排队项时，模型切换或对话分支不会提交。`/pending apply` 会保留排队项，需先运行、逐条移除或明确丢弃后再切换；排队正文不会悄悄迁移到另一模型或分支。

这项能力来自对固定 OpenCode 源码中不同递送时机的阅读，见[源码记录](research/opencode-source-reading-20261020.md#16-排队与引导的递送时机2026-10-23)。它不提供定时调度、跨进程自动重启、已递送历史编辑或副作用恰好一次保证。离线三协议、TUI/CLI 与安装包回归只验证产品行为，不证明真实模型编码完成率提高。CI 依用户要求在 2026-11-01 前冻结，到期仍须核对账户限制和此前必要 gate。
