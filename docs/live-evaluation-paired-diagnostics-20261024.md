两套评测工厂继续显式固定 16000 字节的原始命令采集/展示上限，没有沿用产品新默认的 1 MiB。mini 小夹具的额外 600 秒 SDK 壁钟限制包含审批等待，两次均未触发；Sprig 没有相同的额外壁钟限制。原生工具、模板、历史处理与附加检查说明不同，因此相同原始文件和用户任务不意味着完整 HTTP 输入相同。mini 原生报告没有单独保存 Node 版本，不能声称逐条运行环境元数据全部相同。

## 崩溃与修正

第四次运行已完成基线和文件读取，在独立多文件编辑的内部预检阶段，`MeasuredTools.execute` 将 `EditPreview` 当作普通工具结果传给 `json.dumps`，抛出 `TypeError`。没有取得原生报告，不能从终端事件补算完整请求数、用量、审批等待或任务耗时，缺失字段保留 `null`。

保留的候选与初始文件逐字节一致，没有实际写入。另行批准的固定后置检查仍有 3/4 项失败，验收目录与原始快照一致；这只是崩溃后候选状态，不是完成了正常循环后的模型能力成绩。没有重试该模型任务或追加预算。

修复将内部预检单列为 `edit_preflight`，只记录工具名、耗时与是否就绪；不序列化文件路径、版本、规则或前后快照，也不冒充模型实际收到的结果字节。就绪不代表批准、写入或验收。预检前后继续核对验收器完整性，实际写入仍逐条取得新批准。

同时复核出 Sprig 和 mini 评测包装器用 `bool(callback(...))` 接受非布尔回调值的问题，已改为只有字面 `True` 才授权。旧代码下，`1`、`"yes"`、非空列表确实能越过包装器触发临时命令；普通产品工具自身的严格判断没有改动。本轮真实操作使用内置终端批准函数，返回值为布尔值，没有利用这个缺口。

新回归覆盖两文件编辑成功、拒绝首项后余项停止、预检失败零写入、预检期间验收器变化及非布尔回调拒绝。修复后的真实模型任务尚未重跑，不能把离线脚本化修复成功当作第四条真实成绩。完整本地范围见[修复验证记录](benchmarks/benchmark-boundaries-20261024.json)。
