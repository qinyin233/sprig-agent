# 请求统计保存与恢复

启用 `--save-session NAME`、TUI 保存或已有的 `auto_save_session` 后，请求统计随私有会话一起保存。未启用保存时只在内存中记录。`/usage`、TUI 的请求统计按钮和 `--metrics` 将当前 Provider 的进程内统计与 `session_usage` 分列；查看统计不新增模型请求。

```sh
uv run --locked sprig --tui --save-session coding
uv run --locked sprig --tui --resume coding
uv run --locked sprig --session-usage coding
```

最后一条是独立离线入口：只输出数值、固定状态与本地标识，不选择原模型、不要求模型凭据、不输出对话或重新验收。可用 `--session-dir PATH` 指定已有私有存储；其他模型或工作目录下保存的数值也可检查，但恢复对话仍要求原有模型/端点/工作区绑定。占用中的会话拒绝跨进程读取，路径、隐私、文件大小和结构校验保持。这个入口沿用私有租约锁，不改写已有会话正文或统计，也不启动 MCP/LSP、后台命令、固定检查或模型。

每次 HTTP 尝试前保存开始标记，收到完整结果或确定失败后分别结算。配置允许的 HTTP 重试逐次记录，不按一次逻辑调用合并隐藏。原有请求数、重试规则、输出上限、总期限、独立检查和工具审批保持；统计不进入模型上下文。保存开始标记所用时间计入同一请求期限，过期后不会再开始网络操作。

如果进程在开始与结算之间退出，恢复会把该请求列为 `uncertain_requests`。它可能尚未发出，也可能已到达供应商，不能由本地开始标记推断消费或服务端副作用。恢复和离线查看都不会重发。缺少旧统计的历史有 `coverage_gap=true`；有缺口、未结算请求或供应商缺失某类 token 时，相应字段的完整总量保持 `null`，已报告的部分和已知数量另列，不填成零或推算账单。

保存失败或同步结果不确定会阻止后续请求及该响应的待执行工具意图。当前 Provider 的原始成功/失败记录保留，显示 `persistence_blocked`；先明确恢复并核对实际保存状态，再继续。替换前失败可能留下开始标记，替换后同步失败也可能已留下完整结算，因此恢复以实际读到并校验的私有文件为准，不重放动作。新建对话仍需正常确认，原文件保留。

会话分支、编辑历史请求和模型切换为新会话建立独立计数，旧累计值作为 `inherited_snapshot` 保存来源标识和快照摘要，标记 `new_consumption=false`。不会把复制历史算作新调用，也不把继承快照加到当前会话的消费数。继承记录描述分支建立时原会话的累计观察，不按所截取的消息比例分摊；不同分支里的继承快照不能相加当作全局账单。审批期间源统计变化会使旧分支/切换提案失效。

每个会话最多保留 128 条已结算请求的明细，累计计数独立保存。只接受严格的数值、布尔值、允许列表状态和本地摘要/标识，拒绝多余字段、异常数字、过期计数和凭据冲突；保存沿用既有私有目录、会话租约、原子替换和 8 MiB 上限。统计字段不保存提示、正文、头、URL、工具参数或推理；已启用的私有会话仍按原规则保存对话。会话统计是本地观察，不是批准、文件版本、任务通过证明或供应商账单。

源码依据见 [OpenCode 阅读](research/opencode-request-measurements-20261029.md)。最终验证范围与首轮失败见[机器记录](benchmarks/request-usage-20261029.json)；没有追加外部模型请求，也不把统计可靠性等同于编码完成率提高。远程 CI 继续按 2026-11-01 前的冻结规则待验证。
