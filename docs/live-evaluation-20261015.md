[Click 实际运行](benchmarks/live-click-sprig-20261015-01.json)的 12 次请求均成功，服务报告总 token 77,429，没有传输或工具错误，却仍未提出编辑或命令，耗尽轮次后停止。18 次工具调用为列目录 4 次、读取 7 次、搜索 7 次；搜索命中为 6、1、2、0、0、1、1 行，没有相同参数与返回对象的重复检查。前四次工具调用都在逐层列目录，五次按行读取标记仍有后续正文；它们不是输出丢失的证明。总时长 278.677 秒，pacing 等待 138.154 秒，HTTP 合计 138.890 秒。

这一次不能把没有开始修改归因为调用错误；但 12 轮预算不同于旧版 20/40 轮，不能证明更大预算必然失败，也不能单凭一次运行排除网络路由的普遍影响。思考请求参数并未让此次受限任务完成，整体缺口仍是较复杂任务中的定位、决策与实现推进，而不是仅有连接是否可用。

随后仅修改 Sprig 的工作提示：陌生仓库优先使用已有 `project_map` 的符号/路径查询定位，随后针对性搜索和按行读取，保留“地图不是完整行为、需检查截断并阅读实现”的要求。没有强制预设工具序列或根据预算自动编辑，也没有改变批准规则。提示增加 299 个 UTF-8 字节；这些实测发生在改提示之前，没有把新提示伪装为已验证收益。

本地一次性 Click 快照上，实际 `project_map(query="command")` 返回 15 个文件、91 个匹配声明，包含 `resolve_command`，输出 7,559 字节且未截断。这验证了已有工具可直接提供定位信息，不能证明模型会使用它或减少后续模型调用；相比浅目录列表也增加了初始上下文开销。本批到此停止真实 API 测试。三条真实运行共 25 次成功请求，服务报告合计 111,927 token，不是账单或全任务成功率。
