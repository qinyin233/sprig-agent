# 读取版本绑定的整行编辑

`read_file` 完整校验文件后，返回 `sha256` 和一个简短的 `read_id`。已知文件路径时，也可通过 `grep(output_mode="read")` 同时搜索和取得完整编号窗口及读取标识。模型用 `edit_lines` 提交当前版本的修改。[单文件搜索读取](grep.md#在单个文件内搜索并读取)

```json
{"path":"src/example.py","read_id":"r0123456789ab-1","edits":[{"start_line":3,"end_line":4,"new":"replacement\n"}]}
```

范围读取默认在 `content` 中显示 `N: ` 行号前缀，`line_numbers=true` 也可为不带范围的读取启用此视图（默认最多 2000 行）。前缀是显示信息，不属于文件；传入 `line_numbers=false` 获得原文，附件始终使用原文。CR、LF、CRLF 决定物理行号，Unicode 段落分隔符不产生新行；编号也计入输出字节预算。编号不会改变原始摘要或版本标识。

精确 `old/new` 替换失败后的导航提示显式带 `line_numbers=false`，便于按实际原文重提精确匹配，避免把编号复制成文件内容。

超长单行另有 `read_file(cursor="start")` 的可续读字节分页。游标绑定路径与内容版本，每页先完整校验。字节片段不发放行编辑的 `read_id`，编辑前仍需读取相关完整编号行。[可续读字节分页](text-transfer.md)

行号从 1 开始，结束行包含在内。插入使用 `end_line=start_line-1`。每次最多 32 段，不能重叠。`new` 是字面文本，须包含所需的 LF、CRLF 或 CR。后面还有文件内容时，非空替换必须以换行结束。在没有末尾换行的文件后追加时，必须明确提供前导换行，或直接替换最后一行。违反这些条件会在审批前拒绝整批，避免把新旧代码拼到同一行。最终行可以不带末尾换行，空替换可删除完整行。

在换行一致的文件中，可以用 `lines` 提交完整物理行，无需在字符串中写入换行符。

```json
{"path":"src/example.py","read_id":"r0123456789ab-1","edits":[{"start_line":3,"end_line":4,"lines":["replacement",""]}]}
```

每段选择 `new` 或 `lines`。数组内每个字符串保留空格和缩进，不能包含 CR、LF 或 NUL。Sprig 为每项附加原文件唯一的换行符，空文件或没有换行符的文件使用 LF。`[""]` 表示一条空行，`[]` 表示删除选中行。为混合换行文件提供新行时，用字面 `new` 指定行尾。要写入没有换行符的最后一行，或在现有未终止行之后追加且保留它的内容，也用字面 `new`。失败的提案需要重新提交。

512 KiB 写入上限、完整 diff、新批准、审批后内容与文件版本复查、精确撤销继续适用。短标识关联路径与完整 SHA-256。

成功的 `edit_file` 或 `edit_lines` 可返回提交后版本的 `read_id`。若已知修改后的相关原文，下一次可以用它提议新编辑。每次写入仍需独立批准和内容复查。相关工具须启用，结果须能容纳标识。

同一入口也支持 `patch` 代替 `edits`，包含多个标准编号 unified hunk，逐行严格核对上下文和坐标，沿用文件换行与完整版本门禁；见[紧凑补丁](line-patches.md)。两种输入不能混用，既有 `edits` 的字面换行语义保持。

范围读取仍扫描整个受限文件（最多 8 MiB）；返回窗口可以有后续行，但当前物理行必须完整。普通截断字节前缀、局部物理行、二进制、包含已知凭据或被隐私规则排除的内容均不发放标识。编辑前仍应读取全部相关行。

标识只在当前工具实例的一次 agent 运行内有效，最多保留 128 个文件版本。相同路径与摘要复用标识；不同路径不能互用。以下情况需重新读取：

- 对该文件完成写入、撤销或重做后。
- 普通获批命令会清除标识。编辑后的固定检查先清除标识，所有命令正常退出后，应用重新读取并校验最近至多 16 个版本，恢复路径仍可读且内容摘要相同的标识。每个文件最多读取 512 KiB。超时、输出超限、中断或后台任务状态变化时，按命令失效规则处理。[编辑后检查](edit-checks.md)
- 新任务、继续、恢复或工具实例关闭后。保存的对话可能包含失效的旧标识。
- 标识因有界缓存淘汰而不再存在。

外部更改使旧摘要失效，停在审批之前；审批期间更改也拒绝覆盖。其他文件的编辑不使本文件标识自动过期。原来的 `edit_file(old,new)` 与精确多片段替换保留；旧 `sha256+line_edits` 运行接口仍兼容，模型 schema 推荐使用独立 `edit_lines`。

用 `/continue` 或不附带新任务的 `--resume` 继续时，Sprig 可在首个模型请求中为此前读过的源码发放新标识。它从本次请求的最近 48 条消息中检查当前任务仍可见的 `read_file`、`grep` 或 `search` 源码结果，包括本次压缩保留的完整源码窗口。最多复核 8 个文件，每个最多读取 512 KiB。文件须通过当前路径和隐私策略，并且完整 SHA-256 与当时一致。模型收到路径和新标识，可以直接使用此前看过的行；原标识仍在当前请求中时也会列出。受请求预算限制时省略提示。恢复过程只检查文件，原先未完成的工具调用保留中断记录。编辑仍需新的批准及版本复查。

`[tools].edit_lines=false` 可单独关闭它；`edit_file=false` 或只读模式同时禁止两种写入接口。项目层不能借启用 `edit_lines` 绕过用户禁用的 `edit_file`。

版本参数错误返回固定分类：`missing_revision`、`invalid_revision`、`unknown_read_id`、`stale_revision`；无效参数不会被替换成当前版本后继续写入。基准诊断只记录这些固定状态与版本是否可用，不发布摘要、短标识、路径或原始参数。

这项接口源于[20 轮 Click 失败记录](live-evaluation-20261016.md)后续的离线改进。原始模型第二次编辑的原始参数未保留，不能确定是缺失摘要还是格式错误；离线接口回归不能证明该真实任务已修复或模型编码能力提高。

后续保留私有会话的 CLI 复测仍未完成任务，但首次能重放原始编辑：缺少末尾换行的提案在旧实现中拼接了后续类定义。新边界校验拒绝该原提案，明确补换行后的离线新提案通过语法检查。这只证明已定位并防止具体拼接问题；模型的行号选择、正确实现和完整验收仍需真实复测。
