# 审批回调的严格布尔契约

更新：2026-10-22。所有审批回调只有返回 Python 布尔值 `True` 才能放行。`False`、`None`、字符串（包括 `"yes"` / `"false"`）、整数 `1`、列表、字典和其他对象均拒绝。不调用返回对象的 `__bool__`、不解释对象中的 `approved` 字段，也不自动等待 future/coroutine。宿主回调应明确返回 `True` 或 `False`。

普通用户操作保持原样：CLI 将人在终端输入的 y/yes 转换为布尔值，非交互输入默认拒绝；TUI 的批准按钮返回 `True`，拒绝、关闭或无效弹窗结果均拒绝。此契约约束可编程回调和弹窗边界，不把模型文字或工具结果当作授权。

此前部分入口使用 Python 真值判断；回调意外返回非空 `"false"` 或 `1` 时，会错误地放行文件写入、命令或私有数据删除。新回归先复现误放行，再收紧：

- `Tools.request_approval` 在发布 approved/running 观察前规范为严格布尔值，继续执行取消与关闭资源检查。
- 独立 MCP、LSP、网页入口，以及 Git worktree 的确认也单独检查类型；拒绝 checkout 不记录“已尝试创建”。
- 配置创建、日志清理、会话保留清理、CLI/TUI 删除、模型切换、对话分支与摘要确认遵循同一契约。TUI 不因无效弹窗值误记本地操作已获批准。
- 回调异常继续向上传播；取消仍中断动作。一次有效批准不授权下一次动作，版本复核、隐私与只读/硬禁用边界保留。

新测试覆盖真实文件、子进程、私有日志/会话、实际 Git 仓库和 Textual 界面，并在独立传输入口验证无效回调不会构建 MCP/LSP/HTTP 客户端。14 项新回归包含正常 `True` 的执行和逐次拒绝；相关既有测试覆盖三协议和运行状态。验证范围、源文件摘要和平台跳过见[机器记录](benchmarks/approval-types-20261022.json)。

这是误放行防护，回调宿主仍负责连接真实的授权界面；任意获批命令仍没有 OS 文件/网络沙箱。本批没有修改原生进程后端，远程 CI 按用户要求暂停到 2026-11-01，之后仍先检查账户限制和旧 gate。
