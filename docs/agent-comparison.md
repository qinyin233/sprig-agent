# 同类编程代理对照与 Sprig 开发路线

调研日期：2026-10-02。依据公开 README 和实现源码，以下是能力对照与设计取舍，没有做跨产品性能测评，也不声称 Sprig 已覆盖其他项目的全部功能。

本页记录已有实现与早期补齐清单。扩展到八个现行项目和一个归档项目的最新调研、差异化提案及建议实施顺序见[Sprig 差异化调研与产品提案](sprig-differentiation.md)。

Sprig 借鉴这些接口边界和交互流程。模型与工具核心使用 Python 标准库，终端 TUI 使用 Textual，所有依赖由 uv 管理。本轮实现没有复制这些项目的源码，没有引入它们的依赖或框架。

## 本轮共同基础能力

| 能力 | Sprig 当前实现 | 当前范围 |
| --- | --- | --- |
| 读取、搜索、编辑、终端执行 | 六个 function tools；精确匹配编辑、diff 与逐次确认 | UTF-8 文本；命令没有沙箱 |
| 流式交互 | `--stream`，文本增量显示，工具参数按索引组装 | Chat Completions SSE；完整响应后才执行工具 |
| 终端界面与连续对话 | `--tui`、Enter 发送、中途引导、实时模型/命令输出、确认窗、取消、会话管理；保留 `--chat` | 单一工作线程；新要求在安全节点生效；无交互式 stdin/PTY |
| 安全操作模式 | 只读模式、敏感文件排除、`.sprigignore`、最小命令环境、增量密钥遮盖 | 应用层防护；编辑模式的获批命令仍没有操作系统沙箱 |
| 会话管理 | 保存、恢复、列表、确认删除；绑定服务/模型/目录/验收条件 | 独占操作系统锁；崩溃释放；不重放中断操作；列表不上传正文 |
| 项目地图 | `project_map` 给出文件路径与 Python 声明行号 | Python AST；其他语言只列路径，没有调用图 |
| Git 查看 | `/diff`、`/git` 本地查看当前工作目录 | 需确认；不自动提交或回滚 |
| 测试与修复 | 用户固定 `--check` 命令，失败返回模型 | 每次执行需确认，仍受步数和命令资源上限约束 |
| 跨平台 | POSIX 目录 FD/进程组；Windows 无重解析句柄/DACL/Job Object | Linux、Windows 本地实测；[三平台、四版本 CI 已通过](https://github.com/qinyin233/sprig-agent/actions/runs/37007902891) |

## 本轮差异化功能：绑定会话的独立验收

Aider 已有自动测试与修复反馈，因此“能跑测试”本身不是新概念。Sprig 本轮新增的组合围绕逐次确认和恢复一致性：

1. 验收 argv 由用户指定，模型不能把应用验收条件换成其他命令。
2. 应用在模型结束后独立执行验收，用真实退出码、超时和输出截断状态决定验收结果。
3. 命令意图先保存，工具结果后保存；恢复时不重放可能已经产生副作用的操作。
4. 服务、模型、工作目录和验收条件一同绑定。恢复时删除或修改验收参数会被拒绝。
5. 失败证据进入下一轮修复，拒绝执行则停止；用户没有授权时不会继续寻找绕过方式。

这是 Sprig 当前产品的差异化设计方向，不是“行业首次”声明。验收命令也可能写文件或访问网络，没有操作系统沙箱；用户定义的标准是否充分，需要由用户判断。

## 后续路线与验收条件

按优先级继续补齐，而不是把尚未实现的能力列为产品功能：

| 优先级 | 下一步 | 完成标准 |
| --- | --- | --- |
| 1 | 会话并发锁与会话管理（已落实） | 已验证两个进程不能覆盖同一会话、退出/崩溃后释放、列表/确认删除 |
| 2 | 上下文预算与压缩 | 保留用户目标、拒绝记录、未完成调用和验收条件；可查看压缩前后差异 |
| 3 | Git 隔离工作树与可审查修改记录 | 不改变已有未提交工作；按会话显示 diff；撤销需要明确确认 |
| 4 | 更完整的项目索引 | 增量更新与跨语言符号索引；明确区分语义索引和名称扫描 |
| 5 | MCP 工具接入 | 工具来源、权限和输出预算可见；不自动提升现有批准范围 |
| 6 | 命令增量日志与任务队列 | TUI 有界显示命令输出；排队任务不能绕过确认、取消或验收条件 |
| 7 | 容器/受限进程工作空间 | 明确验证文件、网络、环境变量和子进程的隔离能力 |

本轮交付的是上述共同基础功能、终端 TUI 和独立验收机制。多代理、浏览器、容器执行和完整 IDE 集成仍属于后续工作。
