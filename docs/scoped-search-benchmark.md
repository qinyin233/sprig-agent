# 固定 Click 源码的检索对照

本入口复用 [Click 编辑基线](repository-edit-benchmark.md)中的修复前快照 `19fd4d6e18bc9fce451f92f422696b11169faa57`：52 个文件、快照 SHA-256 `7d610833c8a6564f980f747e4601e7f4821872702c4a59f32ff9c5d653300d08`。数据保持上游许可，读取前验证完整清单、大小和内容摘要，测量不下载、不执行该项目的代码。

两个上下文场景分别查找 `src/click/core.py` 中的 `def format_commands(` 和 `tests/test_options.py` 中的 `def test_unknown_options(`，需要命中行以及紧邻前后两行。另加同一源码目录、不筛选、不带上下文的普通搜索作对照。位置和查询来自已知源码，是同一代码窗口的文件工具对照；没有模型参与定位，不能解释为真实任务成功率或 SWE-bench 成绩。

旧版 `c165daf476164ce72a86224cac5da77900229ae6` 仅支持目录搜索，因此搜索目标的父目录，再按命中行号读取范围。新版第一个场景直接搜索文件并返回上下文；第二个场景仍搜索父目录，使用工作空间相对 glob 筛选目标文件并返回上下文。两边均用默认 16,000 字节结果预算和原有隐私检查；每次实际调用工具，要求命中唯一目标、行号正确，返回的五行与冻结源码完全相同。分页读取的 `truncated` 表示文件还有后续页，只有 `line_truncated` 表示这次所需行未完整返回。

## 重复运行

先按[快照准备说明](repository-edit-benchmark.md)用 `benchmark-edit-repo.py --fetch` 获取固定输入，再运行：

```powershell
uv run --locked python scripts/benchmark-tools.py --click-fixture $sprigClickFixture --compare-ref c165daf476164ce72a86224cac5da77900229ae6 --repeat 11
```

POSIX 使用同一入口，将 `$sprigClickFixture` 替换为快照根目录路径。`--click-fixture` 只运行本检索对照，不混入解析或其他性能场景；原有无此参数的索引测量入口保留。

每版在独立工作进程中导入指定源码，并核对实际 `Tools` 来源；从受信的本地 Git revision 提取旧版。使用同一个 uv Python、输入和上下文范围。计时仅包含实际搜索 / 范围读取，排除导入、夹具校验、复制、结果验证和报告编码。通过同一 `Directory.open_read` 包装统计成功打开的内容文件和真正返回的字节；包装在计时内，因此时间也包含统计开销，不能视为无插桩的生产性能。已知模型环境凭证不会进入子进程，不调用模型或命令工具。

## Windows 结果

[原始报告](benchmarks/scoped-search-click-windows.json)保留解释器、依赖、锁文件、源码 / 驱动 / 辅助文件摘要、输入身份、重复次数，以及逐次工具调用、文件读取、读取字节、返回字节、耗时和上下文摘要。

| 场景 | 工具调用：旧 / 新 | 实际内容文件读取：旧 / 新 | 实际读取字节：旧 / 新 |
| --- | --- | --- | --- |
| 已知源码文件 | 2 / 1 | 19 / 1 | 532,316 / 135,359 |
| 测试文件筛选 | 2 / 1 | 32 / 1 | 432,382 / 88,654 |
| 不筛选、无上下文的普通搜索 | 1 / 1 | 18 / 18 | 396,957 / 396,957 |

每版、每场景重复 11 次，共 66 次检索流程；其中 44 次上下文检索的五行及 22 次普通搜索的命中行都完整且摘要相同。计数不包含未打开的 `.sprigignore` 查找、Git 和夹具准备；包括旧版搜索后的实际整文件范围读取。筛选仍遍历目录项，不等于完全没有目录遍历开销。

普通搜索的读取量相同，本次中位耗时为旧版 13.375 ms、新版 14.154 ms，结果 JSON 从 168 增至 251 字节。新增取消检查、扫描统计和完整预算计算也有开销，运行噪声仍存在；本批改善的是主动缩小范围与直接上下文的检索，不宣称所有普通搜索都更快。两个上下文场景的计时和全部原始数据均保留在报告中。

测量只覆盖两个已知位置的代码窗口。未清空系统缓存，不设置耗时阈值作为测试，不能把调用、字节或工具时间的减少直接换算为 token、费用、模型请求轮数或整体任务延迟。当前新增报告仅为 Windows 本地证据；同模型自主复杂仓库任务和远程多平台 CI 将继续验证。

本批 Windows Python 3.11 / 3.13 全量测试各运行 351 项：338 通过、13 项 POSIX 专用检查跳过。本机 WSL Linux Python 3.12 同样运行 351 项：335 通过、16 项平台检查跳过；包括 POSIX 链接、FIFO、目录 FD 和新增搜索检查。原生 Windows junction、设备路径、CRLF 与新增文件搜索检查实际运行。构建和 CLI 帮助通过。本地证据不能标记为 GitHub CI 通过；本批按额度限制跳过 CI，远程矩阵将随大更新执行。
