# 本地命令与旧验收结果

TUI/chat 的 Git、worktree、MCP、LSP 和后台命令入口可能执行外部程序。即使操作名是“查看”，程序也可能调用辅助程序，或在返回错误前产生副作用。Sprig 按本次真实批准事件使旧验收失效，不依靠工具结果里是否仍有 approved 字段。

- CLI 的 `/git`、`/diff`、`/worktree`、`/worktrees`、`/mcp`、`/lsp`、`/job` 共用批准观察；后台 start 和 cancel 同样适用。
- TUI 收到相关操作的批准时立即使原任务变为未重新验收；本地操作失败或取消不能使它重新显示通过。后台停止也适用。
- 每条本地命令最多追加一条固定的工作区结果不确定提示。worktree 的多个命令仍分别批准，但只产生一条整次操作提示。
- 本地状态、缓存分页、拒绝或尚未获批时的取消不会凭空追加副作用记录。命令的错误/取消状态仍会如实显示，不能据此推断命令已执行。
- 已批准操作会清除旧读取标识和语法缓存。继续编辑需要重新读取，提示本身不授权任何命令或文件修改。

CLI 取消仍返回 130，执行错误或保存错误按原错误路径处理；操作后需要重新验收时保持未完成状态。TUI 分开显示任务状态和最近本地操作状态，查看本地数据不会把旧任务自动变成通过。运行快照记录的是最近模型运行阶段，旧快照中的检查通过不能覆盖本地操作之后的任务失效状态。

提示只描述不确定性，不上传本地命令 argv、输出、MCP 返回内容或 worktree 路径。终端仍展示本地结果。已有工具结果若先前已明确进入模型历史，不会因此被删除；本规则不改变用户显式发送上下文的行为。

启用私有保存时，提示随普通历史保存；保存失败会显示错误并保留内存提示，不能声称磁盘已经更新。恢复或 `/continue` 不重放本地命令，也不复用旧批准。只有用户再次发送任务或继续时才请求模型，固定最终检查仍单独运行并新批准。

外部程序仍具有当前用户权限，本功能不提供 OS 沙箱、自动回滚、全局文件监视或崩溃后的副作用追踪。尚未获批时没有记录，并不证明其他独立进程没有修改工作区。

回归见 `tests/test_local_actions.py`：真实 MCP 进程写文件后取消、真实后台进程启动后丢失结果、后台停止的控制错误、Git/worktree 批准前取消、四次 worktree 批准、私有保存、继续时不重放，以及 TUI 的独立验收和停止/保存失败。故障注入用于覆盖返回结果或存储失败，不能冒充真实模型编码成绩。平台、源码摘要和 CI 暂停状态见[验证记录](benchmarks/local-actions-20261022.json)。
