# 受批准的目录、删除与移动

`file_action` 让模型直接提出有界文件操作，CLI、chat 和 TUI 共用同一执行路径。无需让模型为基础文件操作拼接 Windows/POSIX 命令。默认启用；`[tools].file_action=false` 或 `--disable-tool file_action` 关闭，`edit_file=false` 同时禁用它。只读模式隐藏该工具，并在实际执行入口独立阻止它；显式项目配置不能重新启用用户禁用的写入策略。

| 参数 | 行为 |
| --- | --- |
| `action="mkdir", path="pkg"` | 创建一个目录；父目录须已存在，目标须不存在；单独批准，不隐式创建整条目录链 |
| `action="delete", path="old.py", read_id="…"` | 删除已读取的一个普通 UTF-8 文件；显示完整删除 diff，重新批准 |
| `action="move", path="old.py", destination="pkg/new.py", read_id="…"` | 先独占创建完整副本，再单独批准删除源文件；禁止覆盖目标 |

已有文件的操作要求当前运行中 `read_file` 发放的读取标识，按完整内容摘要复核源文件。文件最多 512 KiB；二进制、无效 UTF-8、受保护/排除项、活动配置、已配置凭据、越界路径及无效标识在批准前拒绝。依旧使用工作区相对 POSIX 路径，Windows 的设备名、备用数据流和重解析点等沿用底层限制。普通目录、文件工具禁用与取消检查均由程序执行，不依赖模型遵守提示。

## 移动是两个明确阶段

第一份批准显示目标新文件的完整 diff，并明确这只是复制。目标采用独占创建，即使批准期间突然出现外部文件也不会覆盖；文件正文逐字节保留。复制完成后第二份批准显示源文件完整删除 diff。删除前重新检查源文件、目标副本、隐私及适用项目规则；目标变了，就保留源文件并返回部分完成状态。

第二步拒绝或出错时，第一步已批准的副本可以保留，返回 `copied=true`、`partial=true` 和源删除状态。取消也可能发生在复制之后：查看两个路径和修改记录再继续，不重放原意图。不会绕过拒绝删除源文件，也不会未经新批准自动清理副本。TUI 审批框内 Enter 发送新引导时同样保留副本，并准确报告已有工作区改动。

这不是 OS 原子 rename，不保留全部文件系统元数据、硬链接关系、时间戳或扩展属性。POSIX 保留普通权限位；Windows 新副本使用当前用户私有 ACL，批准界面明确提示。Windows 大小写等价的同路径移动、目录移动、递归删除和目录递归创建都不由此工具提供。

## 撤销、状态与文件引用

删除记录完整原始文件；撤销重新创建，重做重新删除，每次仍须新批准并验证当前状态。Windows 撤销/重做重新创建缺失文件时使用当前用户私有 ACL，避免继承父目录更宽的读取权限；这也可能收紧原来的共享权限。移动记录两次文件变化：撤销先恢复源文件，再撤销目标创建；重做也按两步进行。文件备份沿用 16 条/4 MiB 上限与可选私有日志，不因目录操作扩大。目录创建不进入文件撤销历史，批准界面明确说明。

写入或日志检查点失败时，工具报告 `outcome="uncertain"`，保留待确认记录并阻止后续文件修改。移动第二步结果不确定时 `source_removed=null`，不能解释成源文件仍在。目录创建失败也要求检查当前状态；不会自动递归回滚目录。

模型操作明确成功后，已选实时引用跟随移动，删除的路径从引用集合移除；第二步批准中说明这一点。引用路径总预算在动作前检查，失败不会先改文件。拒绝、部分移动或不确定结果不擅自改引用。撤销/重做若明确删除了引用文件，也移除该引用；不会恢复更早的整个引用集合。普通历史中的旧正文仍保留。

`check_after_edit` 对成功的文件操作批次也运行固定阶段检查；模型结束时的最终验收继续独立运行。复制、删除或阶段检查成功都不等于任务整体完成。当前没有跨文件事务，多个生命周期调用或混合工具回复仍顺序执行；较早已批准的变化不会因后续失败自动撤销。

## 验证边界

新增回归覆盖实际文件变化与精确撤销/重做、私有日志恢复、不覆盖竞争、两个审批节点的源/目标变化、隐私/规则变化、取消、拒绝、未确定的日志结果、读取标识和配置硬限制、TUI 中途引导、实时引用及历史压缩。脚本化回环 HTTP 执行“读源文件 → 创建包目录 → 移动实现 → 删除旧文件 → 修改导入 → 阶段检查 → 独立最终检查”，全部使用一次性夹具，没有付费模型请求。

工具说明精简了重复文字，九个工具的紧凑 JSON 定义为 4920 字节，旧八工具为 4932 字节；没有增加请求上限。既有大块编辑回放继续保持相同预算和请求次数。字节与脚本化协议证据不能推导真实模型成功率或与顶尖 agent 的性能差距已经消除。

能力对照参考 [OpenCode 工具文档](https://opencode.ai/docs/tools/#apply_patch)：其补丁入口涵盖增改、移动和删除路径。本实现采用显式阶段批准和读取标识，不声称补丁格式兼容、完整原子移动或相同模型表现。
