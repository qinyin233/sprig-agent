# 按名称查找语法调用位置

`project_map` 现在可以在同一结果中给出声明和调用候选：

```json
{"path":"src","query":"resolve_command","include_calls":true}
```

模型可直接使用这个现有工具参数，CLI/TUI 共用同一后端，无需启动语言服务器或设置额外配置。`path` 为工作区内的目录范围。`query` 必须是一个简单标识符，例如 `resolve_command`、`Worker`、`$target`；有命名空间时使用末尾名称。查询不区分大小写。默认不启用调用位置，原有按名称/路径筛选的声明地图保持原格式。

## 结果与边界

`symbols` 中的声明仍使用原有 `kind`；新增项的 `kind="call"`，并提供：

- `name`：调用名称；Rust 原始标识符的 `r#` 前缀在此处去除。
- `line`、`column`：调用表达式起始位置，均从 1 开始，列按 UTF-8 字节计算。
- `enclosing`：所属命名声明的导航线索，不代表运行时调用者，也不保证能直接用于 `read_file.symbol`；可以按行范围读取附近源码。
- `target`：可取得时给出由标识符组成的目标链，使用点号表示；不是可重放的原始表达式。
- `receiver_unresolved`：接收者或目标形状无法完整识别时标明。

支持现有 Python、JavaScript、TypeScript、TSX、Rust、Go、C、C++、Java 解析器。普通注释和字符串不会产生调用候选；包含表达式的插值字符串保留其中的调用表达式。装饰器、默认参数、嵌套声明等只按语法归属展示，不推断执行顺序。

结果带 `calls_are_syntactic=true`：同名方法属于不同类型时会一起出现，导入别名、反射、动态分派、函数指针、隐式调用和宏展开没有完整绑定分析。运算符等不属于简单标识符的查询仍使用原有地图/搜索方式。Go 的泛型/下标歧义等情况会保留候选并标明不确定。无法识别的调用目标会令该次结果 `truncated=true`；解析、扫描或输出预算不足同样会报告截断。即使没有截断，空结果也不能证明不存在语义引用。

不要据此直接批量改名或判断代码未被使用。先读当前源码，再提出修改并执行检查。地图不返回编辑读取标识或内容版本，不授予写入/命令批准。

## 预算、隐私与缓存

沿用原有工作区、敏感路径、`.sprigignore`、配置路径排除和取消检查。每个受支持文件至多扫描 512 KiB，目录遍历至多 5000 个条目、累计 8 MiB；每个文件的调用数、遍历节点、名称长度和目标嵌套深度也有硬限制。启用调用位置时，含已知配置凭据的文件在索引前拒绝，避免凭据进入元数据缓存。

调用和声明使用有界的共同输出选择器，优先保留同等匹配等级的声明；位置排序和省略状态确定。新增结果标记也计入 `max_output`。工具 schema 总序列化大小仍为 4932 字节，旧有 16 KiB/131072 字节请求预算测试没有提高上限。

缓存按源内容和解析格式区分，合计仍限制为 128 条、1 MiB 序列化元数据，另有运行时对象开销；不缓存原始源码或 AST。每次请求仍重新读取和验证文件，缓存不绕过新隐私规则。普通声明地图只清理本次扫描覆盖的缓存格式，不会无故清掉调用/声明范围缓存；容量不足时按正常 LRU 淘汰。

## 与现有工具的关系

[Aider 的仓库地图](https://aider.chat/docs/repomap.html)包含关键定义信息，并利用文件依赖图选择上下文；[其实现](https://github.com/Aider-AI/aider/blob/main/aider/repomap.py)提取定义和引用。[OpenCode 的实验性 LSP 工具](https://docs.opencode.ai/docs/tools/)提供定义、引用和调用层级等查询。上述实现帮助确认了“声明之外的关系信息”这一缺口。

Sprig 本次只增加本地语法调用线索，没有实现 LSP 语义绑定、Aider 的图排序或完整引用图，也没有证明会提高模型成功率。它可以在一次只读查询中给出部分定义与使用位置，具体任务仍须实测。
