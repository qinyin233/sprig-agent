# 文件与大文本

文件上下文是 JSON 中的 UTF-8 文本快照，不是独立的文件上传服务。大文件优先通过路径检索、行范围或字节页读取所需部分；不会静默截断附件、自动提高限额或自动补发付费请求。

普通 `read_file(path=...)` 被截断时会返回 `read_guidance`，说明这只是前缀、没有编辑读取标识，并提示编号行、精确声明或字节分页。提示不发起后续操作，也不改变已有字节/扫描限额；旧成功输出压缩时随正文省略，完整保存历史保留。

文件名或父目录找不到时，文本和图片读取可在 `suggested_directory` 中给出已打开的上一级工作区目录。可先在该目录运行 `list_files`，再按实际文件名发起读取。提示受隐私规则和输出上限约束。

密集搜索可先用 `search(output_mode="files")` 只发现匹配文件，或用 `output_mode="count"` 得到已完整扫描文件的匹配行数，再有针对性地读取源码。两者不返回正文，仍先完整校验受限文件，不扩大扫描限额；详见[精简搜索模式](compact-search.md)。

按行读取另外返回 `range_complete`，表示本次请求窗口是否完整。不要把 `truncated=true` 单独解释为窗口缺失：它也可能只是表示文件后面还有行。

如果同一文件中需要几处相隔较远的代码，可一次请求 `read_file(path="src/example.py", ranges=[[12, 20], [140, 146]], line_numbers=true)`。`ranges` 接受 1 至 8 个按起始行升序排列、互不重叠的闭区间。行号从 1 开始，至多选 10000 行。显式传入 `line_numbers=true` 或省略它都会显示原始行号并返回相同结果。此模式独立于连续窗口、符号、字节游标和图片读取。

所有行段来自同一份最多 8 MiB 的完整校验快照。超出文件末尾、隐私校验失败或完整结果放不进 `max-output` 时返回错误。成功结果的 `range_complete` 只描述请求的行段。文件没有需要遮盖的配置值时，结果附带同一个 `read_id`，后续 `edit_lines` 仍逐次批准并复查完整文件版本。旧行段可按既有历史压缩规则省略，压缩器不会将它们作为整文件覆盖的证据。

| 按行读取结果 | 含义 |
| --- | --- |
| `range_complete=true`、`truncated=true` | 请求窗口完整，文件仍有后续行；是否继续读取取决于任务 |
| `range_complete=true`、`truncated=false` | 请求窗口完整，已到 EOF；空文件的有效首窗口也完整 |
| `range_complete=false`、`line_truncated=false` | 输出限额使部分请求行没有返回；已返回的完整行仍可拥有原有编辑读取标识 |
| `range_complete=false`、`line_truncated=true` | 首个物理行只返回前缀，没有编辑读取标识；可改用字节分页 |

窗口截至所请求的 `offset + limit - 1` 或更早的 EOF；只指定 `line_numbers=true` 时仍使用原有的 2000 行默认窗口。原始前缀、字节页不返回此字段，命名读取继续使用 `symbol_complete`。这不增加读取、输出或请求预算，也不是写入授权；隐私、只读、取消、版本绑定和逐次批准保持不变。旧成功正文压缩后保留完整性标记，完整保存历史不变。

| 入口 | 范围与限制 |
| --- | --- |
| CLI `--file` / TUI `/add` | 每批 1–16 个完整 UTF-8 文件，单文件 1 MiB、整批 2 MiB 原始字节读取上限，独立于工具展示；全部读取及实际请求预算通过才加入历史，见[附件预算](file-snapshots.md) |
| 同入口图片 / 本轮 TUI `@` | [四种常用静态图片](image-inputs.md)原生传入三协议；完整解码并移除元数据，原始/规范化字节及实际请求分别有界；像素不做 OCR 脱敏 |
| CLI `--ref-file` / TUI、chat `/ref` | 至多 16 个实时引用；完整小文件请求前刷新，大文件只传路径和大小；不自动扩大扫描或请求预算 |
| 普通 `read_file` | 按 `max_output` 返回前缀；`truncated=true` 表示不完整，不发放完整版本标识 |
| 行范围 / 字节分页 | 每次完整扫描并校验至多 8 MiB 的源文件，再返回不超过 `max_output` 字节的内容 |
| 模型请求 | 完整序列化 JSON 请求体受 `max_context_bytes` 限制；超限时不联网；字节数不是模型 token 数 |
| 模型回复 | 非流式或 SSE 回复至多 2 MiB；不完整、超限或输出 token 耗尽的工具提案不执行 |
| TUI 输入与引导 | 单条发送文本至多 `max_context_bytes` 个 UTF-8 字节；待处理引导最多 32 条，合计也不超过该字节限额；拒绝时保留草稿 |
| TUI 显示 | 保留最近 64,000 个字符，裁剪后持续显示标记；不改写模型历史，保存会话仍需明确启用 |

附件继续先做完整文件隐私检查，检查上限和 10,000 行窗口也适用；超限、二进制、无效 UTF-8、受保护路径或不完整文件会拒绝。某个文件失败时，不加入该批其他文件，也不发送模型请求。附件是快照，文件变化后需明确重新附加。

## 超长单行与可续读字节页

压缩 JSON、生成代码或很长的日志行可能超过单次输出上限。行范围返回 `line_truncated=true` 时，可从字节页重新读取：

```json
{"path":"data/large.json","cursor":"start"}
```

结果包括 `content`、零起点 `byte_offset`、不包含末尾位置的 `end_byte_offset`、`total_bytes`、`truncated`、`sha256` 和 `next_cursor`。下一次将返回的 `next_cursor` 原样作为 `cursor` 传回；其为 null 表示到达文件尾部。只在完整 UTF-8 码点边界分页；BOM 和 CR/LF/CRLF 不转换。组合字符及多个码点组成的 emoji 可能跨页，依序拼接后恢复原文。JSON 元数据和转义另外计入完整请求预算。

游标绑定规范化相对路径与完整内容摘要。文件变化、换用路径、游标格式错误或指向 UTF-8 字符内部都会拒绝，不返回该页内容。工具新实例或恢复会话后可显式继续同一游标，但每次都会重新校验文件、路径、隐私与版本，不自动获取后续页，也不保存文件正文副本。

字节模式中 `offset` 保持默认 1，不设置 `limit` 或 `line_numbers`。页面不发放行编辑的 `read_id`；游标是只读内容引用，不是编辑标识或操作批准。整行编辑仍先读取相关完整编号行，再提出新提案并取得新批准；512 KiB 编辑上限不变。

为防止需要遮盖的值被拆到多个页面后暴露，只要完整文件包含任何已配置凭据或需要遮盖的命令环境值，字节分页就拒绝，连页面内容与摘要也不返回。其他内置凭据模式、排除规则、无符号链接/重解析点、取消和工具禁用同样生效。这些检查不提供通用秘密识别或命令沙箱。

## UTF-8 请求与长输入

已知声明名时，可用 `read_file(path=..., symbol="Class.method")` 直接取得其索引范围，避免先猜测行号；此模式解析至多 512 KiB，长声明继续受输出和行数限制。重名不自动选择，解析与返回内容使用同一份已校验快照。见[命名源码读取](named-reads.md)。

JSON 请求使用紧凑 UTF-8，避免将所有中文变成 `\uXXXX`、emoji 变成代理对转义；符合 [RFC 8259 的 JSON 传输编码规定](https://www.rfc-editor.org/rfc/rfc8259.html#section-8.1)。解码后的任务、工具参数和内容不变，压缩预览和发送前检查均按实际请求体字节数计算。无效 Unicode 在网络请求前失败，诊断不回显原文；没有自动重试或改变模型 token 上限。

TUI 超限输入留在原输入框，便于缩短或另存为工作区文本文件；拒绝的引导不入队、不改变模型历史，也不取消正在等待的新操作批准。输入限额只是第一道检查：历史、工具定义、JSON 转义和元数据仍可能使完整请求超限，最终预算检查继续独立生效。

Enter 启动的普通任务还会在本地请求预检期间保留草稿；完整预算、文件引用或规则检查失败时仍可编辑。原任务可能已进入保留历史，修正后原样再次 Enter 会继续该任务；也可用 `/continue`。真正开始调用 provider 后，未改动的已发送草稿清空；用户在预检期间新写的文字保留，执行中仍可 Enter 发送引导。已发起网络请求后的错误不承诺恢复草稿。引用的有界刷新、会话元数据和大文件限制见[实时文件引用](live-file-references.md)。

请求预算采用[分块精确计数](context-memory.md)，避免仅为知道长度就构造完整的大请求。Provider 超限时在封包与网络前停止；实际发送仍由原标准 JSON 编码器完成，不以近似 token 数代替字节预算。

启用压缩时，`[context].keep_read_bytes` 可在硬上限内保留少量完整的旧源码窗口，默认 8192 个编码字节，0 关闭。候选放不下就省略，不扩大请求、不自动补读或拼接不完整页面。保留正文明确标为历史快照，移除旧 `read_id`；完整会话和原有逐次批准、隐私、版本检查保持不变。选择和边界见[源码窗口保留](read-retention.md)。

明确启用的本地会话保存也受独立的 8 MiB 上限约束。保存前按脱敏后的完整缩进 JSON 精确计数，中文、emoji、转义字符和缩进空白均计入；超限时不构造完整 JSON、不创建临时正文文件，也不覆盖旧会话或释放已有会话锁。计数不会截断正文、自动删除历史或提高上限。最终仍核对标准编码器实际生成的字节数；保存格式与恢复规则不变。该检查限制的是额外序列化分配，不限制已存在的内存历史或脱敏副本。

当前不支持任意二进制、图片/PDF 或大于 8 MiB 文件的直接上下文读取，也没有通用上传下载、远程断点传输或 GB 级扫描后端。命令执行依旧逐次批准，其网络和文件访问没有 OS 沙箱；不能把普通命令视为这些专用能力已经实现。
