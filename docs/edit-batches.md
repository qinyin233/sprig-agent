# 独立文件编辑的整批预检

模型在同一回复中提出 2–16 个 `edit_file` / `edit_lines` 调用、且目标路径互不相同时，Sprig 会先校验整批提案，再进入逐文件批准。CLI、聊天和 TUI 共用这条执行路径，无需配置开关。

例如，一次修复需要同时更新实现、调用方和测试。如果测试文件的旧文本已不匹配，整批预检会在第一个文件请求批准前停止，三个文件都不会由这一批提案写入。模型会收到原失败原因，其余调用收到明确的 `skipped` 结果，可以读取当前源码后修正提案。

## 校验和批准

预检复用正常编辑的校验：工具启用状态、只读模式、工作区和隐私限制、项目规则、UTF-8/二进制限制、原文唯一匹配、整行范围、读取标识及完整版本、单文件 512 KiB 上限、配置密钥备份保护。文件父目录必须已存在。

预检仅在内存中保留路径、文件状态、前后内容摘要和规则指纹；不保存整批原文，不写文件、临时替换文件或撤销记录，不授予批准，也不会生成新的读取标识。JSON 参数仍受原有深度限制；工具数量仍受完整模型响应的 16 次调用上限约束。

整批通过后，每个实际写入仍展示自己的完整 diff，并单独请求一次新批准。执行前检查该文件是否仍与预检一致；每次批准后，复查所有尚未完成的目标和相关规则，再进入当前文件原有的备份、替换和日志流程。较大批次会增加本地读取量，不能据此声称更快。

任何错误、拒绝或不确定结果都会停止余下编辑，避免继续请求批准。跳过结果报告 `batch_writes_completed`，表示此前明确成功的写入数；不确定写入不能按这个数字推断为未发生，必须阅读原错误和待恢复备份。合法的无变化提案无需批准，不会阻止后续文件。

## 不提供跨文件原子事务

预检能防止一开始就无效的后续提案造成部分修改，但外部进程仍可能在检查之后改文件，磁盘或日志也可能在写入中失败。先前已成功写入的文件会保留，并各自留下正常撤销记录。后续文件被拒绝时也不会自动回滚之前已批准的修改。

先查看工具结果和当前文件；需要恢复时，使用现有撤销功能，每个恢复仍需新批准。日志有待确认写入时，沿用原有恢复阻断规则，不重放工具调用。取消和中途引导也会结束批次，恢复会话时不会继续使用内存中的预检结果。

重复目标路径、同文件连续修改，或混有读取、命令和计划工具的回复，保持原有逐次执行。路径比较规范化 `./` 等表示，在 Windows 上忽略大小写；这不是任意文件系统别名检测。预检不是权限边界，单文件工具本身的限制和批准始终有效。

启用 `check_after_edit` 时，完整工具批次结束后按原配置运行一次阶段检查；最终验收仍独立运行。每个检查命令都需新批准。预检错误、局部写入或阶段检查通过均不等于任务完成。

## 验证范围

`tests/test_edit_batches.py` 覆盖初始匹配/参数/版本/大小/隐私失败、逐文件批准与撤销、无变化和新建、拒绝后的部分结果、外部改动、规则变化、取消/中途引导、日志检查点失败、关闭的根目录和同文件顺序兼容。回环 HTTP 验证失败后修正、完整工具结果顺序、16 KiB 请求上限，以及阶段检查和独立最终验收。

这些离线测试验证执行和协议行为，没有付费模型成功率、请求次数减少或顶尖 agent 性能对照证据。
