# CLI 拒绝时附带更正说明

在 `--cli` 单次任务或 `--chat` 的模型任务中，逐次确认可输入：

```text
Approve this exact action? [y/N; n: correction] n: 不要创建新目录，请修改现有的 src/main.py
```

这会拒绝当前操作，将冒号后的说明作为当前任务的新用户引导收存。在下一个安全节点递送后，尚未执行的旧调用补为 skipped，模型重新提出操作；新的写入、命令和固定检查仍须分别批准。已执行的写入不会因后续拒绝而撤销。只有去除首尾空白后的 `y` 或 `yes`（大小写不敏感）会批准眼前操作；普通 `N`、空输入或 EOF 均拒绝，非交互 stdin 不读取说明。

支持 `n: 正文` 和 `no: 正文`，去除正文首尾空白，限非空单行、4096 个 UTF-8 字节；不能用多行粘贴夹带批准。空的 `n:` 按普通拒绝处理。说明还受原有输入数量、总字节和请求上下文预算限制。正文超限、多行、编码无效或保存失败时，确认继续等待并显示未接收，不会将当前操作视为批准。

启用会话保存时，先保存收件记录再确认接收；未启用时明确提示仅在进程内存中。正文按当前模型配置的已知凭据脱敏，本地输入 ID 仅用于递送去重，不发送给 Chat Completions、Messages 或 Responses。切换模型或建立历史分支后，后续反馈使用新会话和当前配置，父文件保留。说明的接收、递送与模型回答、工具执行、任务验收是不同状态。

若保存替换完成但目录同步报错，不能断言磁盘没有收到输入。确认窗口会阻止 `y`，重试**同一条** `n: 正文` 沿用原 ID，避免重复递送。也可输入普通 `N` 拒绝并回到聊天；收存状态未解决前，不能继续模型或旧工具提案。`/pending apply` 明确重试引导收存并加入本地历史，不联系模型；之后 `/continue` 才继续模型请求。`/pending discard` 仍须新批准；失败时保留恢复信息并阻止旧内存输入递送。修改待处理输入时保存不确定也会阻止递送，须恢复会话或明确丢弃；不能把磁盘和内存里不同版本的说明混用。若递送保存失败，可用 `/pending apply` 重试已有 ID；存储已标记不确定时须恢复会话或明确丢弃。排队任务的收存重试仍用相同 `/queue` 正文，详见[保存与恢复](pending-inputs.md)。

更正不会增加 `max_steps`。最后一次模型请求中才收到说明时，它可能留在待处理输入中，当前任务以未完成状态结束。保存后用 `--chat --resume NAME` 检查 `/pending`，明确 apply 或 discard，再继续；恢复不会自动发送说明或重放工具。无保存的单次 CLI 退出后，内存中的待处理说明无法恢复。

此入口只在模型任务执行期间启用。本地 `/pending` 修改、模型切换、分支、配置管理等确认依旧只接收批准或拒绝，不把拒绝文字偷偷交给模型；嵌套 CLI 调用及新线程也不会继承外层任务接收器。TUI 批准窗已有更正输入，Enter 发送并停止旧提案，本批没有改变它。文本反馈不能取消已经运行的外部副作用，也不授予预先批准或沙箱隔离。

离线回归使用真实私有会话、临时文件和三种协议的回环 HTTP，核对旧批次跳过、替代写入与固定检查的新批准、保存失败和去重、最后一轮恢复、排队分离、本地操作隔离与模型/分支重绑定。完整本地范围见[机器记录](benchmarks/cli-rejection-feedback-20261023.json)。没有新增真实模型完成率证据。GitHub Actions 在 2026-11-01 前冻结，到期后仍须确认账户限制和先前必要 gate；本地平台跳过与 WSL 结果不能替代原生 CI。
