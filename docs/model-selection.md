# 运行中选择配置模型

TUI 和连续 chat 可以在空闲时切换启动配置中的提供商/模型，无须退出终端。选择不调用模型，也不联网发现模型；下一条任务或“继续”才会向目标发送保留的对话。原有写入、命令、MCP 逐次批准规则仍由执行层检查。

## 操作

- TUI 侧栏“切换模型”或 `/model` 打开本地选择器；搜索、↑↓、Enter 选取，随后明确确认，Esc 关闭。按钮不清空主输入草稿。最多显示 20 个匹配项，更多时提示细化查询。
- `/models` 查看启动时的配置目录；`/model PROVIDER/ALIAS` 明确选择某个别名。
- `/model PROVIDER` 选择该提供商配置的默认模型；`/model @startup` 恢复启动时的模型/传输/生成设置。
- 连续 chat 用 `/models` 列表和 `/model KEY` 选择，使用原有终端确认提示。单次非交互 CLI 继续使用启动参数，不等待模型选择输入。

例如，已有 `[providers.ustc.models.flash]` 时可输入 `/model ustc/flash`。别名必须在配置目录中，不能通过此命令指定任意 URL 或未知模型。TUI 命令补全选择 `/model` 只填回输入，不自动执行；主输入保持 Enter 发送，Shift+Enter / Ctrl+J 换行。

选择菜单、拒绝、取消和本地预检不会发出模型请求。执行中不切换配置，`/model` 不成为模型任务或引导；可先取消并等待任务结束。确认窗内仍可发送普通新要求，旧切换提案被放弃，交给原模型继续处理。

## 配置和凭据

选择器使用启动时已验证的用户/项目/profile、启动参数及凭据环境快照，不重新读取修改后的配置或环境。新增模型/变更密钥后请重启。目录包含配置别名、提供商默认项及 `@startup`，不推断费用、可用性或模型性能。

切换到启动提供商时，保留其启动参数覆盖。其他提供商按自己的配置解析模型、端点、鉴权、代理、协议和生成设置，不携带启动提供商的命令行端点/传输/生成覆盖及 `SPRIG_BASE_URL` 覆盖。全局备用 API key 不会隐式转发：只有目标明确配置的 `api_key`、`api_key_env` 或头环境引用参与目标鉴权；引用变量缺失时报错，没有后备提供商。

工作区、只读、工具禁用、路径排除、验收命令、命令环境、UI 和存储策略保持当前值。目标别名可使用其配置的请求字节上限，完整协议封包仍须通过预算检查。切换不能放宽工具策略；所有已知的旧/新凭据及动态 MCP 会话标识继续参与脱敏和子进程环境过滤。

确认列出目标端点、协议、鉴权头名称、代理、实际生成设置、预算和新会话名称，不显示密钥值。多组凭据连续脱敏时，已有 `[REDACTED]` 标记不会被后续短头值反复展开；完整凭据本身含此标记时仍会遮盖。

## 历史、保存和权限

切换保留可见用户/助手文字和工具历史，重新准备系统规则；移除旧 `reasoning_content`、原生协议 `native_state`（含签名/不透明数据），重新遮盖已知凭据。无效历史仍拒绝，未结束工具步骤按既有恢复规则标记交付不明，不重放。选择不同模型、协议、生成或鉴权设置都可能使旧私有状态不再适用，因此不将这些状态直接转交目标。

启用了会话保存时，确认后的切换创建 `model-<UUID>.json` 私有分支，绑定新模型/端点/协议及设置。原会话文件不覆盖。恢复沿用既有绑定校验，实际模型/端点/协议或相关设置不同的旧文件须先切回匹配配置；凭据值不写入绑定，密钥轮换或只改提供商别名未必改变绑定。当前未保存时仅保留内存，可另存。草稿和未发送的文件/粘贴选择不自动进入分支；原来因请求准备失败保留的草稿可在切换后重试，不重复加入同一条任务。

保存失败、预算不足、提交前取消或提案过期会阻止切换，保留原模型及草稿；失败不会自动重试。完成后的取消不回滚已经生效的本地切换。每次提交消耗一次明确确认，保存失败后也需要新确认。对于异常中断、交付不明的本地写入，应核对确认中指定的新分支名称，不自动覆盖或删除残留文件。

新模型使用新的运行/用量状态，先前验收不再标为当前已验证；短计划仍只是历史中的模型报告。清除旧文件读取标识、摘要投影、语法缓存和 MCP 连接/结果；旧命令日志所有权及工作区编辑备份保留。断开旧 MCP 连接只清理本地状态，不暗中发送 DELETE。历史里的 `approved=true` 不能批准新命令，目标提出的动作仍需全新的批准。

原生/推理元数据会按目标协议和配置用于后续同模型请求及启用的本地保存。本地文件不加密；原始分支仍可能包含旧提供商元数据。`/usage` 从新 provider 实例开始统计，切换结果另显示旧实例的统计，不合并成未经区分的费用结论。

## 验证范围

对照固定 OpenCode `dev@9d90d892dcbfc52b47e95b2ea31b8aba877128fd` 的 [`dialog-model.tsx`](https://github.com/anomalyco/opencode/blob/9d90d892dcbfc52b47e95b2ea31b8aba877128fd/packages/tui/src/component/dialog-model.tsx)：上游选择配置项后更新本地 model preference，可继续选择 variant。Sprig 在现有三协议客户端上增加明确确认、凭据隔离、历史投影与私有会话分支；没有移植价格/免费标签、远程发现、收藏/最近使用、OAuth 或配置热重载。

`tests/test_model_selection.py` 通过真实 Textual、CLI chat 和回环 HTTP/SSE 验证三协议切换后请求、私有保存/恢复绑定、旧元数据不转发、草稿重试、拒绝/取消/预算/保存失败、执行中引导、过期提案和新命令重新批准。固定回复验证程序/协议行为，不新增模型编码性能结论。平台、安装包和远程 CI 范围见[机器记录](benchmarks/model-selection-20261021.json)。
