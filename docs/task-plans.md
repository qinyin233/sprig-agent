# 可恢复的任务计划

Sprig 的 `update_plan` 工具让模型维护一个短清单，TUI 侧栏的「计划」页和 TUI/`--chat` 的 `/plan` 可本地查看。执行中仍可 Enter 发送新要求；模型可以据此更新清单。该能力参考了 [Codex 的 update_plan 控制工具](https://github.com/openai/codex/blob/main/codex-rs/core/src/tools/handlers/plan.rs)所提供的进度接口，代码独立实现。

```json
{
  "plan": [
    {"step": "定位实现和失败行为", "status": "completed"},
    {"step": "实现修复并补充验证", "status": "in_progress"},
    {"step": "运行固定验收", "status": "pending"}
  ],
  "explanation": "根据新要求调整下一步"
}
```

清单最多 16 项，状态为 `pending`、`in_progress`、`completed`，同时最多一项进行中。每条描述最多 256 字符，说明最多 512 字符；结果序列化后最多 4 KiB，并受更小的 `max_output` 限制。字段只接受短纯文本，控制字符、未知字段/状态、过多步骤和超限整批拒绝，保留上一个有效版本。空数组清空清单。

## 进度和实际执行分别确认

计划中的“已完成”始终是模型报告。它不能批准写入、执行命令、关闭只读、改变工具权限或证明测试通过。`update_plan` 只更新内存数据，不执行步骤中的文字，不读写工作区文件，也不启动程序，因此只读模式可用。写入、命令和最终固定检查仍经过原有逐次批准与独立验收。

TUI 会明确显示该边界。`/plan` 不发送模型请求；原有 Enter 发送、默认拒绝和中途调整要求的行为保持。新要求到达时，旧计划是最近一次模型报告，后续由模型修订，不自动标为新要求已经完成。普通简单任务可跳过计划。

可在用户/profile 配置中禁用：

```toml
[tools]
update_plan = false
```

也可使用 `--disable-tool update_plan`。禁用同时作用于模型 schema、分发和直接方法；项目层不能重新开启可信配置关闭的工具。查看已有计划不会执行或重新放行工具。

## 会话、取消与压缩

默认不新增任何计划文件。显式启用会话保存后，计划随已有私有、未加密历史一起保存。恢复只读取配对的已完成成功结果；未完成、拒绝、失败、无对应调用或被压缩成占位符的记录不能更新计划，也不会重放意图。计划可在恢复后、模型请求前显示。新建对话确认后清空当前内存计划，原会话保留。

启用现有 `compact_context` 时，旧成功计划的参数和结果可以在请求副本中省略；最新成功计划、错误/拒绝和最近六条消息保留，原始历史不变。整个实际请求仍需通过字节预算。请求 JSON 去掉结构性空白，字符串和解码后的载荷不变；回归继续使用原来的 16 KiB 上限，没有扩大预算容纳新工具。

此能力没有增加长期目标执行器、工作区回滚、后台任务或自动调度。离线 HTTP、真实私有会话与 TUI 回归证明上述流程；尚未用真实模型证明它提高复杂任务成功率。2026-10-16 的[基线复测](live-evaluation-20261016.md)在加入计划工具之前仍失败，记录保持原样。
