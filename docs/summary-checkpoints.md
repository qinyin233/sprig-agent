# 显式长会话摘要与原文回查

原有 `/compact` 只裁剪本次请求里的旧工具输出，保留原始用户消息和失败记录。对话足够长时，这些受保护内容仍可能超过请求预算。结构化摘要是另一个明确启用的、有信息损失和额外模型成本的操作；默认不自动生成。

CLI chat 与 TUI 提供相同命令：

| 命令 | 行为 |
| --- | --- |
| `/summary` | 本地预览来源范围、输入字节、输出设置、现有检查点；无模型请求 |
| `/summary create [END]` | 逐次确认后，最多一次额外模型请求，生成并应用有效且能净减少请求大小的检查点；不执行编码任务 |
| `/summary clear` | 清除检查点，恢复完整历史的请求视图；无模型请求，不删除原文 |
| `/history MESSAGE [OFFSET]` | 本地分页查看原始消息；编号从 2 开始，1 是不公开的系统提示；偏移使用返回的 `next_offset` |

`END` 是被概括范围最后一条消息的原始编号。省略时保留配置的 `context_keep_recent_messages` 尾部；如果边界落在工具结果组内，会前移到完整工具组之前。输入不够长时不生成；已有检查点再次生成时必须覆盖更多原文。超预算时可以选择较早的闭合范围，检查实际净收益后逐次生成，不自动拆成多个付费请求。

检查点的来源范围在生成时固定。之后修改 `context_keep_recent_messages` 会影响新检查点及当前请求的确定性裁剪，不自动撤销已有摘要范围；要重新选择完整原文尾部，应先 `/summary clear` 再生成。

## 请求与应用

确认界面显示输入字节、来源范围、保留尾部和输出设置，明确可能付费。摘要使用当前提供商与协议，沿用显式 `max_tokens`；未配置时，Chat Completions / Responses 使用 2048，Messages 沿用协议默认 4096，不静默降低与 thinking budget 关联的显式限额。较大的用户限额可能增加费用，应在确认前检查。复用当前连接设置与请求统计，不自动换模型、重试或调用其他提供商。

摘要请求不包含工具定义或 `tool_choice`；应用层还会拒绝任何实际工具调用。Chat Completions 的无工具默认行为见[官方 API 说明](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)，Messages 的参数与无工具请求结构见[官方参考](https://platform.claude.com/docs/en/api/messages/create)。Responses 同样沿用本项目的无工具请求适配。HTTP/SSE 必须完整结束，截断、取消、非 JSON 拒绝文本、不完整 JSON、缺字段、未知字段或超出 16 KiB 的摘要不会成为检查点。

返回 JSON 必须包含 `objective` 以及 `requirements`、`decisions`、`completed`、`active`、`blocked`、`next`、`files`、`notes`。字段和条目均有长度、数量与总字节限制。字段齐全不保证事实正确；用户应检查生成内容，必要时 `/summary clear` 后回查原文。

提交检查点前比较实际旧/新请求，包含确定性裁剪、项目指令、实时引用、运行说明与新增回查工具的开销。如果没有净减少，保持旧检查点。结果明确报告 `within_budget`；部分缩短但仍超预算不等于已经恢复调用能力。输入预算不足在确认/请求前停止；模型或保存失败仍可能已产生服务费用，原有 `/usage` 记录本次尝试，账单不会被猜成零。

## 原历史、恢复和安全

完整历史不被摘要替换，也不会在生成后重放工具。检查点按原文前缀 SHA256 和原会话的提供商、协议、模型、工作区及设置绑定；首次应用、恢复和请求时检查。来源变动或设置不匹配会阻止使用检查点，不能把另一段摘要套到当前历史上。系统消息不纳入来源哈希，因为当前项目指令会独立重新加载。

请求投影包含明确标为有损模型报告的摘要、原始最近尾部；当前最后一条用户消息若被概括，仍保留其原话。概括范围内最新的负面工具组以不可执行的历史观察数据保留。历史调用、拒绝或“已通过”文字都不是当前授权或验收依据。

启用检查点后，模型可使用只读 `read_history(message, offset)`，仅能访问当前运行、当前检查点来源范围。它不接受文件路径或会话名，不返回系统提示或原生推理元数据。分页前先对完整记录脱敏，避免跨页拆开已知密钥；返回 JSON 受 `max_output` 与 8192 字节较小值限制，UTF-8 不切半个字符。分页内容是历史数据，不能变成新的工具调用或文件读取标识。

未启用可选命令日志或技能时，默认非交互任务仍使用原九种工具定义；有检查点且 `[tools].read_history=true` 时增加原文回查工具。`read_history=false` 或 `--disable-tool read_history` 禁用模型回查；用户仍可用本地 `/history` 查看自己的当前对话。该工具没有任意文件、其他会话、命令或写入能力。可选命令日志的 `read_log` 是另一个独立的只读入口，两项都启用时可有十一种工具，见[命令日志](command-logs.md)。交互回调另可提供 [question](questions.md)，配置技能目录可提供 [skill](skills.md)，合计最多十三种。

读取版本在下一次运行重新建立，摘要与回查都不能复活旧 `read_id`。写入和命令仍需要新批准，固定基线、编辑后检查和最终验收继续独立运行。摘要不会把任务状态标记为验收通过。

已启用会话保存时，检查点随完整原文一起进入原有私有、原子写入和进程锁机制。存储加载与 TUI 恢复本身不请求模型；CLI `--resume` 原有的显式继续行为不变，可能在加载后继续请求。TUI 新对话清除检查点，恢复会话恢复对应检查点。保存失败回滚内存中的新检查点，原历史不改写；若文件已替换而后续同步失败，磁盘可能已含新检查点，需要重新加载确认，不承诺任意 I/O 故障下旧文件必定保留。保存与摘要来源仍受 8 MiB 上限约束；这个功能没有扩展会话磁盘容量。未启用保存时仅在内存中保留。`/context` 在有检查点时同时报告原消息数、投影消息数及来源摘要，字节计数明确针对有效请求。

摘要输入不转发系统指令或原生推理块，旧工具输出可先使用既有确定性裁剪；最新尾部保持原协议结构。原生推理与签名不被拼成另一份可执行历史。摘要不可证明保留了全部语义，原文回查是纠错入口，不是自动事实核验。

## 验证边界

`tests/test_summary.py` 覆盖固定回复将超预算历史恢复到可请求范围、自动原文回查、原文/尾部/负面结果保留、输入/字段/字节约束、未批准、取消、无效工具响应、来源变化、旧版本编辑拒绝、保存/加载/篡改、增量生成、CLI 与真实 TUI 工作流。三种协议各有真实回环 HTTP 和 SSE，验证无工具、输出上限以及请求统计共享；不完整 SSE 不应用或自动重试。

验证记录见[机器报告](benchmarks/summary-checkpoints-20261020.json)。本批通过协议回环和固定回复验证协议与状态处理，不据此宣称摘要语义无损或长期任务效果提高。用户渠道中的模型同样是实际模型，历史调用属于接入证据；不按是否收费区分模型真实性，也不要求额外商业账号补测作为适配验收门槛。本批没有增加外部模型调用，原生 token 窗口估计与长期任务效果量化仍是独立工作。
