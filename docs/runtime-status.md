# 执行阶段与运行结果

TUI 侧栏现在显示准备上下文、等待模型响应、工具处理、等待批准、已批准、澄清问题等待回答、检查和本轮结束。澄清回答不属于操作批准，见[问题流程](questions.md)。CLI 输出模型/检查/结束阶段，CLI chat 与 TUI 的 `/status` 均可查看相同的结构化运行快照；这些本地查看不会请求模型。

状态来自应用实际执行路径，不解析模型文字或工具输出中的“通过”“完成”等词。模型任务计划仍单独展示，不能改变运行结果。

## 如何理解状态

| 状态 | 含义 |
| --- | --- |
| 准备模型上下文 | 正在读取规则、准备引用和检查预算；尚不代表已发出请求 |
| 等待模型响应 | 已进入调用 Provider 的阶段；实际 HTTP 次数、成功/失败和 token 用量仍查看 `/usage` |
| 工具进行中 | 正在处理这个工具调用，可能仍需参数、路径、版本或其他检查；有副作用的动作另需批准 |
| 等待确认 | 应用正在向用户请求本次操作的批准 |
| 已批准，仍需执行 | 收到批准；随后仍要检查取消、路径、版本等，不能当作写入或命令成功 |
| 工具已结束 | 已取得工具结果并完成当前 checkpoint 回调；未启用保存时不代表已经持久化 |
| 任务前基线 / 编辑后检查通过 | 对应阶段的固定命令通过；最终验收仍要单独执行并批准 |
| 最终验收通过 | 本轮独立运行的全部用户固定检查通过；不代表检查覆盖所有正确性条件 |
| 模型本轮结束，未配置验收命令 | 模型结束了本轮，尚无独立固定检查；保持原有 CLI 退出语义，不伪造检查通过 |
| 取消 / 结果不确定 / 未完成 | 不能据此认定任务完成；已经发生的副作用需要检查，不会自动回放 |

步骤计数表示本次 `Agent.run` 的循环预算，不是 HTTP 账单计数。新引导导致旧响应被弃用时也可能消耗步骤；真实请求统计以 `/usage` 为准。

## 范围和安全边界

运行快照只保留当前进程最近一项不可变事件，含随机 run ID、序号、步骤预算、工具动作序号、固定工具名、检查阶段/序号及有限结果分类。不会放入任务正文、路径、工具参数、原始调用 ID、响应内容或异常正文；未知工具名统一显示 `unknown`。

它不进入模型请求、会话 JSON 或编辑备份。TUI 事件视图仍限制为 1,000 行。新建或恢复对话清除旧运行快照，恢复历史会显示未重新验收；本地操作之后原任务验收是否失效仍由原有任务结果管理。

事件、观察回调返回值和模型文字均不能授予执行权限。写入/命令仍经原批准函数，随后重新检查取消、文件身份和内容版本。观察回调异常会终止后续动作；若动作已经完成而保存失败，快照标记 checkpoint 失败并保留对应工具动作序号，不能承诺回滚已经完成的修改。原意图和修改日志的安全恢复规则保持有效。

执行中引导仍在安全边界加入；`/status` 明示待处理引导仅在内存，当前没有持久 inbox 或独立任务队列。本批没有实现后台任务、长期摘要或统一的本地管理操作事件。

## 验证方式

`tests/test_runtime.py` 使用真实回环 HTTP、文件工具、子进程检查、私有会话和 Textual 界面，覆盖过期编辑拒绝→新读取→批准修改→阶段检查失败→修复→独立最终验收。另检查观察回调不能批准、回调异常/取消阻止写入、保存失败后不重放、预算拒绝不冒充已发请求、未知工具名不泄露、模型伪造通过文字无效，以及新对话清除旧状态。

已有 TUI 中途引导与网络/批准取消测试补充运行状态断言。运行证据按批次记录；测试跳过不计为通过，当前修改没有付费模型性能结论。
