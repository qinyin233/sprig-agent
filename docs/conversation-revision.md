# 编辑历史请求并重发

TUI 的“编辑历史请求并重发”或 `/revise` 打开用户轮次选择器。选中后，在独立编辑区修改旧请求，**编辑区 Enter 会先预检，再确认建立新分支并发送**；Shift+Enter / Ctrl+J 换行。主输入框的草稿、文件选择和折叠粘贴保持，不随这次编辑发送。

也可用 `/revise MESSAGE` 直接选择 `/timeline` 中的消息号。只允许真实用户请求，应用观察不是分支点；旧未标记记录仍沿用[既有来源分类](message-origin.md)，不按正文猜测迁移。显示的是已保存/保留的用户正文：任务模板已展开、秘密已脱敏，不恢复先前的原始按键或密钥。

连续 chat 使用一个 JSON 字符串保留换行、引号和首尾空白：

```text
/timeline
/revise 2 "修复解析器。\n保留公开 API。"
```

TUI 的 `/revise MESSAGE "JSON 新正文"` 可预填替换文字，然后在编辑区检查。没有正文的 chat 命令只显示用法，不发送模型请求。编辑区正文始终是普通任务数据；即使以 `/exit`、`/undo`、`/review` 或 `@路径` 开头，也不递归执行本地命令、模板或附加文件。

## 分支、确认与工作区

新分支保留目标用户消息**之前**的闭合历史，再加入分支说明和新请求。所选旧请求、它的回复/工具结果和之后的轮次不进入新分支。原对话文件不覆盖，**工作区文件不回滚**。当前模型、端点、协议、工具/路径规则和固定检查保持；确认中列出目标服务和新私有文件名，模型请求只在成功提交且未取消后开始。

完整请求在确认前检查预算，确认后再次检查来源和上下文；不因为分支而扩大预算或静默截断。来源绑定实际父历史、消息号、工具会话版本和 Agent 身份，过期编辑不能替换另一份对话。只接受布尔 `True`；旧批准、历史回执和新引导不会代替本次确认。

分支沿用[普通分支](conversation-branches.md)的失效处理：清除读取标识、推理/原生元数据、摘要、MCP 连接和旧命令日志所有权，停止当前拥有的后台/LSP 进程，重新建立验收状态；文件编辑备份保留。新写入、命令和图片发送仍各自批准。保留的旧检查或计划勾选不能当作新任务通过。

启用了会话保存时，新请求在发送前写入新私有分支；未启用时保留在内存。来源与保存策略保持，数值用量沿用同一 provider，不把分支伪装成消费清零。保存交付不明时核对确认中指定的分支文件，不自动覆盖、删除或重放。

## 草稿、取消和失败

拒绝、预检失败、取消或保存失败会保留编辑区草稿。修短正文后可再次 Enter，重新检查并确认；原来因错误恢复重建父历史列表而无法重试的问题已修正。若来源实际变化，仍需重新选择，不能沿用旧确认。

确认时收到新引导或排队输入会阻止旧修订提交；输入按原队列策略保留。编辑区保持打开且不自动请求模型，关闭后用 `/pending`、`/continue` 或队列控制明确处理。普通模型执行中的引导流程保持。

分支已提交后再取消，或模型网络请求失败，已编辑请求仍只保留一次；不会自动重新建分支或重发。核对当前分支后明确“继续”。TUI 恢复保存的分支保持空闲，不重建旧编辑表单；其他入口沿用既有显式恢复规则，旧工具动作不会重放。

Esc/“关闭（放弃草稿）”放弃本编辑区未提交的修改；主输入草稿仍保留。分支切换后，发送主草稿会把它作为新分支的后续任务，所选文件仍在实际发送时重新检查。

## 长正文与附件

长正文先显示只读摘要，Enter 使用完整内容；F4/“展开”可查看和编辑全文，大段内容显示可能较慢。“替换全文”清空本编辑区并切换为普通文本；空编辑区的大粘贴完整收存为摘要。已有正文中的大段局部粘贴会拒绝，原文不改，不发送预览标签。

含 CR、Tab 或终端控制字符的旧正文采用可往返的 JSON 字符串视图；只转义控制字符，中文保持可读。安全视图分块计数，最多 `min(2 MiB, 6 × 输入预算 + 2)` UTF-8 字节，超限拒绝而不截断；可分页回查原文后提供较短替换。新正文仍受原单条输入与完整请求预算限制，显示摘要不会减少模型字节或 token。

确认中，至多 8192 UTF-8 字节的正文完整显示；更长正文明确只显示字节数和 SHA256，全文可在编辑区查看或核对输入。该摘要只绑定待发送正文，不是编辑 read_id 或验收证明。

截断点之前已经保存的文本/图片快照仍是历史数据，不重读为当前版本。被截掉的部分、未保存的 `@` 本轮附件和模型读图缓存不会重建；主草稿文件不随本次修订附加。需要新内容时，在后续新消息明确选择，或让模型按路径重新读取并遵守原有权限和图片发送确认。实时引用沿用当前显式选择并正常刷新。本功能不提供文件快照回滚或原始附件元数据重建。

## 验证范围

25 项新增回归包括三协议各 JSON/SSE 的六条正常 chat 链：先保存两轮原对话，夹具在修订前外部改变文件，再确认分支、读取当前文件、新批准编辑并独立固定检查；原文件逐字节保持。80×24 TUI 验证主草稿/选择/折叠粘贴、Enter、长正文、控制字符、来源变化、拒绝/取消、保存失败、新引导、网络失败与恢复。

这些是合成夹具和回环服务的实现证据，没有外部模型调用或新增编码成功率结论。最终范围与隔离反例见[机器记录](benchmarks/conversation-revision-20261025.json)。2026-11-01 前不运行 GitHub Actions，远端 CI 待验证。
