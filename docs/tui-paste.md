# TUI 长文本粘贴

主输入框与批准窗的引导输入框接收终端粘贴事件。超过 200 个字符，或包含至少三行的文本，自动显示为 `[粘贴 #编号 · 行数 · UTF-8 字节数 · F4 展开]`。这只是本地显示占位，选择标记不会提交任务。Enter 发送，Shift+Enter / Ctrl+J 换行。

焦点在输入框时按 F4，或点击主输入框旁的“展开粘贴”，可以把所有折叠块展开为可编辑正文。展开不请求模型、不写文件，也不批准操作；可以继续编辑，再按 Enter 发送。折叠不减少模型上下文或费用。

## 内容与编辑

- 粘贴统一 CRLF 和单独 CR 为 LF，保留缩进、tab、首尾空格和末尾空行，不使用 `trim()` 裁剪正文。包含粘贴的整条消息按这个方式发送；没有粘贴的普通输入保持原有首尾空白裁剪。
- 在标记前后编辑会移动其范围。可以多次粘贴、替换选区，并与显式 `@文件` 选择混用；粘贴里的路径或 `@` 文字不会自动选择文件。
- 编辑或删除标记会移除对应正文并提示。要改正文，请先展开。撤销、重做由该次编辑的元数据恢复正文，不根据标记文字查找内容；手动输入、粘贴或复制一个标记不会获得旧正文。
- 粘贴、展开、删除和普通编辑支持 Textual 的撤销/重做。原有文件选择仍遵循独立规则：重做文件标记不重新授权附件读取。
- 折叠内容以及展开后的同条草稿不作为本地 slash 命令执行。例如折叠文本以 `/exit` 开头，Enter 发送的是模型任务数据。清空输入框或换入新草稿后恢复普通 slash 操作。

## 限制与预算

单次粘贴和加入粘贴后的完整展开草稿受 2 MiB UTF-8 上限约束，最多同时折叠 16 块。这是当前输入的本地上限，不是整个进程内存上限；撤销栈仍会暂存可撤销的正文。实际模型请求还受通常更小的 `max_context_bytes` 限制，包括工具定义、项目指令、实时引用和协议包装。

含无效 Unicode、ESC、NUL 等终端控制字符的粘贴整段拒绝，不静默删除后继续插入。tab 与换行允许；ANSI 日志应先转换成可见文本。拒绝时不覆盖原草稿或选区，不把正文加入日志。没有自动读取剪贴板、抓取 URL、上传图片/PDF 或写临时工作区文件。

发送展开后的完整正文，不能用短标记绕过单条输入或引导队列限制。空闲时，包含粘贴的新任务在修改历史、保存检查点或运行基线命令前先做完整协议预算预检；失败保留草稿、折叠内容和原历史。删除该块后重发，不会把那次未通过预检的正文遗留在新请求里。预检通过后仍保留正常请求前的二次预算、取消和隐私检查。

执行中粘贴的新引导以完整正文进入现有有界队列，按现有安全节点处理，仍会使待定旧批准失效。队列满或超预算时不清空草稿。批准窗内 F4/Enter 只能展开/发送引导，不能替代“批准”。已发送的正文按原会话规则保存，未发送草稿仅在内存中；进入 Provider 后的网络异常不保证服务器未收到请求，也不会自动重发。

## 实现与验证

`composer.py` 共用范围移动/失效逻辑，`DraftPastes` 只按明确范围展开。编辑条目保留粘贴前后状态，撤销不靠全局标记字符串匹配。换入新草稿或请求准备完成后自动清空输入时，清除旧元数据与撤销历史；用户手动删除仍可撤销。新草稿不会被旧请求准备回调清空。修复了多行展开撤销时，滚动条刷新先于旧光标恢复而访问已删除行的问题。

`tests/test_paste.py` 包括真实 Textual 粘贴事件、CRLF/中文/emoji、选区与光标、F4/按钮、多块与文件选择、撤销/重做、伪造标记、控制字符、字节/数量限制、预算失败重复发送/删除、新草稿、中途引导和批准拒绝。三种协议实际回环 HTTP 检查正文空白及预检前无检查点或基线执行。

具体本地测试、构建和原生 CI 状态见[验证记录](benchmarks/tui-paste-20261020.json)。固定回复与界面回放不代表真实模型编码成绩，也不能证明已追平主流 agent。
